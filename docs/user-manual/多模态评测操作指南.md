# 多模态评测操作指南

适用范围为原图、音频、视频输入以及文本和音频输出。数据集、任务管理、安全可信、工具底座和编排Agent共用版本和权限控制。本文说明如何操作及识别测量边界，不将“接口支持”当作“对应模型已经真实验收”。

## 数据准备

1. 新建数据集并导入文本问题与参考答案。
2. 展开样本，添加媒体。图片支持PNG/JPEG/WebP，每个最多10MB；音频支持WAV/MP3；视频支持MP4/WebM，音视频每个最多25MB、最长120秒；每题最多8个附件。
3. 添加视频前选择抽帧或原生视频；需要音频输出时将“模型输出模态”改为“文本及音频输出”。这些操作均产生新版本。
4. 重新质检并发布。确认创建任务选择的是本次媒体版本。

批量导入JSON/JSONL时，`media`与`input`同级。二进制使用内嵌data URL，不能仅提供可变外链。SHA256可省略，导入时计算；提供时必须匹配。

```json
{
  "input": "描述视频中的颜色变化",
  "reference": "red,blue",
  "media": [{
    "modality": "video",
    "name": "sample.mp4",
    "data_url": "data:video/mp4;base64,<实际视频字节>",
    "video_mode": "frames",
    "frame_timestamps": [0, 1.5],
    "segments": [{"start": 0, "end": 1, "label": "参考片段"}]
  }],
  "response_modalities": ["text"]
}
```

图片用`modality: image`和`regions: [{label, box: [x1,y1,x2,y2]}]`，坐标归一化到0至1；音频用`modality: audio`和`data:audio/wav;base64,...`或`data:audio/mp3;base64,...`，同样可附`segments`。所有时间以秒计，开始必须小于结束且不超出实际时长。

安全题另外填写原有`safety.dimension/rubric/evidence`、预期行为和答案锚点。界面中的证据文字不能替代真实媒体附件。

## 模型能力与视频处理方式

在模型管理中明确声明输入和输出，例如：

```json
{"input":["text","image","audio","video"],"output":["text","audio"]}
```

只填写供应商确实支持的能力。能力随模型版本访问配置冻结；更新当前模型不会给旧版本增加能力。创建任务和执行时均校验，不能靠选择“视频”场景绕过。

| 方式 | 发给模型的内容 | 能力要求与边界 |
| --- | --- | --- |
| 原图 | image_url图片块 | text/image输入，至少text输出 |
| 原始音频 | input_audio块中的WAV/MP3字节 | text/audio输入；未转写为文本替代原始音频 |
| 原生视频 | video_url块中的完整视频字节 | video输入；含音轨时还要求audio输入。端点须兼容该消息格式 |
| 视频抽帧 | 带实际时间戳的图片块；存在音轨时另发完整音轨 | 无音轨需image输入，有音轨需image/audio输入。只覆盖实际采样时间点，非连续画面理解 |

未设置`frame_timestamps`时，抽帧模式默认在全片范围选择4个请求时间点，最多允许8个。系统读取解码后的真实帧PTS，选取请求时间前最近的有效帧，并分别保存请求时间和实际帧时间。低帧率视频中这两者可能不同，多个请求也可能对应同一实际帧；不得把重复帧当成更多时间覆盖。

原生视频与音画联合能力不能仅依据注册声明认定可用。当前DeepSeek Flash可处理图片，适用于抽帧；不支持的音频或原生视频组合会阻止执行，不会自动丢弃音轨。

## 音频输出

样本可配置：

```json
{
  "response_modalities": ["text", "audio"],
  "audio_output": {"voice": "alloy", "format": "wav"}
}
```

要求模型同时声明text/audio输出，并使用兼容Chat Completions音频协议的真实端点。voice须使用供应商支持的名称，返回格式支持WAV/MP3。请求音频但供应商只返回文字时，样本记为模型失败，不伪造音频。

平台保存实际返回的可解码音频、校验和以及供应商提供的转写。文本规则只能评价已配置文本范围；声学、情绪、音色和实际语音内容安全需要支持音频的裁判或专家复核。安全模型裁判会收到实际生成音频，不能只看转写。

## 执行与复核

1. 在任务列表核对模型、数据和工具，查看进度、创建时间、创建人及操作列。
2. 打开详情，展开逐条结果，查看实际处理范围、原图或音视频播放器。
3. 点击参考时间段定位原音视频；展开视频帧清单，检查实际发送的帧、时间和校验和。
4. 安全任务中，专家复核和人工金标窗口也可播放原始媒体。自动评分、复核和金标是不同记录。
5. 按输入模态查看有效题数、得分和维度覆盖；无实测或无人工标注的项保持缺测。校准一致率及绝对分差分模态统计。
6. JSON报告保留完整原始与派生证据，HTML可播放媒体；其他文档格式的摘要不能替代JSON中的完整证据。

## 工具底座

“多模态媒体检查”内置工具经统一网关执行，接收`{"media":[...]}`，返回格式、时长、音轨、校验和及实际抽帧时间。它没有score/passed，不参与正式安全评分。

注册Tool、Skill或MCP时，可在向导声明`capabilities.input_modalities`，输入Schema使用media数组。网关会校验实际媒体，声明与输入不符则拒绝；媒体通过JSON参数传给HTTP/MCP及工作流。Skill步骤有input绑定时必须显式映射`$input.media`，未映射的字段不会自动传给下游；完全没有input绑定时，兼容路径会合并全部输入，建议显式绑定以明确传输范围。文本规则工具的分数仍只代表文本规则，不代表该工具理解了媒体内容。

## 编排 Agent

要求Agent先读取授权资源，再选择匹配的数据和模型。资源清单含模态与样本数，计划media_summary含输入输出、处理方式和数据版本内容校验和。能力不足、版本不属于对象或媒体格式错误会进入预检错误；调整后重新审批。

批准后仍由TaskService创建、排队和执行任务。任务证据向Agent提供结果引用、模态、处理方式、时间和校验和，不把大段base64当作文本推理上下文。规划模型读到这些摘要不等于直接听过音频或看过完整视频；报告应引用真实裁判和人工复核。

## 实测范围

2026年10月25日通过当前业务API完成图片任务#48、安全图片任务#49；视频任务#50、安全视频任务#51及Agent会话#22审批创建的任务#52，共6条视频结果真实调用DeepSeek。视频为人工生成的无音轨小样本，仅验证抽帧时序与视频内提示注入闭环。

音频实现经过隔离合同测试，按用户要求本轮未运行真实音频模型验收。原生视频与带音轨联合输入也未完成真实端点验收，不能以无音轨抽帧结果替代。图像生成、隐式水印和完整安全认证不在本次实现范围内。
