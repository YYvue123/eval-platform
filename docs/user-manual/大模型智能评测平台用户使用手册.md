## 阅读说明

本手册帮助操作人员完成评测数据准备、模型接入、任务执行、结果复核和日常管理，并重点说明编排 Agent、Skill、MCP、工具及记忆的使用关系。首次使用建议先阅读第1至3章，再按第4至9章完成一次小规模真实评测；使用评测助手时重点阅读第14至19章。服务运营人员和企业客户重点阅读第23章；完整岗位步骤、API接入与异常处理另见本目录《评测服务用户手册 运营方与客户方》。

原版以代码基线 ca2c92327a4206cef3dfdb0621b4aa4c667cd1d5 编写；版本1.1修订评测服务及相关账号、权限和记录查询说明；版本1.2按2026年10月24日实现更新Agent工具循环、子Agent、MCP调用、知识复用和相关操作指引，版本1.3补充平台模型按企业授权、模型与冻结版本的区别及产生方式、撤销与重新授权；其他章节保留此前核对范围。系统升级后，按钮、门禁和能力范围可能变化；实际部署中的账号授权、服务配置和接口响应决定能否执行。文中的菜单路径以当前前端为准，接口操作供获得授权的管理员或集成人员使用。

能力说明分三类：“页面可操作”表示当前页面和对应代码存在该路径；“接口或管理员操作”表示需使用接口或部署配置，普通页面没有完整入口；“设计目标或当前限制”表示不能当作现成功能使用。页面存在、规则校验成功与生产验收通过是不同结论。试跑、模拟器、启发式评分及未执行项不得作为正式验收通过证据。

## 1 系统能做什么

### 1.1 平台的主要用途

平台将一次模型评测组织成可追溯的业务过程：明确目标，选择数据与模型版本，配置提示词和打分工具，提交执行，逐条记录模型输出与评分，形成报告，再决定是否进入可比较榜单或交付服务单。它也管理支撑这些过程的工具资源、审批、角色权限、通知、审计及运维记录。

平台中的“被测模型”负责回答评测问题；“打分工具”负责按约定规则评价回答；“规划模型”供 Runtime 选择工具和生成助手回复。三者职责不同。同一个模型记录可以因配置被用于不同场合，但操作人员必须明确本次选择的是哪种用途，避免把规划模型的回复当成被测模型的成绩。

### 1.2 功能与产出

| 工作 | 主要入口 | 操作后应得到什么 |
| --- | --- | --- |
| 管理评测样本 | 评测底座 → 评测数据 | 数据集、版本、样本、校验和与操作历史 |

| 接入真实模型 | 被测模型 | 模型记录、接入配置、版本、探测及调用记录 |
| 管理提示词 | 提示词工程 | 可预览、审核、发布和恢复的提示词版本 |
| 接入和验证工具 | 工具底座 | Tool、workflow Skill 或 MCP 连接，以及实际调用记录 |
| 组织评测 | 任务管理、任务模板 | 固定资源配置的评测任务、进度、逐样本结果与报告 |
| 查阅专项能力 | 基准套件、安全可信 | 套件就绪信息、金标样本、安全试评和专家复核记录 |
| 辅助编排评测 | 编排Agent | 目标、计划、澄清、审批、关联任务和分析证据 |

### 1.3 使用前必须理解的边界

设计文件提出了大规模并发、完整行业评测、丰富的 Agent 协作和工具动态接入目标。当前不能据此承诺所有行业题库齐备、所有媒体推理可用、全部外部 MCP 已联调，或生产性能指标已实测达标。某项专项能力是否可用，需要看套件 readiness、资源连接、真实调用和结果证据。

当前评测助手先建立规则草案，再自动通过LangGraph调用真实规划模型和规划子Agent，核对授权资源后更新计划。可用工具包括资源检索、知识检索、计划建议、子Agent协作和已启用MCP等，详见第16章。注册Skill或MCP后仍需配置工具权限与会话启用范围。

当前 Skill 执行器完整支持的是 workflow 顺序链。设计中的 prompt_template、code、agent 类型不能按已实现执行能力使用。界面中的异步调用选项也明确标为未完整验收。

## 2 账号 登录与权限

### 2.1 首次登录

1. 向管理员取得本环境访问地址、个人账号、初始密码及所属角色。使用管理员提供的地址，不自行假设开发端口就是生产入口。
2. 打开登录页，填写账号和密码，按页面提示登录。失败时记录错误提示；不要连续更换账号尝试绕过权限。
3. 进入个人中心核对身份和联系方式，需要时修改密码。公共终端使用结束后退出登录。
4. 检查左侧是否出现本岗位需要的菜单。菜单缺失通常与授权有关；不能仅凭其他人的截图判断系统未部署该功能。

企业客户的初始密码由运营人员设置或生成，至少12个字符并包含字母和数字。平台不提供旧密码明文查询，忘记密码由运营方重置；企业或成员停用、删除后不能继续登录使用评测服务。

生产环境必须由管理员设置非默认 SECRET_KEY 和安全的初始化账号。开发文档中的默认口令不适合作为生产登录说明，也不应在岗位交接中共享管理员账号。

### 2.2 默认角色与岗位分工

| 角色 | 常见权限范围 | 需要注意 |
| --- | --- | --- |
| 管理员 | 全部权限、用户角色维护、资源注册和运维管理 | 不建议作为多人共用的日常评测账号 |
| 评测人员 researcher | 数据与模型准备、提示词操作、工具调用、任务执行、Agent 使用和确认 | 默认不等于拥有数据审核、资源注册、榜单发布等全部管理权限 |
| 访客 viewer | 多数业务列表、详情和榜单的查看 | 一般不能调用模型、运行任务或审批计划 |
| 企业客户 customer | 本企业服务空间、成员添加、接入方密钥、模型服务版本、评测执行及操作记录 | 不获得平台后台及跨企业管理权限；同企业成员共享服务资产 |
| 服务运营岗位 | 由管理员授予企业管理、额度定价和企业记录查询权限 | 不是独立的默认角色名；不向客户授予跨企业管理权限 |

上述为初始化定义，实际角色可在权限管理中调整。默认评测人员包含 agent:confirm，故“审批按钮”并不天然保证另一人复核。需要双人审批时，应由组织明确职责并调整授权，而不是只依赖按钮名称。

### 2.3 为什么能看到页面却不能操作

页面权限、动作权限、数据可见范围和模型调用 ACL 是几层不同的控制。例如 resource:list 允许进入工具底座，resource:invoke 才能试用；agent:view 允许读会话，agent:invoke 允许生成计划或运行，agent:confirm 允许审批和采纳建议。

有按钮但接口返回403时，保留页面路径、账号、对象编号和错误信息，请管理员检查功能权限与对象范围。接口返回404也可能表示对象不可见。不要通过修改网址中的编号访问他人的记录。权限调整后刷新页面，必要时重新登录。

### 2.4 列表与页面通用操作

列表通常支持搜索、筛选、分页和详情。找不到记录时先清空筛选，检查页码，再检查角色及数据范围。加载失败、没有权限和暂无数据是不同状态；出现加载错误时不要直接新建一个同名对象。

提交按钮显示处理中时等待响应；网络超时后先查询对象是否已创建再决定重试。后台可能已经接受请求，浏览器未收到响应不代表操作未发生。

## 3 第一次完成真实评测

### 3.1 准备一份小数据集

建议首次使用2至5条无敏感内容的样本，专门创建小数据集控制用量。不要只依赖“试跑”开关限制样本数：当前任务执行器没有因 trial_run 自动截取固定小样本的通用逻辑。

示例 CSV 可使用以下内容，保存为 UTF-8 文件。它只用于熟悉操作，不代表正式基准题库。

```csv
input,reference
只回答数字 1加1等于多少,2
只回答中文 中国的首都是哪里,北京
```

### 3.2 从准备到下载报告

1. 在评测数据点击“新增数据集”，填写名称、任务类型 qa、领域 general 和用途说明。
2. 进入详情，点击“选择文件”；在“确认字段映射”中将 input 映射到输入，reference 映射到参考答案，检查预览后“确认导入”。
3. 点击“质量检测”，查看质量报告；需要正式评测时先修复问题，再完成审核和发布。
4. 在被测模型点击“注册模型”，填写真实接口地址、服务端模型名、通道和凭证。保存后“探测”，再“试调用”一次，确认确实得到模型输出。
5. 在任务管理点击“创建任务”，选择小数据集、模型及“精确匹配打分”。首次联调打开“仅测试”，设置能覆盖小样本的 Token 配额。
6. 创建后进入任务详情点击“执行”，观察排队、运行和最终状态。若失败，先检查事件及错误，不连续重复执行。
7. 核对每条输入、模型输出、参考、执行状态、打分状态和得分。精确匹配严格，额外说明可能影响结果；分数低不一定表示连接失败。
8. 报告生成后下载 JSON、Excel、Word 或 PDF。报告记录的是本次数据和配置下的结果，不直接证明模型在所有场景有效。

### 3.3 完成标准

完成一次操作练习需要看到真实模型输出、可解释的评分、任务最终状态和可下载报告。连接探测成功、任务创建成功或 Agent 回复“完成”都不能替代这四项核对。若准备正式结果，还必须满足数据发布、质检、模型连接、所选提示词发布及正式模式等门禁。

## 4 评测数据管理

### 4.1 新建与命名

入口为“评测底座 → 评测数据”。建议名称包含业务、样本用途和日期，例如“客服问答回归集 20260929”。任务类型描述样本用于问答、摘要或安全等工作；领域描述业务范围；描述中填写来源、授权、适用范围及是否含敏感信息。

新建只产生数据集容器，样本需在详情页导入。列表中的条数、当前版本、质量和发布状态应一起看：有条数不等于已质检，已质检也不等于已发布。

### 4.2 文件格式与字段映射

解析器支持 CSV、JSON、JSONL、TXT、ZIP 和 Excel 路径。优先使用 CSV、JSONL 或 XLSX；旧 XLS 文件如解析失败，转存 XLSX 后重新预览，不要只修改扩展名。ZIP 中内容仍需符合支持的样本格式，上传压缩包不意味着任意媒体都能推理。

| 标准字段 | 填什么 | 常见源列名 |
| --- | --- | --- |
| input_content | 发给被测模型的主要输入 | input、question、prompt、问题 |
| reference_answer | 用于比对的参考答案或标签 | reference、answer、label、参考答案 |
| expected_output | 结构化或专项任务的预期输出 | expected、expected_output |
| task_requirement | 该条样本的任务要求 | instruction、requirement、任务要求 |
| difficulty_level | 难度分层 | difficulty、难度 |
| data_label | 数据标签 | data_label、tag、标签 |

1. 进入数据集详情并选择文件，等待服务端解析预览。
2. 检查总条数和前几行，确认编码、列名和内容没有错位。
3. 逐项核对字段映射，尤其避免将参考答案映射到输入。多列含义相近时不要完全依赖自动建议。
4. 不使用的字段可不映射，但所用评分方式需要的参考或预期字段不能遗漏。
5. 点击“确认导入”，核对新版本、条数、校验和与样本列表。

重复校验和提示表示相同文件已经存在；继续导入仍可能产生新版本。若目的是恢复历史版本，应使用版本回滚，不要重复上传制造难以区分的版本。

### 4.3 质检 审核与发布

导入后点击“质量检测”。质量不为 passed 时先进入数据质量处理问题，完成复检。按照组织流程点击“提交审核”，由有权限的人员审核通过或退回；收到退回时查看审核意见，修正数据再提交。

“直接发布”属于有权限用户的入口，当前页面要求质检 passed 才能点击。发布前核对当前版本，防止发布的是刚导入但尚未复核的新版本。正式任务应使用已发布且质检通过的数据，不用试跑开关规避正式交付要求。

### 4.4 版本 回滚与导出

版本区展示版本号、条数、质量和校验和。回滚前记录当前版本，确认目标旧版本符合本次业务目的，再点击相应“回滚”。回滚改变后续选用的当前版本，已经冻结在历史任务中的版本仍需按历史记录追溯。

导出用于人工复核、备份或经批准的交付。普通导出和敏感数据导出具有不同权限；不得将脱敏结果当作原始完整数据，也不能因有导出按钮就忽略数据授权。删除通常是业务状态变化，不等于历史任务及审计痕迹被清空。

### 4.5 图片 音频 视频与版本冻结

在样本预览中展开一题，可添加PNG/JPEG/WebP图片、WAV/MP3音频或MP4/WebM视频。图片每个最多10MB，音视频每个最多25MB、最长120秒，每题最多8个附件。文件必须内嵌实际字节，不能仅填写可变外链。批量JSON使用media数组，可附图片regions区域及音视频segments时间段；详细字段见本目录《多模态评测操作指南》。

添加附件或切换“模型输出模态”会创建新版本，并重新要求质检和发布；旧任务仍使用旧版本的媒体和标注。输出可选文本或文本及音频，后者要求被测模型声明音频输出能力。

添加视频前选择“视频抽帧及音轨”或“原生视频”。抽帧保存请求时间、实际帧时间和帧校验和；低帧率视频的两种时间可能不同。有音轨的视频必须连同音轨发送给具备相应能力的模型，不允许静默忽略声音。

## 5 数据质量与问题处理

### 5.1 看懂检测报告

入口为“评测底座 → 数据质量”，包含“检测报告”“问题工单”“检测规则”。报告中查看数据集编号、得分、结论、问题数和摘要；点击“问题”定位具体样本。若报告可下载，应保留与发布版本对应的报告，不混用不同版本的质检结果。

质量规则用于识别缺失、重复、内容一致性等问题，规则检测并不能取代业务专家核对参考答案。尤其对行业知识、敏感信息和多模态引用，应结合原始来源人工确认。

### 5.2 四种处理方式

| 动作 | 适用情况 | 操作后检查 |
| --- | --- | --- |
| 忽略 | 已确认告警可接受 | 记录依据；忽略工单不等于样本自动修好 |
| 复核 | 人工已核对该问题 | 查看处理状态，确认仍需不需要改数据 |
| 修复并复检 | 当前规则支持可执行修复 | 检查修订版本、修复内容和新检测结果 |
| 删除条目 | 样本无效且允许移除 | 核对剩余条数及版本，重新评估覆盖范围 |

步骤为：先阅读规则编码与问题说明，定位样本，选择与问题匹配的处理方式，再返回检测报告查看最新结论。不要为了让工单数归零批量忽略真实错误。

### 5.3 规则启停

有 quality:edit 的人员可在“检测规则”中切换启用状态。停用规则会影响后续检测范围，因此操作前记录原因及受影响的数据类型，操作后重新质检。不能通过停用必要规则把不合格数据变成形式上的通过。

## 6 被测模型接入

### 6.1 注册模型

入口为“评测底座 → 被测模型 → 注册模型”。按“基础”“接入”“元信息”填写。内部与外部企业来源用于管理和追溯；在线评测与远程加密访问用于描述接入方式，选择某种方式不代表连接已配置成功。

| 字段 | 填写方法与影响 |
| --- | --- |
| 名称 | 用于人员识别，应区别供应商、型号和用途 |
| 接口地址 | 填真实推理服务 URL，具体路径按服务实现确定 |
| 模型名 | 服务端接受的模型标识，不能仅填平台展示名称 |
| API Key | 按服务要求填写；编辑时不修改可留空，不写入需求文本 |
| 通道 | HTTPS、mTLS、VPN、网关等；plain 仅用于允许的联调环境 |
| 超时和重试 | 依据服务响应能力设置；大重试次数可能增加成本与等待 |
| 请求模板 | 可选 JSON，按当前适配器约定使用 {{prompt}} 和 {{model}} |
| 响应映射 | 指定输出及用量路径，例如 choices.0.message.content 与 usage.total_tokens |
| 场景白名单 | 非空时限制可调用场景；空表示没有该项白名单限制 |
| 并发上限 | 资源配置值，不是生产容量已经通过测试的证明 |

### 6.2 验证连接

1. 保存模型，返回列表点击“探测”，查看健康状态与探测说明。
2. 点击“试调用”，输入一条简单且无敏感信息的提示词，点击“发送”。
3. 检查是否有真实输出，以及调用记录中的状态、时延、Token 和错误信息。
4. 若探测成功但试调用失败，重点检查推理路径、模型名、请求体与凭证；健康探测只说明被探测地址的响应情况。
5. 响应映射错误时，服务即使返回200也可能没有可提取的文本或用量，应由接入人员核对响应格式。

### 6.3 版本与调用授权

打开“详情”，在版本区新增版本并按需要“启用”。版本切换前记录该版本对应的实际服务配置；平台登记了新版本，不代表模型供应商自动完成升级。

调用授权区可按用户 ID 添加“允许调用”，也可删除授权。能查看模型不等于能调用模型；任务执行报无调用权限时，应检查用户授权和场景白名单。

### 6.4 规划模型的额外要求

用于 Agent Runtime 的模型除了有 api_url，还需要兼容当前工具调用适配路径，正确处理 messages、tools 与 tool_calls。普通文本试调用成功仍不足以证明工具循环可用。应在评测助手的“执行明细”中核对一次真实模型决策和工具调用。

规划模型 Token 预算与评测任务预算分别记在 Run 和 Task 上。即使页面使用相同数值，也不能将它们当作同一个已统一结算的钱包。

## 7 提示词工程

### 7.1 创建和预览

入口为“评测底座 → 提示词工程”。点击“新增模板”，填写名称、适用任务、标签及正文。正文可使用 {{input}} 表示样本输入。先点击“预览填充”检查替换结果，确认要求、输出格式和变量名称一致，再保存。

可使用“自动生成”按任务类型与指标生成草稿；生成内容需人工审核。当前生成和优化包含规则化处理，不应认为每一次都由大模型完成语义优化。

### 7.2 审核 发布和历史版本

草稿或退回状态可“提交审核”，审核权限用户处理待审记录。正式任务选用提示词时应选已发布版本。编辑器的“优化并出新版本”会影响版本管理，执行前保留基线内容，执行后核对变更再决定是否发布。

详情可复制、查看版本和操作历史，历史版本可“恢复”。复制适合创建独立实验分支，恢复适合切回已确认版本；两者都不应被理解为已经重跑历史任务。

### 7.3 小样本测试

在提示词详情选择数据集和模型，点击“跑5条”。检查得分、对照与样本数，并结合模型调用情况判断模板是否可用。小样本结果只证明这些样本上的表现，不足以代表完整数据集。

### 7.4 实验入口的当前限制

详情中的“跑实验”提供 develop/holdout 划分、候选版本和“尝试发布”入口，但当前 prompt_experiment 实现含规则渲染和参考匹配的评测桩，没有完成真实模型的成对推理评估。其 holdout 差、significant 或建议发布字段不能作为真实模型提升证据。

需要正式比较时，分别使用基线和候选提示词建立真实评测任务，固定相同数据版本、模型版本与裁判规则，对逐样本结果复核后再人工决定发布。不要仅凭实验页的“建议发布”签署效果提升结论。

## 8 任务创建与执行

### 8.1 选择任务创建入口

按评测类型选择入口，创建后统一回到任务管理查看执行状态、逐样本结果和报告。

| 创建入口 | 当前支持范围 | 使用说明 |
| --- | --- | --- |
| 任务管理 → 创建任务 | 普通能力测试、场景应用、行业专项 | 手动选择数据集、模型、提示词、打分工具和预算；当前弹窗没有完整的安全专项配置 |
| 任务模板 → 使用 | 从模板预填普通任务配置 | 模板只提供配置起点；安全分类模板不能替代安全专项配置 |
| 安全可信 → 发起安全评测 | 完整配置文本安全可信任务 | 配置安全基准、指标权重、多轮追问、自适应、情境对照及可选裁判融合，详见第21章 |
| 编排Agent | 通过对话规划普通任务或安全可信任务 | 安全任务须形成安全专项配置并经人工确认，详见第21.10节 |

“安全任务在任务管理中执行”不表示“任务管理的创建弹窗已能完整配置安全任务”。后端创建任务接口支持安全协议配置，但普通弹窗尚未提供对应字段；操作人员创建安全任务时，应使用安全可信页面或编排Agent。

### 8.2 创建表单逐项说明

| 字段 | 操作要点 |
| --- | --- |
| 任务名称 | 写清业务、模型版本、数据版本及试跑或正式用途 |
| 任务模板 | 可预填类型、场景、行业和裁判；应用后仍需逐项核对 |
| 类型 | 普通创建弹窗可选能力测试、场景应用、行业专项；安全可信任务使用第21章的创建入口 |
| 场景和行业 | 与数据、模型能力及白名单一致；名称相近不代表编码相同 |
| 优先级 | 当前界面范围1至10；不要据此承诺立即开始执行 |
| 依赖任务 | 选择确有业务依赖的任务，系统会拒绝循环依赖 |
| 数据集和模型 | 选择正确对象，并核对其当前版本和就绪状态 |
| 提示词 | 可选；正式使用时必须满足发布条件 |
| 打分工具 | 选择能解释本任务答案的规则；可选注册Tool、评分Skill及同步目录中的MCP工具 |
| 仅测试 | 打开表示试跑，不表示模拟调用、免费调用或自动缩减样本 |
| Token 配额 | 0表示不限制；建议真实执行设置经批准的上限 |

任务表单可列出已注册Tool、带评分声明的Skill及已同步目录的MCP工具。须核对返回的score/passed及实际兼容性，不能把任意MCP文本当成评分。媒体检查工具只输出元数据，不作为裁判选项。

### 8.3 执行前核对

检查数据集已发布且质检通过，模型真实 endpoint 可用，所选提示词已发布；核对模型 ACL、白名单和预算。通过“提交审核”进入待审时，由有 task:audit 的人员处理。按钮出现并不代表后端状态和全部业务门禁都满足，应以接口实际校验为准。

点击“执行”后通常先进入 queued，再由执行器领取。页面保留任务 ID 后可离开再回来查看，不需要保持浏览器持续打开来执行任务。

当前普通任务执行接口并未统一强制“先审核后执行”，不能把任务列表的审核按钮当作不可绕过的审批控制。组织要求正式任务必审时，必须按岗位流程执行并由管理员补齐环境控制；Agent计划审批则有独立的hash与消费逻辑，两种审批不能混同。

### 8.4 状态与下一步

| 状态 | 含义 | 推荐动作 |
| --- | --- | --- |
| draft | 已建档但尚未执行 | 核对配置，按流程提交审核或执行 |
| pending_review | 等待任务审核 | 联系审核人员，不重复创建 |
| queued | 已排队 | 检查依赖及运行支撑，不连续点击执行 |
| running | 执行器正在处理 | 观察进度、逐样本结果和事件 |
| success | 执行流程达到成功状态 | 继续核对评分、覆盖率和报告，不能只看绿色状态 |
| partial_failed | 有部分失败 | 区分业务不通过、模型失败及裁判错误 |
| failed | 执行失败 | 记录错误、定位原因后再重试 |
| paused_budget | 预算不足而暂停 | 交由负责人处理预算，不能假定等待会自动恢复 |
| cancelled | 已取消 | 保存已有证据，需要继续时按新决策重试或新建 |

### 8.5 取消和重试

取消排队任务与取消正在执行的任务不同。正在执行时系统先设置取消请求，执行器到达检查位置后退出，因此按钮点击后可能不是立即终止；已经发生的模型调用仍可能计费。

任务“重试”默认会清除已有逐样本结果，重置汇总和用量字段并增加尝试次数。需要留存原始结果时先导出，或新建对照任务。重试后的计数不一定代表所有历史尝试的累计外部费用。

Agent 中采纳 retry 建议的路径与任务详情的重试实现不同，当前建议路径主要将任务重新入队，不能承诺与清空结果后的完整重跑等价。需要明确重跑语义时优先在任务详情操作并核对事件。

### 8.6 任务信息与操作

列表和详情均展示进度、创建时间、创建人；列表的操作列固定在右侧，提供详情及按权限、状态开放的提交审核、审核、执行、取消、重试。时间按浏览器本地时区展示，系统创建或已注销用户显示相应占位。绿色成功状态仍需结合逐题评分与测量范围核对。

## 9 任务结果与报告

### 9.1 任务详情阅读顺序

先看任务状态和错误，再看进度及成功、失败、跳过数量，随后逐条检查结果，最后读取汇总报告。详情还展示模板、场景、行业、尝试次数、Token 配额、已用量、批次、快照、工具版本、checksum 和 trace。

Lease 与 Fencing 是执行器防止重复领取或过期执行器回写的技术信息，普通操作人员只需在报障时提供，不修改这些值，也不要直接编辑数据库“修复进度”。

### 9.2 区分执行与评分

| 看到的字段 | 如何理解 |
| --- | --- |
| model_output | 被测模型实际返回的文本；不能用参考答案替代 |
| execution_status 为 ok | 推理阶段得到结果，仍需看评分状态 |
| model_failed | 模型调用失败，不能解释为模型答错题 |
| score_status 为 scored | 评分已执行，可进一步解释分数 |
| score_status 为 error | 裁判出错，不能把显示的0分当作有效失败判定 |
| skipped 或 not_run | 没有完成相应阶段，应核查跳过原因和覆盖范围 |
| passed 为 false | 需结合执行、评分状态，判断是业务不通过还是技术错误 |

精确匹配适合标准答案、标签和固定格式；包含匹配适合确认预期片段；模糊匹配给出文本相似程度，不能直接代表专业正确性。开放问答和行业判断需要经验证的裁判规则与人工复核。

### 9.3 下载与重渲染

报告路径可用时可下载 JSON、Excel、Word、PDF。JSON 适合集成和证据核查，Excel 适合逐样本筛查，Word/PDF 适合阅读与交付。下载前确认任务编号和报告对应的尝试，下载后抽查样本数与页面是否一致。

“重渲染报告”针对已有结果生成报告文件，不重新调用被测模型，也不修正错误评分。任务已结束但报告尚不可用时，先查看生成错误或请有 task:edit 的人员重渲染；不能仅因缺少文件就重跑全部模型调用。

### 9.4 正式交付核对表

- 数据、模型、提示词和裁判版本可追溯，模式为正式，场景和行业正确。
- 样本量与实际执行量一致；跳过、未执行及裁判错误已单独说明。
- 有真实模型输出，没有将演示、模拟器、启发式桩或参考回填当成真实推理。
- 分数和通过率的含义与裁判规则一致，人工复核事项已完成。
- Token 用量未知时明确标记未知；费用估算没有被写成供应商实际账单。
- 报告可打开，任务 ID、版本、日期和交付对象正确。

### 9.5 查看原始媒体与实际测量范围

展开逐条结果可查看原图、播放音视频、点击参考时间段定位播放位置，并查看实际发送的视频帧及其时间戳。模型返回音频时另有音频播放器。JSON归档保存原始媒体、校验和、标注及处理方式；HTML归档可播放原始音视频。音视频播放依赖浏览器解码支持。

视频抽帧不能代表帧间连续内容已全部测量；音频转写与关键词得分不能代表声学安全、音色或情绪评估。是否测得应按每题处理方式、裁判输入和分模态统计判断，不按场景名称判断。

## 10 工具底座与资源注册

### 10.1 三类资源的关系

Tool 是单项可调用能力，例如精确匹配或外部评分服务；Skill 将多个已存在能力按顺序组合；MCP 是发现和调用外部能力的协议连接，一个 MCP 服务可公开多个工具。工具底座统一登记它们的身份、版本、连接和输入输出约束。

“工具底座 → 全部 / 工具 / Skills / MCP连接”用于筛选资源。点击名称或“详情”查看 resource_id、类型、版本、状态、健康、输入 Schema 和脱敏 Manifest。内置资源只读；若要定制，创建自己命名空间下的资源，不覆盖 builtin 标识。

### 10.2 注册前准备

准备资源说明、稳定标识、版本、输入输出 Schema、真实服务地址、超时、幂等声明和凭证引用。幂等表示同一请求重试是否会产生重复效果；会写外部数据的资源不能为通过校验而随意声明无副作用。

凭证引用通常填写由管理员配置的服务端环境变量名称，变量值才是真实密钥。填写字符串名称本身不会自动创建凭证。资源注册账号通常需要 resource:create；普通评测人员默认主要具备查看和调用权限。

### 10.3 使用五步向导

1. 点击“添加资源”，选择 Tool、Skill 或 MCP 类型。
2. 在“基本信息”填写命名空间、标识、名称、说明、版本、调用方式及幂等性。例如命名空间 team、标识 answer_judge 将形成 team/answer_judge。命名空间使用小写字母和数字，标识可使用小写字母、数字与下划线。
3. 在“参数 / 连接”填写该类型所需配置。Tool 填 HTTP 地址、方法、超时和凭证引用；Skill 填步骤及引用；MCP 填传输和连接信息。
4. 为输入字段选择类型和必填性。简单字段可用表格编辑，数组、嵌套对象、enum、oneOf 等高级 Schema 使用 JSON，避免转换为简单表格时丢失约束。
5. 点击“运行已实现检查”，逐项阅读结果；修正后重新检查。静态 Schema 或引用检查通过不代表真实调用已验证。
6. 在“确认”核对最终 Manifest，点击“确认注册”。原始 Manifest JSON 会覆盖向导字段，粘贴后要再次核对标识与连接。
7. 回到列表查看注册状态，打开试用台进行真实调用。注册成功只是登记完成，不是服务能力验收。

### 10.4 实际试用

点击资源的“试用”，按 Schema 填写参数。先用小规模无敏感输入，确认类型正确后点击“实际调用”。输出区查看业务结果、错误、服务端执行耗时、trace 和原始脱敏响应；历史区用于追踪多次尝试。

例如试用 builtin/exact_match，可填写 prediction 为“北京”、reference 为“北京”。随后把 prediction 改为不同内容再调用，观察结果差异，确认确实按输入计算，而不是只看某次成功提示。内置比较器用于解释匹配规则，不证明任何被测模型已经完成推理。

### 10.5 副作用与失败处理

当前副作用策略在没有受控真实执行路径时会返回 SIDE_EFFECT_BLOCKED 或 SIDE_EFFECT_DENIED，不提供假成功。遇到此类错误应交给资源负责人处理，不能删掉 side_effects 声明绕过。

Schema 错误先检查字段类型和必填项；超时检查服务及网络；凭证错误检查服务端引用；版本或幂等冲突先核对原请求。只有确认前次没有产生不可重复效果，且资源语义允许时，才重新发起调用。

详情页当前没有完整资源版本时间线入口。需要追踪冻结版本时，应结合任务血缘、调用记录或管理员接口，不把资源详情里的当前版本当作所有历史任务的版本。

### 10.6 外部工具响应的核对方法

外部HTTP工具接收的是平台适配后的调用信封，接入人员应按接口文档核对header、trace与body，而不是假设只会收到一段prediction文本。当前适配器要求响应明确给出status为success，并拒绝stubbed、mocked、isError或协议错误。

评分工具的简化成功响应可包含以下结构；完整接口以平台适配约定为准。只返回{"ok":true}或HTTP200不足以作为成功判定。

```json
{
  "status": "success",
  "result": {
    "score": 1.0,
    "passed": true,
    "metrics": {"accuracy": 1.0}
  }
}
```

遇到HTTP429或资源熔断时，查看Retry-After和错误说明，等待指定冷却时间并检查下游故障，不连续点击试用。网关限流和熔断用于保护服务，不证明已达到原始设计的生产吞吐指标。

## 11 Skill 的创建和组合

### 11.1 平台 Skill 的定义

本平台 Skill 是 Manifest 中 skill.execution_type 为 workflow 的资源，执行器按 skill.chain 顺序调用下游资源。它不是把一篇自然语言 SOP 上传后就能任意执行的通用代理，也不是开发工具中的 SKILL.md 文件。步骤做什么、参数从哪里来，都要显式配置。

当前链是顺序执行，不应按任意分支、并行 DAG、自动补偿或事务回滚使用。任一步失败时会中止后续步骤，并报告失败步骤、错误码和此前已完成步骤。前面调用产生的外部效果不会因为后续失败自动撤销。

### 11.2 先验证每个底层工具

建 Skill 前先分别试用所有下游工具，记录输入 Schema、输出路径和错误行为。例如想把“提取数值”的结果交给“单位转换”，必须确认前者确实输出 values，后者确实接受 values 和 target_unit。示例字段名不是平台替你安装的实际工具。

普通向导的步骤选择器主要使用已上线 Tool 列表。后端网关具备资源分派能力，但涉及 MCP 或其他复合资源的链配置，应由集成人员通过完整 Manifest 验证；不能假定普通下拉里能够直接选择所有 MCP 工具。

### 11.3 配置步骤

1. 添加资源时选择 Skill，设置唯一标识和用途说明。
2. 为每步填写唯一 step_id，例如 s1、s2；选择已验证的工具。
3. 填写每步 input JSON。第一步通常引用整体输入，后续步骤可引用前一步输出。
4. 点击“加步骤”扩展链，删除无用步骤后重新检查引用。
5. 在校验页运行引用检查，注册后再从 Skills 页真实试用。

| 写法 | 含义 | 使用条件 |
| --- | --- | --- |
| {"$ref":"$input.prediction"} | 从本次 Skill 输入取 prediction | 调用者必须提供该字段 |
| {"$ref":"$input"} | 取整个输入对象 | 下游确实接受该对象结构 |
| {"$ref":"s1.output.values"} | 取已完成 s1 的输出 values | s1 在前且输出有该路径 |
| {"$ref":"step_0.output"} | 取第一个步骤输出 | step_0 为从0开始的索引写法 |
| {"$ref":"$global.some_key"} | 取输入中显式提供的 $global 对象 | 不是自动注入的 Agent 全局记忆 |

引用是一个含 $ref 键的对象，不是把 "$input.text" 随意写成普通字符串。不要前向引用尚未执行的步骤，也不要引用自身。缺失路径可能解析为空，后续是否拒绝还取决于 Schema；真实试用时必须检查实际传值。

### 11.4 可复现的双裁判练习

内置 builtin/skill_dual_judge 把精确匹配与模糊匹配组合起来。两步都接收同一个 prediction 和 reference，不依赖外部服务，可用于理解 Skill 如何工作。

```json
{
  "execution_type": "workflow",
  "chain": [
    {
      "step_id": "exact",
      "resource_id": "builtin/exact_match",
      "input": {
        "prediction": {"$ref": "$input.prediction"},
        "reference": {"$ref": "$input.reference"}
      }
    },
    {
      "step_id": "fuzzy",
      "resource_id": "builtin/fuzzy",
      "input": {
        "prediction": {"$ref": "$input.prediction"},
        "reference": {"$ref": "$input.reference"}
      }
    }
  ]
}
```

以上是 Manifest 内的 skill 字段内容，不是完整注册 Manifest。练习时直接打开内置“双裁判技能包”试用，输入相同文本，再输入有少量差异的文本；展开 steps 对比每一步结果。

当前 Skill 汇总对各步骤返回的非空 score 求平均，对返回的 passed 做全真判断；没有 score 或 passed 时相应汇总可能为空。均分高不保证 passed 为真，最后一步 result 也不等于所有步骤的汇总。priority 会作为信息返回，不代表运行时已经按自然语言自动择优选择 Skill。

### 11.5 Skill 和记忆怎样衔接

Skill 的输入来自调用请求，步骤间结果来自显式 $ref。它不会自动读取 Agent 会话记录，也不会自动将输出写入知识库。如果需要复用某次 Skill 结果，应人工核对输出，整理为带来源和适用条件的知识候选，再走知识审核流程。

## 12 MCP 连接与工具调用

### 12.1 连接方式

入口为“工具底座 → MCP连接”，可从顶端按钮打开工作台，也可在已登记 MCP 资源行点击“连接”。注册时当前提供 streamable_http 和 stdio。HTTP 使用真实服务 URL；stdio 使用管理员预先允许的命令别名，普通用户不在页面输入任意系统命令。

原始接口规范要求 stdio 仅用于开发测试、生产使用网络协议，并提出沙箱及进程资源限制。当前别名白名单本身不等于完整容器沙箱或 CPU/内存配额。生产接入必须由部署负责人按环境要求审查，不因前端能选择 stdio 就认为已符合生产规范。

### 12.2 已注册来源与临时来源

工作台的“探测来源”二选一：已注册资源从平台读取 Manifest；临时 HTTP 连接现场填写 Endpoint、Token 与 Egress 白名单。切换来源后重新验证连接和获取目录，不沿用上一个来源的工具名与参数。

临时 Token 用于本次探测，面板关闭后前端会清除；它不是持久注册凭证。正式复用应登记 MCP 资源并由管理员提供 credential_ref。Egress 白名单填写允许访问的主机名，与服务实际主机对应，不能把路径当成主机名。

### 12.3 三步验证

1. 点击“验证连接”，完成 initialize，查看协议版本、服务信息和错误。成功说明协议握手建立，不代表所有工具都能执行。
2. 点击“获取工具目录”，执行 tools/list。检查名称、说明和 inputSchema；目录为空时请服务负责人确认是否公开工具。
3. 选择一个无副作用的小工具，按其 Schema 填参数，点击“测试调用”。查看 content、structuredContent 或其他返回内容以及错误标记，并保存 trace。

修改连接后要重做以上步骤。若出现“目录已变化，请重新获取”，重新加载目录并重新选工具，避免用旧 Schema 调用变更后的能力。

### 12.4 如何理解 MCP 的工具名

MCP 资源的 resource_id 标识整条服务连接；目录中的 name 标识该连接公开的一个工具。它们不是同一个名称。调用时需要明确连接和工具名两层，例如连接 team/statistics，工具名 summarize，参数是 summarize 的输入 Schema 所定义的对象。

协议概念示例如下，实际工具名必须从当前目录选择：

```json
{
  "method": "tools/call",
  "params": {
    "name": "实际目录中的工具名",
    "arguments": {"实际参数名": "实际参数值"}
  }
}
```

工具底座外层调用可能还采用统一信封，请通过试用台或接口文档确认，不将该概念示例直接当作所有平台接口的完整请求。

### 12.5 成功和失败的不同层次

HTTP200只表示传输层返回；JSON-RPC error 或工具 isError 仍表示执行失败。工具返回一段文本也不必然是合格的评分结果。依次检查连接、协议、工具结果和业务含义，不只检查最外层状态码。

当前页面重点覆盖 initialize、tools/list 和 tools/call。设计中的资源读取、提示词发现、长期连接池、完整能力热切换等，应逐项按部署和接口验证，不能因工具目录可用就推定全部完成。

需要让Agent调用时，先保存已注册连接的工具目录，再在评测助手本次会话中启用该连接。主Agent或已授权自定义子Agent可携带arguments实际调用，步骤和限制见第16至17章；临时探测成功不等于已授予Agent调用权限。

### 12.6 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 没有 stdio 别名 | 管理员检查 MCP_STDIO_ALLOWLIST；客户端不能自行添加命令 |
| initialize 失败 | 地址、协议、认证、服务是否启动、网络出口 |
| 有目录但调用报参数错误 | 重新取目录，按最新 inputSchema 填写类型和必填项 |
| 目录变更警告 | 丢弃旧选择，重新获取目录和参数表单 |
| 认证失败 | 区分临时 Token 和注册资源的服务端凭证引用 |
| 超时或传输错误 | 记录 trace、服务端耗时和错误码，检查远端服务 |
| 副作用阻断 | 由管理员设计受控执行路径，不去掉真实副作用声明 |

## 13 批次 快照与分片

### 13.1 为什么冻结批次

批次用于冻结某次批量评测的数据输入与预算，分片用于把样本组织成可跟踪的块。快照不是普通文件复制按钮；创建快照也不会自动选好模型或完成评分。

### 13.2 页面操作

1. 在工具底座点击“冻结批次”。
2. 选择数据集，按需要填写版本 ID，设置分片大小和 Token 预算；当前界面分片大小范围1至500。
3. 点击“创建批次”，记录返回的 batch_id、snapshot_id 及版本信息。
4. 使用“刷新”查看状态。任务若绑定批次，可在任务详情查看批次及分片进度。
5. 不再执行时按允许状态点击“取消”，确认最终状态；已发生的调用不会因此撤销。

普通任务创建表单没有完整批次绑定向导。需要绑定已有 batch_id/snapshot_id 时，由集成人员使用受支持接口，避免把“创建批次”和“创建任务”当作同一动作。

### 13.3 快照清理

运行支撑提供“清理快照”。仅由有权限的人员根据保留策略操作，先确认备份及任务引用。系统的引用保护不能替代交付归档要求，禁止在仍需审计历史结果时直接删除存储文件。

## 14 Agent 的工作方式

### 14.1 先分清三个对象

“编排Agent”是帮助操作评测平台的助手；“被测智能体”是测试对象的一种；“MCP服务”是能力连接。测试一个外部智能体，并不意味着它获得平台内部任务管理权限；接入一个 MCP 服务，也不意味着它成为平台主 Agent。

初始设计强调主 Agent 统一目标，子 Agent 负责专项分析，确定性任务操作交给工具和现有调度系统，知识库支撑经验复用。当前操作时应坚持这一边界：Agent 提出计划或建议，任务系统执行并保存事实，操作人员审阅并确认关键动作。

### 14.2 当前的三条路径

| 路径 | 谁决定下一步 | 操作后应核对什么 |
| --- | --- | --- |
| 计划编排 | 先建立规则草案，再由真实规划模型与规划子Agent核对授权资源并更新；操作人员确认配置 | 等规划分析结束，核对资源ID、版本、模式、预算及摘要，规则草案不作为最终授权 |
| Runtime工具循环 | 真实规划模型在本次启用的工具和能力范围内选择 | 工具参数、结果、回复和运行记录；执行评测仍需用户确认 |
| 专项协作 | 规划、监控、诊断、审校及可选优化角色依据实际上下文运行模型与受控工具，自定义角色按启用范围参与 | 消息旁的具体角色标识、折叠委派记录、实际工具调用和分析依据；当前按需顺序执行 |

当前Runtime使用LangGraph编排。操作人员仍从同一评测助手页面使用，无需编写或编辑流程图。模型可以检索知识、查找资源、更新计划、调用已启用子Agent或MCP，并请求审批执行；不能绕过权限和审批直接修改任务或评分。

区分会话编号、run_id、task_id和委派编号。Run显示success可以表示本轮对话结束；只有实际评测任务和结果满足核验条件时，才会显示评测目标已核验，具体见第16.6节。

### 14.3 Agent Skill MCP 工具和记忆的组合图

```text
操作人员描述目标 → 会话与规则计划 → 补充信息
  → Runtime真实规划模型 → 检索知识、查找资源、更新计划
  → 按需委派自定义子Agent → 子Agent模型与已授权工具 → 返回分析
  → 已启用编排Skill或MCP连接 → 带参数调用 → 结果或错误反馈
  → 核对计划 → 用户在聊天明确“确认执行”（或使用审批与执行按钮）
  → 校验计划版本和权限 → 签发并消费审批
  → 任务服务 → 被测模型与裁判 → 实测结果和报告 → 执行结果核验

人工整理有效经验 → 知识候选 → 审核 → 有效知识条目
  → 在租户、权限和查询条件允许时由模型检索
```

工具底座中的workflow Skill和评测助手中的“编排Skill”不同：前者按Manifest执行工具步骤，后者用于向模型提供提示约束、知识检索或转交角色等受支持能力。注册工具底座Skill不会自动授予Agent调用权，也不会自动进入编排Skill列表。

会话历史用于回看；checkpoint保存同一Run的执行进度；知识条目用于按问题检索；Skill的$ref用于本次调用传值。它们不会自动把所有历史拼接为长期模型上下文。

## 15 使用评测助手完成计划与审批

### 15.1 进入工作台

菜单为“评测任务 → 编排Agent”，页面标题是“评测助手”。左侧会话列表按颜色区分正在规划、待补充、待确认、执行跟踪、预算暂停、正在停止、已停止、异常结束和已完成。中央分为“对话与计划”“执行明细”“报告与经验”，配置集中在右上角“助手设置”；“计划证据”可打开详细计划。“新建评测”清空上一会话目标、补充输入、预算和可选能力，避免误带旧内容。

首次使用准备可访问的数据集、被测模型和规划模型。选择有 api_url 的规划模型后点击“生成计划”，系统建立规则草案，并自动启动 LangGraph 规划运行：读取当前用户授权的数据集、被测模型及工具清单，调用规划专项子Agent，再由主Agent核对真实资源ID并形成摘要。规划分析完成前不能审批或改配。资源清单有数量上限，缺少目标资源时可进一步检索。

### 15.2 写出可以核对的目标

消息区将回复统一显示为“助手”，旁边的小标识说明实际来源：“主 Agent”表示主入口的规划、答复或汇总；“子 Agent · 具体名称”表示该专项角色的直接回复，例如监控分析Agent、报告审校Agent或自定义顾问。主Agent汇总中引用其他角色时仍标为主Agent，不会把引用当作子Agent的新回复。用户消息显示“你”，平台状态通知显示“系统”。旧会话根据委派角色与当前角色目录补充显示，新消息保留执行时的角色名称。

建议目标包含场景、评测目的、对象、数据范围、输出要求、模式与预算。例如：“对客服问答做回归评测，使用客服小样本集和模型A，先试跑，检查每条回答与参考答案的匹配，保留错误样本，后续再决定正式执行。”

关键资源最终通过选择器确认，不只在自然语言中写一个名字。当前 infer_dims 依赖预定义关键词与编码，不能保证理解任意同义词、复杂约束或用户自定义行业词。对代码编码与中文领域混用的对象，应人工检查计划场景和数据选择。

### 15.3 生成计划

1. 点击“新建评测”，输入目标。
2. 在“评测准备：规划模型与预算”填写Token预算并选择规划模型；可选子Agent、Skill与MCP另行展开。
3. 点击“生成计划”，等待资源检索与规划分析完成；下方专项协作记录逐项出现，可展开检查模型输入、工具和结果。
4. 查看目标、模板、场景、数据、被测模型、试跑或正式模式及预算。
5. 打开“计划证据”，核对 dataset_version_id、model_version_id、judge_resource_id、resource_gaps、validation_errors、clarifications 和 canonical_hash。

系统会按资源信息做推荐，但推荐不是业务确认。通用场景下仍可能选择最新可用资源；某些未就绪条件还会促使计划切为 trial_run。不能因为输入写了“正式”就忽略计划摘要中的“试跑”。

### 15.4 补充信息

出现“需要补充”时，逐项处理数据集、被测模型、预算和目标等澄清。资源缺失应先到对应模块注册或发布，再回到选择器选择。修改后点击“补充并更新计划”，重新检查所有字段，不只看本次改动。

正式计划要求提供正数 Token 预算；试跑可按当前规则容许未设限额，但操作上仍建议控制小数据集及用量。关闭试跑模式后如果又变回试跑，应检查数据发布、质检和模型 endpoint 条件。

试跑模式用于调通数据、模型与裁判链路，放宽部分正式门禁；仍执行所选数据集版本，不自动抽样，仍可能真实调用并产生费用，不能作为正式准入结论。原“试用模式”与此开关是同一功能，页面已统一名称。工具底座的“试用”是单个工具调用，属于另一个入口。

发送后用户消息立即进入对话区，等待模型时显示三点动画；有新动态后更新。消息只需发送一次，历史会话的重复规划首条消息会合并显示，审计原记录保留。Markdown支持标题、列表、表格、代码块与引用。

### 15.5 审批计划

计划 ready 后主动作变为“审批计划”。有 agent:confirm 的人员先逐项核对评测对象、版本、裁判、预算、模式、数据使用授权及预期报告，再点击审批。当前前端签发的审批有效期为30分钟。

审批绑定计划 hash，关键配置变化会使旧审批失效。审批后又修改数据、模型、版本或预算，需要重新检查并签发审批。过期审批不能继续用于创建任务。

### 15.6 确认并执行

也可以直接在对话输入“确认执行”“确认当前计划并执行”“按当前计划执行”或“确认提交并执行”，无需再逐个点击下方按钮。系统将这条消息作为人工授权，核对当前计划版本、完整性和审批权限，再通过同一任务服务签发并消费审批、创建入队并启动跟踪。“好的”“知道了”等普通回复不会执行。计划未就绪或发送期间被修改时会阻止提交，需核对新计划后重新确认。仅在消息中提出改配而未明确确认，不会自动执行。

数据集、被测模型、裁判、试跑/正式模式和Token预算可以在聊天中补充；助手需调用工具实际写入，核对计划摘要后再发送确认。已有任务的会话不再修改执行配置，要做新评测请新建会话。

审批有效后点击“确认并执行”。系统消费审批、创建或返回关联任务并入队，同时启动或续接任务跟踪Run；后台按实际状态变化调用监控分析，失败时调用诊断，终态时调用报告审校。记录 task_id，点击“查看任务”核查进度。网络出错后先重开会话，看是否已有任务，避免重新建会话重复消耗。

审批是对本计划的一次授权，幂等机制用于避免同一次确认重复建任务，不是允许无限次复用审批执行不同任务。一个会话已有任务时通常会返回已有绑定；要做新的对照评测，应新建会话或任务。

### 15.7 什么时候算完成

有task_id后，进入任务详情检查实际状态、逐样本输出和报告。工具循环记录也会给出本轮完成情况：普通对话完成不表示已经执行评测；“评测任务已完成，目标核验通过”表示通过当前正式执行核验；“任务已结束，评测目标尚未核验通过”时仍需检查试跑、模拟、缺失结果或报告等原因。

若模型调用“请求审批执行评测”后进入等待，按第15.5至15.6节核对并确认计划。仅点击“继续会话”不能代替审批。确认执行后，已部署的后台执行器会在条件满足时继续核验；未自动继续时可以刷新或在允许状态下恢复原Run，先核对已有任务编号，不重新创建同一评测。

## 16 助手分析与工具调用详解

### 16.1 准备与启动

对话区默认高度至少720像素。点击消息区右上角“专注阅读”可隐藏会话侧栏，增大消息宽度，再点击“退出专注阅读”恢复。评测助手与模型榜单均支持暗黑主题；榜单图表及导出图片跟随当前主题。新建评测的能力选择按边框与间距分组，助手设置中提示词与模型配置区分开显示。

1. 打开右上角“助手设置”，在“助手行为与工具”中核对主Agent提示词、可用工具、模型决策上限和超时。有权限人员可修改这些配置。
2. 在“子Agent与编排Skill”维护需要的能力。创建或打开会话后，在该次编排的能力选择中明确启用子Agent、编排Skill和MCP连接。
3. MCP先在工具底座完成“验证连接”“获取工具目录”和一次测试调用，再回到会话选择已注册连接。临时探测地址不会自动成为Agent可用连接。
4. 新建评测时选择真实规划模型并生成计划；需要补充时直接发送一条消息。也可点击“继续分析当前计划”，沿用已保存的需求检查资源和未完成事项，不必再发送相同需求；此按钮不会自动执行评测。
5. 检查“工具循环记录”的轮次、用量、工具事件、回复和完成说明；涉及计划变更时重新打开“计划/证据”核对实际字段。

会话提交后由后台运行真实模型与工具，页面持续读取记录。最大模型决策轮次取“主Agent”的最大迭代设置，默认10轮；接口调用者可显式指定。新Run会带入有限的近期会话内容，不能依赖完整历史始终存在。恢复原Run则继续使用该Run保存的消息和工具结果。

助手设置中的“实时执行动态”控制前端SSE事件展示，模型完整回复在完成后显示；当前没有逐字Token流式输出。关闭后通过轮询更新，后台工作照常进行。

“关键操作始终需确认”说明人工介入的范围：任务创建与执行、配置变更导致的重新审批、异常恢复、补测和报告发布等需要人员核对。该门禁不能关闭；当前不支持在任意模型或工具执行中途接管。原有容易误导的“人工介入”开关已移除。

### 16.2 当前允许的工具

下列工具需同时符合主Agent配置和本会话启用范围。模型可能选择调用，也可能在信息足够时直接回答；看到工具名称不表示它已执行。

| 工具或页面名称 | 输入与作用 | 重要限制 |
| --- | --- | --- |
| get_resource_inventory 授权资源清单 | 当前用户可访问的真实数据集、模型与工具，含ID、状态、版本、样本量及能力结构 | 不含连接凭证；仍需检查正式门禁 |
| get_task_evidence 任务与样本证据 | 本会话任务的统计、逐样本输入输出、评分和近期事件 | 限定本会话，样本返回数量受限；无任务时明确说明 |
| search_knowledge 检索知识 | query关键词；查找当前租户已审核且未过期的知识 | 按字符串匹配；本次工具结果最多返回前5条，不保证每次命中 |
| infer_dims 识别场景 | text文本；按预置关键词推断场景和行业 | 不是通用语义分类器，需人工核对 |
| search_eval_resources 查找资源 | query关键词，可选kind类型；查询可访问的数据集、模型和裁判 | 资源存在仍需通过正式任务门禁 |
| propose_resources 更新资源建议 | 真实数据集、模型、裁判ID、场景、试跑开关及非负Token预算 | 更新后检查计划摘要；规划模型不能作为被测模型，关键变更使旧审批失效；已有任务后禁止再改执行配置 |
| delegate_agent 调用子Agent | 已启用role，可补充input任务说明 | 仅调用本会话启用的角色；自定义角色需真实规划模型 |
| invoke_skill 调用编排Skill | 已启用code，可补充input | 提示词型返回约束，不等于完成评测；不执行任意代码 |
| call_mcp 调用MCP | 已启用resource_id、目录tool_name、arguments参数对象 | 按最新工具Schema校验，并检查resource:invoke及对象访问权限 |
| get_task_status 查询实际任务状态 | 无需另传任务ID，查询本会话关联任务 | 不允许借此查询任意任务 |
| request_task_execution 请求审批执行评测 | 对当前已就绪计划请求用户确认 | 只进入审批等待；创建和执行由用户确认后经任务服务完成 |

调用MCP时，连接标识、工具名和参数要匹配。例如可以要求“使用本会话启用的统计连接，按目录参数计算这些样本的均值，并说明工具结果”。是否实际调用、传了什么参数，应在时间线与资源调用记录中确认，不只看回复文字。

### 16.3 观察时间线

| 事件或页面提示 | 意味着什么 | 后续操作 |
| --- | --- | --- |
| run.created、run.claimed | Run已创建或领取执行 | 等待决策与工具事件 |
| llm.select | 规划模型已决策 | 核对选中的工具、轮次和用量 |
| tool.selected | 模型提出工具调用 | 尚不能认定工具成功 |
| tool.observed | 工具结果已返回并保存 | 查看具体业务结果 |
| tool.rejected、tool.failed | 参数被拒绝或工具失败 | 先看错误；可纠正的MCP业务错误可能交回模型重试 |
| run.waiting_approval 等待用户审批 | 当前计划需要用户确认 | 审批并确认执行；恢复按钮不能授权 |
| run.waiting_task 等待任务结果 | 关联评测尚未进入终态 | 到任务详情查看排队、进度和错误 |
| llm.reply | 模型给出回复 | 继续检查任务与核验说明 |
| run.verified | 已按实际任务与样本检查执行情况 | 阅读通过范围或未通过原因 |
| run.success | 本轮运行结束 | 区分对话完成和正式评测执行核验通过 |
| run.failed、run.paused_budget | 失败或预算暂停 | 按错误处理，不重复提交相同需求 |

“每轮执行明细”提供上一轮、下一轮及轮次下拉选择，区分需求规划、普通对话和执行跟踪。切到历史轮次不会取消后台跟踪；点击“跟随最新”回到当前运行。每轮独立保存主Agent事件与子Agent委派。展开“专项协作记录”可查看模型输入、公开响应、工具参数、真实返回及失败信息；这些是可审计执行记录，不是模型私有思维链。

时间线按事件序号排序和去重。一次MCP失败后出现纠正参数并成功调用的记录，不能抹去前次失败；最终结论应依据成功返回的数据。权限或参数结构错误仍可能直接结束运行。

### 16.4 轮次 用量和预算

主Agent回复的小标识和执行明细中的委派记录相互对应。子Agent的直接回复显示具体名称，委派记录提供其输入、工具与输出；主Agent的最终汇总可能引用多个角色，但仍由主Agent负责表述。标识只说明消息来源，不代表分析结论已被人工验收。

页面创建助手运行会传入当前计划Token预算。运行创建后，检查工具循环记录里的实际限额，不将后续计划修改自动视为已改变旧Run。主Agent最大迭代控制默认轮次；自定义子Agent还受自己的最大迭代和超时限制。

Run用量来自模型返回，子Agent模型用量也计入父Run。显示“用量未回报”时，0或已知部分用量不代表没有其他消耗。Run限额与评测任务的token_quota是两个执行对象的限制，不是跨两者自动合并扣减的统一钱包；企业服务额度和供应商账单还需分别核对。

预算检查发生在模型调用之后，最后一次调用可能使累计用量超过限额；服务不返回usage时无法精确计费。0表示未设Run限额，不能当作零成本。

页面“模型决策 3 / 10 轮”表示本次Run主Agent已调用规划模型3次、最多10次，不是聊天轮数或评测样本数。0表示主Agent尚未进行首次决策；此前可能正在完成专项子Agent，子Agent用量与记录单独列出。上方“每轮执行明细”的轮次选择器用于切换不同Run，二者含义不同。

### 16.5 取消 恢复和预算暂停

同一会话只能有一个queued、running或waiting的活跃Run。遇到409先检查现有运行，不重复启动。点击“停止助手”并确认后，助手在执行节点之间停止分析与跟踪；正在进行的模型或外部请求可能仍需等待返回并产生费用。此操作不取消已提交的评测任务，取消任务需进入任务详情。

手动停止或异常结束后可点击“继续会话”，保留会话上下文和关联任务：可恢复的等待Run重新入队；已终止Run新建一轮分析或任务跟踪，原记录保留。不会仅因继续会话再建一次评测任务。恢复前需处理连接、凭证、权限或工具错误；若需要重新执行失败任务，仍须单独审核恢复或补测建议。

等待审批和等待任务结果时，先完成对应业务条件，再恢复。服务正常退出会释放自身未完成节点的租约；进程异常退出后的活跃运行需等待执行租约过期再由后台回收，可能不是立即继续；持续无进展时联系管理员检查Agent执行器。

预算暂停不能在原Run直接提高限额继续。页面“继续会话”会在预算暂停时要求新预算大于原限额及已用Token，更新计划后创建新Run，下方运行记录将更换；先核对是否已有评测任务，避免把预算调整理解为重新执行该任务。轮次耗尽或反复失败时，应缩小目标并排查根因。

### 16.6 核验结果与使用边界

| 完成说明 | 如何理解 |
| --- | --- |
| 本轮对话已完成，尚未核验评测目标 | 模型已回复，但没有关联的评测任务；不能交付评测成绩 |
| 正在等待评测任务的实际执行结果 | 关联任务仍在排队或执行，继续看任务详情 |
| 任务已结束，评测目标尚未核验通过 | 可能是试跑、模拟、无完整实测样本或缺少报告记录；必须逐项检查 |
| 评测任务已完成，目标核验通过 | 任务success、样本数大于零、非试跑和非模拟，每条样本有实际执行与已评分记录，且任务记录中已有报告路径 |

核验范围是“评测执行完整性”，不自动证明任意自然语言目标、业务质量阈值、生产性能或专家验收达标。仍需按第9章复核逐样本结果和报告；任务记录里有报告路径，也应实际打开交付文件检查。

## 17 子 Agent 监控 诊断与建议

### 17.1 选择和配置角色

打开右上角“助手设置”中的“子Agent与编排Skill”，查看角色用途、工具、Skill和启用状态。有编辑权限时可“添加”或“编辑”自定义子Agent，填写标识、名称、系统提示词、模型名与生成参数、可用工具、Skill、最大迭代和超时。然后在本会话的能力选择中启用该角色。自定义角色可在“评测标尺”JSON中配置stages（planning、monitoring、diagnosis、review、optimization）和trigger_keywords；新会话需求命中已启用定义的关键词时，系统会按场景自动绑定并在相应阶段调用。没有关键词配置时需要显式选择。

| 角色 | 执行方式与用途 | 使用时核对 |
| --- | --- | --- |
| monitor 监控分析 | 根据关联任务状态、进度、事件生成摘要 | 没有任务时只提示等待，不代表已在监控实际执行 |
| diagnose 异常诊断 | 根据失败或中断事实给出处置建议 | 不直接恢复或补测，建议需人工核对 |
| plan_analyst、param_advisor | 规划阶段对授权资源、方案、预算和参数做真实模型分析 | 默认随模型规划启用；不会自行创建任务 |
| report_reviewer | 任务终态后核对统计、样本与报告口径 | 默认绑定；有规划模型时运行真实子图 |
| report_optimizer | 选择后在报告就绪时生成独立Markdown优化稿 | 可选；需人工发布或撤回，不修改原报告及分数 |
| 自定义角色 | 真实模型决策、受控工具调用、返回最终分析 | 核对委派记录、工具调用与证据，提示词不再直接充当分析结果 |

自定义子Agent使用当前会话规划模型的连接，可按定义覆盖模型名、温度及输出长度，不是为其自动部署一套新的模型服务。没有可用规划模型时会明确失败。

让主Agent调用已启用角色，例如“请让覆盖检查Agent核对本次方案缺口，并把依据交回主Agent”。当前按需顺序执行，不提供任意递归委派或多机并行自治。子Agent工具取自身白名单、主Agent允许范围和会话绑定能力的交集，不能修改计划、创建或恢复任务、继续委派其他Agent。需要MCP时还要在会话启用连接并有调用权限。

会话有关联任务后，助手按阶段自动调用监控和诊断角色；也可发送消息要求专项分析。在“执行明细”核对委派，在“报告与经验”查看待处理建议。监控分析和异常诊断是必需角色，页面不允许删除。

### 17.2 监控怎么使用

对话中“子 Agent · 监控分析 Agent”表示监控角色直接返回的分析；“系统”的任务状态更新来自平台实际快照；“主 Agent”表示主入口对各角色与任务事实的汇总。查看异常时先区分这三类来源，再核对时间、任务编号与执行明细，避免把旧进度摘要当作最新状态。

确认执行后，助手在任务状态变化、进度跨越10%区间、新失败或报告就绪时主动跟进；长时间没有变化时，每5分钟保存一次仍在执行的跟进记录。可发送“请检查当前任务状态”进一步分析，并在执行明细中查看进度、证据与子Agent结果。没有新事实时不会反复调用相同专项模型。

确认执行后的会话跟踪由后台Agent worker处理，关闭页面不会停止该会话的跟踪；部署时需启用Agent执行器。这不等于自动永久监视所有平台任务。后端通过持久化任务事件游标和状态轮询发现变化，并非消息队列推送。前端启用“实时执行动态”后通过SSE接收已提交事件，断线后按序号补取，失败时回退轮询。页面关闭不影响后台跟踪；后台服务停机期间不能产生新消息，恢复后继续处理。

### 17.3 诊断怎么使用

1. 打开失败任务对应的会话，查看自动诊断，或发送“请诊断当前任务失败原因”。
2. 阅读错误、失败数量和建议理由，核对是否来自真实任务事件。
3. 检查数据质量、模型健康、资源可用性和预算，先处理根因。
4. 在“报告与经验”的建议区查看待处理建议。
5. 对 retry 等可能重新消耗资源的建议，确认影响后由有 agent:confirm 的人员点击“采纳”。

子 Agent 的工具集合以只读分析为主，不允许直接使用创建、取消或重试任务的写工具。采纳建议是平台业务动作，可能触发重新入队；不是仅把一个文字标为已读。

### 17.4 反复失败时怎么做

同一恢复措施再次失败时，记录会话、任务、Run、委派和 trace 编号，在运行支撑建故障工单，请模型或工具负责人介入。不要反复采纳相同建议，也不要修改数据库的任务状态、分数、lease 或 fencing。恢复判断需要实际证据，摘要中的 ready_to_archive 不是专家签署的正式验收。

### 17.5 优化报告与版本回退

在生成计划前选择“报告优化Agent”。任务结束且原始报告可用后，系统根据任务统计及逐样本证据生成优化草稿，在“报告优化版本”查看或下载。草稿与原始评测报告分开保存，报告分析不得改变评分事实。

有agent:confirm权限的人员核对论断、样本引用、限制与建议后点击“确认发布”。发布时系统再次核对原报告和证据快照，已发生变化时拒绝发布。点击“撤回优化稿”后保留修订历史，并恢复使用原报告。优化稿发布不代表专家验收或业务达标。

### 17.6 开发环境自定义角色测试场景

以下角色和资源来自2026-10-24真实开发演示，实际编号和运行状态见[演示记录](../delivery/agent-development-evidence-2026-10-24.json)。输入样本由AI生成，参考答案可人工核验；结果来自实际模型和裁判调用。

| 自定义角色 | 触发场景和阶段 | 建议测试输入 |
| --- | --- | --- |
| customer_coverage 客服场景覆盖顾问 | 包含“客服”或“售后”；规划 | 评测客服售后质量，核对意图覆盖和规则边界 |
| finance_verifier 金融数值核验顾问 | 包含“金融”或“利息”；规划 | 评测金融利息计算，检查单位、精度和裁判口径 |

### 17.7 通过 Agent 编排多模态任务

要求Agent读取授权资源清单，核对数据输入模态、模型输入输出能力及工具声明。计划的media_summary记录模态、处理方式和数据版本内容校验和；能力或版本不匹配时先调整资源，再重新审批。执行仍走统一任务队列、预算、取消和审计。

Agent通过get_task_evidence读取样本处理方式、实际帧时间和校验和，引用任务号与题号；文本资源摘要不等同于规划模型直接看过视频或听过音频。语义结论以真实多模态裁判和人工复核证据为准。

## 18 Agent 记忆与知识复用

### 18.1 五种信息不能混为一谈

| 信息层 | 保存什么 | 主要用途 | 是否自动进入下一次模型调用 |
| --- | --- | --- | --- |
| 会话消息 | 用户需求、计划提示、分析消息 | 回看本次业务过程 | 新Run带入有限近期消息，不保证完整历史 |
| 计划与审批 | 目标、资源版本、预算、hash和确认记录 | 冻结授权范围 | 不等于模型自然语言长期记忆 |
| Run checkpoint | 本Run消息、观察、待执行工具和阶段 | 断点恢复与继续循环 | 同一Run的后续轮次会使用其检查点内容 |
| 知识候选和条目 | 人工整理的案例、规则、经验 | 审核后检索复用 | 仅在调用检索且满足条件时可用 |
| 监控与委派证据 | 状态摘要hash、引用、角色结果 | 去重、诊断和审计 | 不代表自动进入任意Agent上下文 |

### 18.2 新会话与恢复的区别

新建会话用于新目标；同会话新建Run用于新一轮分析或跟踪；可恢复的等待Run沿用原checkpoint。已终止Run通过“继续会话”新建一轮，保留关联任务而不重新执行。新Run通常带入近期最多16条非空消息，每条最多2000字符，再附本次输入；首次自动规划会保留完整原始需求并避免重复加入。更早或更长的历史可能省略，消息旁的角色标识不会使模型自动获得该角色的全部历史。

需要模型利用旧结论时，将经确认的必要信息明确写入本次目标，或者通过能够访问相应知识的接口检索后核对。不要把密钥、未经授权的数据或整份原始日志无选择地复制进目标文本。

### 18.3 什么内容适合入知识库

适合入库的内容应具备适用条件、证据、操作步骤和有效期限，例如“模型A在特定请求模板下返回空字段的原因及修复方式”。不适合直接入库的内容包括尚未证实的 Agent 猜测、API Key、一次性的临时地址、未经复核的模型结论以及只有‘已完成’三个字的记录。

建议知识正文包含：问题或经验摘要、适用的模型/工具/数据版本、现象、已验证原因、处置步骤、验证结果、任务与 trace 引用，以及不适用场景。这里描述的是推荐编写格式，不是当前页面提供了一套自动填充表单。

### 18.4 提交候选

在评测助手“报告与经验→知识候选”填写标题、分类和内容，核对来源后点击“新增候选”；列表中的“通过”操作供有审核权限人员使用。集成人员也可通过“系统管理→接口文档”或受控客户端调用POST /api/agents/knowledge，并按需提供标签。

示例请求如下，任务编号和版本应替换为真实证据；示例不会自动创建记录。

```json
{
  "category": "case",
  "title": "模型A响应映射核对方法",
  "content": "适用版本：填写真实版本。现象：填写真实错误。原因与处置：填写经核实步骤。验证证据：task编号和trace编号。限制：填写不适用情况。",
  "tags": ["响应映射", "模型接入"]
}
```

提交后返回候选记录，pending 不能视为可信知识。系统会针对同租户同内容 hash 的待审候选去重；修改内容可能形成不同候选，不能将去重当作全历史版本管理。

### 18.5 审核和有效期

在“报告与经验 → 知识候选”点击“刷新”，查找 pending 项，由有 agent:confirm 的人员审阅。当前列表只简要展示标题、状态和通过按钮，不能仅凭标题批准；必要时使用候选接口查看完整 claim、来源和内容。

审核接口 POST /api/agents/knowledge/candidates/{cid}/review 支持 approve、reason、ttl_days。拒绝或补充详细理由需要使用接口；页面没有完整拒绝与编辑入口。默认有效期365天，不应据此认定任何知识都适用一年，可按业务缩短。

审核通过后产生 KnowledgeEntry 并记录 entry_id；拒绝后不进入正常可信检索。过期条目通常不在默认结果中，若知识不再适用，应通过管理员治理流程处理，而不是假设 Agent 会自行发现其失效。

### 18.6 为什么批准了仍然搜不到

当前知识检索主要采用数据库标题、正文和标签的字符串包含匹配，不是语义向量检索。长句查询、同义词或措辞不同都可能没有命中，应使用条目中的短关键词查询。

Runtime的search_knowledge现在带创建者租户上下文，可检索同租户已审核、未过期且匹配查询词的条目，包括候选审核后入库的条目；不会自动访问其他租户知识。模型必须实际选择检索工具才会得到结果。规则生成计划和部分内置编排Skill仍使用各自的检索路径，不能把Runtime的召回行为推广到全部入口。

此外，部分历史入库路径仍直接写 approved 条目，确认任务时的 archive_experience 路径也不等同于候选审核流程。当前不能宣称所有经验均自动经过审核或所有Agent入口均有同样的长期记忆范围。这类记忆闭环限制应由管理员与研发跟踪；操作上用接口验证命中，必要时人工引用有效经验。

### 18.7 记忆会不会自己改写分数

不会因为一条知识建议就合法改变已经产生的评分事实。知识可帮助选择配置和解释问题，正式成绩仍来自执行器、模型调用和裁判。发现评分规则有问题时，应修正规则并建立可追溯的复测，不覆盖旧成绩来让报告符合预期。

## 19 组合使用案例与责任分界

### 19.1 通过 Agent 发起客服回归

准备一个已验证的小数据集、模型A及适用裁判。在评测助手描述客服回归目标，选择规划模型生成计划；通过澄清明确数据和被测模型，核对模板、版本、试跑和预算。审批后确认执行，在任务详情检查真实模型输出和评分。

可在聊天补充资源、模式与预算，等助手实际写入后核对计划，明确输入“确认执行”提交，也可使用下方审批与执行按钮。执行期间观察系统进度通知、监控子Agent回复和主Agent汇总。失败时先核对诊断证据并修复根因，再单独确认恢复或补测，不用重复发送最初需求。完成后将经复核的经验整理为候选并审核。

### 19.2 在工具底座验证复合评分 Skill

打开 builtin/skill_dual_judge，用相同 prediction/reference 做一次试用，再用相近但不同文本试用。检查 steps 中 exact 与 fuzzy 的返回、顶层均分和 passed，确认差异符合评分定义。

若需把该Skill用作评测裁判，先核对输入输出契约及实际调用，再从任务的打分工具候选中选择已注册且可用的工具、Skill或MCP裁判。助手也可通过对话检索真实ID并写入计划；不能仅因目标写了“用双裁判”就认定配置已改变，需打开“计划证据”核对judge_resource_id、版本与权限。

### 19.3 将外部 MCP 统计能力用于评测分析

资源管理员先注册MCP连接，完成握手、工具目录和小输入测试。操作人员在会话中启用该连接，也可添加一个只允许call_mcp的统计分析子Agent并启用。请主Agent委派该角色，按目录Schema提交数值与单位，核对返回均值、样本范围和异常，再由主Agent汇总。示例：“用已启用统计连接计算2m、4m、6m的均值，必须实际调用工具并说明依据。”工具名和单位格式以实际目录和服务约定为准。

在工具循环记录中核对delegate_agent和call_mcp的参数与结果，再检查资源调用历史的成功或失败。参数语义错误可能反馈给模型纠正；没有成功工具结果时不能接受它心算或猜测的结论。已验证经验仍需人工整理为知识候选并审核，不会因工具成功而自动成为长期知识。

### 19.4 不点击下方按钮完成聊天提交

当前开发环境的会话20提供已落库示例：先在聊天中要求使用数据集44、被测模型9、builtin/exact_match，开启试跑并设置预算200000；真实规划模型调用propose_resources写入后，再发送“确认执行”。系统创建任务41、消费审批并启动跟踪运行34。任务完成12条真实调用与评分，监控角色和报告审校角色留下直接回复及委派记录，无需再点补充、审批按钮。实际环境请替换为自己的授权资源，不能机械沿用这些编号。

该示例为试跑，objective_verified=false，不作为正式准入通过。用户可以回看聊天确认消息绑定的计划hash，并在执行明细切换规划和跟踪轮，展开对应子Agent的工具与结果。详情见[聊天确认验证记录](../delivery/agent-theme-chat-verification-2026-10-24.json)。

### 19.5 组合时的责任分界

操作人员负责选择目标与核对结果；审批人负责授权具体计划；Agent负责受限范围的编排与分析；Skill执行明确的步骤；Tool/MCP承接实际能力；任务服务负责状态与结果；知识库保存经治理的经验。失败时按这一顺序定位责任层，避免把所有错误统称为“Agent出问题”。

## 20 任务模板与基准套件

### 20.1 使用任务模板

进入“评测任务 → 任务模板”，按基础能力、场景应用、行业专项或安全可信筛选。查看模板名称、场景、行业、默认裁判及标尺，点击“使用”进入任务创建流程。

模板的意义是提供配置起点，不等于已准备好全部数据、模型或执行依赖。进入表单后重新核对被测模型、数据版本、提示词、裁判及预算。场景列表包含某行业，仅表示存在分类或模板，不代表该行业所有标准题库已验收。

“安全可信”分类用于查找相关模板，不代表点击“使用”后的普通创建弹窗已具备安全指标权重、追问、情境对照和裁判融合配置。需要本手册第21章的安全专项结论时，请改从“安全可信 → 发起安全评测”或编排Agent创建；仅选择安全相关模板或打分工具不足以完成专项配置。

### 20.2 判断套件是否可用

进入“基准套件”，按分类与 readiness 筛选。每项查看编码、输入模态、指标、金标包、就绪状态与阻塞原因，点击“详情”核查具体要求，有“样本”入口时查看金标样本。

| readiness | 操作含义 |
| --- | --- |
| draft | 套件仍在准备，不作为已就绪的正式基准 |
| blocked | 有明确缺失，例如输入、oracle或隔离条件；先关闭阻塞 |
| ready | 当前声明与规则门禁满足，仍需真实运行验证 |

有 task:edit 的人员可点击“标 ready”，但应先核对实际证据。readiness 是就绪声明和门禁判断，不替代生产验收、数据授权或完整模型测试。媒体输入若只是字符串引用而无真实读取与适配，不构成多模态推理验证。

### 20.3 模拟器与被测智能体工具

基准页可选择模拟器和套件进行“试跑”。模拟器用于验证场景规则和接口行为，结果只在其模拟范围内有效，不能当作真实机器人、生产环境或外部智能体已经测试通过。

被测智能体使用的工具属于评测环境的一部分，需与平台管理工具隔离。不能把平台创建任务、读知识或访问凭证的权限交给被测智能体来提高完成率。代码用例如果没有真实执行，应保留 not_run 或相应限制说明，不用字符串比对冒充代码通过率。

## 21 安全可信评测

### 21.1 评测对象和功能分工

安全评测检查被测模型的生成内容与行为，覆盖内容风险、生成内容标识、价值对齐和幻觉。平台自身的权限、审计和运维检查不等于模型已通过安全评测。

入口“评测任务 → 安全可信”包含“发起安全评测”“基准与证据”“安全结论与专家复核”。安全菜单负责专项基准、指标和人工判断；执行、调度、监控、报告仍使用任务管理中的同一条安全任务。任务类型为security，原始输出和自动评分保留。

安全任务的完整创建入口为本页面的“发起安全评测”或编排Agent（见第21.10节）。普通“任务管理 → 创建任务”弹窗当前不提供完整的安全协议配置，不能仅通过选择安全相关模板或打分工具替代。创建完成后，在任务管理中查看并执行这条任务，无需再创建第二条普通任务。

本章按2026年10月25日页面与接口更新。功能入口可用、隔离回归通过、真实模型执行完成和专业验收通过是不同结论，不能相互替代。

### 21.2 专家复核和人工金标的区别

| 对比 | 专家复核 | 设置人工金标 |
| --- | --- | --- |
| 要解决的问题 | 这条自动评测结论是否可信，证据是否充分 | 自动裁判的判断与人工独立判断是否一致 |
| 填写内容 | 通过、驳回或需补证，以及判断理由 | 人工参考分，范围0至100%，以及整组选样的金标来源与依据 |
| 适用时机 | 自动裁判有分歧、争议、缺证据或高风险需要确认 | 检查裁判偏差、规则或裁判版本更新后校准评分方法 |
| 直接作用 | 更新该结果的复核记录，驳回、待复核或需补证会阻止任务入榜 | 与自动分数对照，计算合格判断一致率和平均绝对分差 |
| 是否修改模型原始成绩 | 不修改 | 不修改 |

例如，自动裁判认为某回答泄露隐私，给0分。专家检查后选择“通过”，表示认可“存在风险、0分”的自动结论，并不是把模型改成通过。如果专家认为裁判误判，选择“驳回”并说明理由，随后应修正基准或裁判配置，另行重新评测，不能直接篡改原始评分。

再如，自动裁判给80分，人工独立判断应为20分。将20%设置为金标后，系统会记录二者的分差和合格判断分歧，用于检查裁判可靠性。设置金标本身不等于复核通过，也不会把原80分改成20分。

### 21.3 从空白新增基准和题目

1. 打开“基准与证据”，点击“新增基准”，填写数据集名称。
2. 点击“新增题目”，选择具体指标和主观题或客观题类型，填写实际发送给被测模型的问题、参考答案及评分依据。
3. 配置规则评分：可选择正常回答或拒绝不当请求；填写答案锚点，一行一项，命中任一项；填写禁止断言，一行一项。未填写锚点时，可使用参考答案作为锚点。参考答案不能代替模型真实输出。
4. 幻觉题必须添加证据编号、证据正文，可补充文档名、网址或业务规则版本。证据应与本题对象、属性、关系、时序、上下文或世界知识检查一致。
5. 价值对齐题必须填写立场准则。跨文化和多元价值题请至少配置两组不同的文化背景或利益观点情境。系统逐情境独立调用模型，不向后一个情境泄露前一个情境的答案。
6. 标识题可填写期望输出的标识JSON字段。字段值和类型均参与检查；数值1不能冒充布尔值true。此功能检查模型实际输出，不用输入中的标识元数据替代输出。
7. 配置引导追问和进阶追问，每个分支最多两条、一行一条。低分进入引导分支，高分进入进阶分支。追问仍应适用本题的证据、评分锚点与核心准则。
8. 点击“确认题目”，题目进入本地基准草稿。可继续新增，或在列表中编辑、移除；这些动作尚未保存到数据库。
9. 点击“保存为新基准”。系统先校验问题、证据、指标、样本编号和评分元数据，再创建数据集及版本。该校验只说明结构有效，不表示模型或基准已通过专业验收。
10. 到“数据集质检与发布”完成质检和发布，之后才能创建正式安全评测。没有题目的空基准不能保存。

### 21.4 使用模板和动态修订基准

模板提供综合评测（17题）、生成内容风险（5题）、合成内容标识（2题）、价值对齐（4题）、证据与事实一致性（6题）、多轮追问与对抗（17题）六种起点。按类别筛选，点击“使用模板”加载题目；展开题目查看准则、证据和标识要求。模板不等于覆盖全部业务风险，需按实际场景补充足量题目和独立人工参考标准。

模板题目同样可用表单新增、编辑或移除。需要批量调整时可进入“高级JSON编辑”；修改答案后必须同时核对规则锚点，修改证据后必须核对裁判依据。每题safety对象保存指标、评分依据、证据、立场、标识元数据、追问及情境配置。

已有基准可在顶部选择后点击“加载并修订”。修改后选择“保存基准新版本”，保留原有数据版本，并让新版本重新进入质检和发布流程。也可以修改名称后“保存为新基准”形成独立题库。历史任务继续引用原数据版本，不能把新题目或新准则回填成历史评分事实。

这套新增、修订、版本、质检和发布流程构成当前的动态基准管理；系统没有自动维护全行业知识或自动认定新增题目有效的能力。

### 21.5 指标含义与适用范围

| 类别 | 指标 | 阅读重点 |
| --- | --- | --- |
| 内容风险 | 违法违规、歧视偏见、隐私泄露、暴力伤害、虚假信息 | 检查不当请求与有害生成；纯规则只能验证配置的特征，语义风险应结合裁判模型和专家复核 |
| 标识合规 | 文本显式标识、输出标识元数据 | 验证实际文本标识、JSON字段和值类型；不代表隐式水印、元数据真实性或完整法规合规认证 |
| 价值对齐 | 立场稳定性、跨文化对齐度、价值观多元性、过度安全 | 立场题可施压追问；跨文化和多元价值使用多情境独立输出；无害题应正常回答，避免过度拒答 |
| 幻觉 | 对象、属性、关系、时序、上下文、世界知识 | 对照本题可追溯证据判断，不能用命中某个对象词代替全面事实核验 |

跨文化对齐不是强求不同文化给出完全相同表述，而是核对共同原则是否稳定、是否尊重具体文化差异。价值观多元性不是选定唯一立场，而是核对模型是否承认、解释并权衡多种合理诉求。具体评判标准需由题目立场准则和裁判依据明确给出。

### 21.6 配置和执行安全任务

1. 在“发起安全评测”选择已发布基准和被测模型。正式执行要求基准质检发布；试跑和探索诊断不进入正式比较榜。
2. 可选裁判模型。规则评分占比按百分比填写，模型裁判使用剩余比例；不选裁判模型时使用纯规则。裁判版本随任务冻结，同源自评须审慎解释。
3. 指标权重合计须为100%。只显示所选基准包含的指标。通用方案平均分配；知识问答侧重幻觉；公共服务侧重风险与对齐。可逐项调整，或按比例调整至100%。零权重不参与综合分，缺测保持为空。
4. 难度自适应开启后，前轮得分达到0.5进入进阶分支，低于0.5进入引导分支。最多设置1至3轮；题目没有对应追问时会提前停止。只有实际发生的追问和输出才计入多轮测量。
5. 页面新建任务默认使用“安全边界 · 采用最低分”：主问题、后续追问及独立情境中的最低分作为样本结论，避免一轮失守被其他高分平均掩盖。选择“综合表现 · 采用平均分”时，使用全部这些测量的平均分。旧任务继续保留原协议和成绩，不会被自动重算。
6. 默认勾选“执行题目中的文化与观点情境”。仅勾选开关但题目没有情境，不算已完成情境测量；跨文化或多元价值应配置至少两组情境。
7. 点击“创建安全任务”后，系统已创建一条带安全专项配置的任务。到任务管理打开这条任务，按岗位流程提交、审核或执行；不要再使用普通“创建任务”弹窗重复建档。任务详情“安全专项结论”返回同一任务的安全页面。

单次测量分数为规则与模型裁判分数按设定占比融合，样本分数达到0.5为该协议下合格。规则与模型意见明显冲突，或裁判认为证据不足时，仍需专家复核，不能仅凭融合分数放行。任务综合分按维度权重融合；所需维度缺测时不生成完整综合分。

### 21.7 核对实际测量和可解释证据

选择任务后查看加权综合分、总合格率、拒答率和指标热力图。展开样本查看原问题、输出、评分依据、立场、参考证据、融合方法、安全边界、每轮难度与得分，以及文化或观点情境的独立输出和裁判理由。完整原始评分记录另可展开核对。

“需求覆盖与测量边界”按这条任务的实际结果显示：四类覆盖、跨文化对照、多元价值对照、幻觉六类、多轮追问、规则与模型裁判融合和标识范围。未选择、未执行或旧记录没有证据的项目，显示部分或未完整测量，不能把配置存在当成已实测。拒答率中的规则特征也不是独立的安全认证。

自动模型调用失败、裁判JSON无效、证据缺失或预算不足不得计为评测通过。报告JSON保留配置、轮次和情境证据；Markdown列出安全证据。历史结果的原始输入、输出、配置及分数保留，后续增加功能不会自动改变历史结论。

### 21.8 执行专家复核与裁判校准

“驳回”表示专家不认可自动结论，通常应检查题目、证据、规则或裁判配置后重新评测；“需补证”表示暂时无法判断，应补充依据后再次复核。两者均保留原始输出和分数，不会把模型成绩改为零，也不会把执行成功的任务改为失败，但会阻止该任务进入可比榜单。同一结果证据以最新复核意见为准；认可一条“不安全”的自动结论，仍代表模型在该题不合格。

专家复核需要safety:review权限，且任务已结束。选择“通过 · 认可自动结论”“驳回 · 不认可自动结论”或“需补证”，所有选项均须填写理由。记录保存复核人、时间和结果证据hash。驳回、待复核或需补证阻止任务入榜；结果重试或证据变化后旧意见不能自动套用。

裁判一致性校准需要safety:edit权限。点击“设置金标”，在弹窗中独立填写0至100%的人工参考分。确认后样本显示“已设置”和“修改金标”，下方列出校准清单。此时只是前端草稿，至少选择两题、填写金标来源与依据并“保存校准记录”后，才持久保存。不要把自动评分直接复制成金标。

刷新同一任务结论保留证据未变化的草稿；切换任务或结果证据变化时清除对应草稿。校准返回合格判断一致率及平均绝对分差。仅看一致率可能掩盖分数偏移，两项应一起判断。例如自动分数90%、人工51%虽然同属合格，但分差仍很大。达到90%一致率只说明这组选定样本的判断一致，不代表整个基准或全部未来场景已校准。

### 21.9 需求覆盖核对与当前缺口

| 需求 | 当前实现 | 尚需补充或验收的部分 |
| --- | --- | --- |
| 动态评测基准 | 新增基准、表单新增编辑题目、证据和情境、模板、版本修订、质检发布 | 领域专家维护足量代表性样本、独立金标及失效证据更新机制 |
| 规则、裁判、对抗与人工复核 | 规则与可选裁判融合、施压与错误暗示追问、独立情境调用、持久复核和校准 | 纯规则不能替代语义检测；裁判偏差与同源自评需独立校准 |
| 内容风险性评测 | 支持文本及原始媒体输入、自定义准则、多轮边界和人工确认 | 完整行业风险类别与攻击强度仍需业务题库及专业验证 |
| 生成合成内容标识合规 | 已支持文本显式标识及实际输出JSON字段和值类型检查 | 图像、音频、视频隐式水印检测、压缩/擦除鲁棒性、标识真实性和完整合规性未实现 |
| 价值对齐四维、场景权重与热力图 | 四维指标、文化与观点情境独立输出、百分比权重和热力图已具备 | 不能据少量情境认定覆盖所有文化或全部价值体系，仍需专业金标验收 |
| 幻觉六类、自适应、多轮与融合 | 六类有证据题、按结果选择难度分支、实际多轮追问、最低分或均值融合和维度加权已具备 | 难度分支未完成统计学标定；开放世界检索、实时事实和外部证据时效核验尚未实现 |
| 可解释、可追溯风险结论 | 输入输出、证据、规则检查、裁判理由、轮次、情境、配置、复核人、hash和报告可追溯 | 这些记录证明本次测量过程，不等于生产压力测试或全行业安全认证 |

因此，当前已覆盖文本安全以及媒体输入的主要执行与复核链路，但不能声明需求的所有范围均已完整实现或验收。特别是广义生成内容标识合规和专业基准有效性，仍有明确缺口。模型榜单只比较同一数据版本、裁判、权重和执行协议的完整实测结果；探索、试跑、模拟、评分失败、不完整测量和未完成复核的任务排除。

### 21.10 通过编排 Agent 发起安全评测

在编排对话中说明安全可信评测目标，要求选择安全基准和被测模型，并设置指标权重、场景、固定或探索集、追问轮次、难度自适应、最差或均值融合、文化观点情境，以及可选裁判模型。Agent通过授权资源清单读取基准实际指标；缺少安全配置时，不能用普通匹配裁判代替安全专项执行。

确认前，在计划摘要核对安全配置及展开的冻结配置。安全配置参与审批哈希，改变后需重新确认；创建任务时再次检查安全创建权限、基准版本、覆盖指标和裁判调用权限及版本。任务仍由现有任务管理调度执行。

执行后Agent可读取实际安全综合结论、维度覆盖、追问和情境证据、待复核及驳回数量和榜单资格；样本证据按工具返回上限展示，汇总基于全任务。Agent不能代专家复核或填写人工金标。标识检测仍限定文本与输出元数据。

### 21.11 音视频安全证据与分模态校准

在结果、专家复核及金标窗口播放原始媒体并定位片段；按模态查看有效题数、得分、覆盖及金标一致率和绝对分差，缺测保持空值。裁判必须接收原始媒体；音频输出需音频裁判能力。图片及无音轨视频抽帧已真实验证，音频按用户要求本轮未做真实模型验收，原生音画联合输入也待对应端点实测。详细步骤与边界见《多模态评测操作指南》。

## 22 模型榜单

### 22.1 查询与比较

进入“应用服务 → 模型榜单”。分类依次为全部模型、语言能力、视觉语言、视频模型、语音模型、K12 学科、金融专项、安全可信。页面仅显示真实任务结果，选择评测套件及榜单类型；视频和语音没有符合条件的结果时显示无正式结果。

| 榜单 | 阅读方式 |
| --- | --- |
| 综合得分榜 | 按各能力维度的配置权重汇总 |
| 单项能力榜 | 选择一个指标，查看该项前十名；不足十个配置时如实显示 |
| 专项评测榜 | 查看行业、场景、安全等专项任务结果 |
| 性价比榜 | 查看综合原始分与每样本估算费用的比值，费用缺失或为零时不授予性价比排名 |

可按模型、模型版本、行业、场景、评测起止时间筛选，并搜索模型名称、机构或筛选开闭源。开闭源信息在“被测模型 → 注册/编辑 → 基础 → 开闭源”维护；未填写时显示“未标注”，不会根据接入方式自动推断。

表格、模型卡片和能力档案可切换。勾选最多五个配置，在下方查看雷达、得分对照、能力矩阵、历史趋势、质量与效率图；图例可点击隐藏，支持放大、保存图片和导出当前视图结果。点击模型名称打开评测卡片，再进入来源任务核对模型输出与评分。

“全部模型”表示不限制分类，仍在选中的评测套件内比较，不会跨数据集或评分工具计算统一总分。切换分类会重新选择套件；未指定套件时，系统优先选模型配置数量较多、时间较新的套件。若恰好选中简单题集，多个配置可能全部获得100分，应查看题目难度、样本数及来源模型，不能据此认定通用能力满分。

### 22.2 评测套件如何关联数据集与工具

当前套件由已完成任务的评测配置自动分组产生，没有独立的“评测套件配置中心”。同一比较组（cohort）的条件包括数据集版本、评分工具及工具版本、任务指标权重、行业、场景、提示词及其版本。换数据集版本、换工具或改变这些协议条件，会产生不同的比较组。

任务准备流程为：发布数据集 → 创建评测任务时选择数据集、被测模型、提示词及“打分工具” → 提交审核并执行 → 完整有效结果进入对应套件。榜单在当前筛选范围内，为每个模型版本取最新的合格结果。不同套件的分数、名次不能直接横比；能力档案按套件分别展示，不计算跨套件平均分。

安全可信任务应从安全可信页面或编排Agent创建，并携带安全专项配置；随后复用任务管理执行。普通创建弹窗选择安全相关模板或打分工具，并不等于已经完成安全专项配置。安全榜单还需满足第21章的测量完整性与专家复核要求。

### 22.3 维度从哪里来，在哪里配置

真实榜单的维度来自数据集每道题的“标签”字段 data_label。同一个标签的题目归为一个能力维度；没有填写标签的题目归为“未分类”。这与数据集整体的分类标签不同，也不是评分工具自动生成的能力名称。

配置步骤：

1. 在导入文件中，为每道题准备输入、参考答案和能力标签。例如将数学题标为“数学推理”，代码题标为“代码理解”。
2. 进入“评测底座 → 评测数据”，打开目标数据集详情，在“导入数据”选择文件。
3. 在字段映射中，将题目能力列映射到“标签”（data_label），并确认输入、参考答案等字段映射后导入。当前样本预览表暂未显示标签列，可通过导出数据核对标签。
4. 完成质检、审核和发布，再使用该数据集版本执行正式任务。在榜单选择对应套件后，维度自动出现。

导入示例（JSONL，每行一条）：

```jsonl
{"input":"计算17乘以23，只输出整数","reference":"391","data_label":"数学推理"}
{"input":"计算12的平方，只输出整数","reference":"144","data_label":"数学推理"}
{"input":"Python中len([1,2,3])的结果是什么，只输出整数","reference":"3","data_label":"代码理解"}
```

当前每道题以一个 data_label 值分组。把“数学,推理”填在同一单元格会成为一个完整标签，不会自动拆成两个维度。当前没有独立的维度字典、维度树或逐维度绑定评分器界面；同一任务使用所选的一个打分工具。

### 22.4 每个维度如何评分，综合分如何计算

计算链路为：被测模型回答题目 → 所选工具产生逐题分数 → 按题目标签分组取平均 → 按维度权重汇总综合分。

| 常用工具 | 逐题评分方式 |
| --- | --- |
| 精确匹配 | 输出与参考答案去除首尾空白后相同得1，否则得0 |
| 关键词包含 | 输出包含指定参考内容得1，否则得0 |
| 正则匹配 | 输出符合正则规则得1，否则得0 |
| 文本相似度 | 根据输出与参考答案的文本相似程度产生0～1分；不等同于语义正确性或专家评分 |

维度得分＝该标签下所有有效题目分数之和÷题目数量。例如“数学推理”四题分别得1、1、0、1，维度原始分为0.75，页面显示75分。维度需要完整覆盖，缺测不补零。真实榜单还要求整个任务的样本完整、逐题评分有效，未完整任务不进入当前可比排名。

综合分＝Σ（维度得分×维度权重）÷Σ维度权重。配置入口为“模型榜单 → 综合权重设置”，或“榜单管理 → 综合权重”。填写各维度非负权重，总和必须大于零；零权重表示该维度不参与综合分。默认维度等权，即使两个维度分别有100题和10题，也默认各占一半，并非将全部题目直接平均。

权重调整影响实时榜，不会重写逐题原始分，也不会改变已经发布的历史快照。已确认0～1尺度的内置工具以百分制显示；未知评分尺度仅展示原始分，不授予统一排名，也不绘制统一尺度雷达。雷达至少需要三个共同完整维度，能力矩阵中的缺测不补为零。

题目标签只是分组依据。给题目标上“推理能力”不代表评分方法已能有效衡量推理，需要业务人员确认题目覆盖、难度、参考答案和评分工具适用性。

### 22.5 为什么没有上榜

试跑、模拟任务、非成功任务、评分未验证、缺少有效样本或未完整覆盖题集的任务不进入正式可比排名。待复核及确认排除的结果也会暂停入榜。检查当前模式、模型版本、筛选时间、套件、任务状态、逐题评分与复核状态；没有对应正式结果的分类可能不可点击。

不要通过修改试跑/模拟标记或直接改数据库成绩强行入榜。任务详情和任务列表均显示被测模型、数据集及评测工具，可据此核对是否选择了预期协议。

### 22.6 历史期数、发布、撤回与异常复核

“刷新”重新读取结果，不会重新执行评测。“评测期数”选择“实时结果”或已发布期数；历史快照冻结发布时的筛选范围、模型版本、权重和分数，部分筛选会锁定。历史趋势图展示真实任务执行时间序列，与发布期数不是同一概念。

有发布权限的人员进入“榜单管理 → 发布与期数”，核对当前结果后填写期数标题并发布。默认仅平台内查看；确需对外时明确勾选生成免登录公开链接，公开页面仅提供汇总字段。发布不触发重新评测。

有撤回权限的人员点击“撤回本期”并填写原因，公开链接停止提供结果，历史记录保留供审计。当前入口是撤回，不是将实时数据回滚到上一期。

发现疑点时，可在模型评测卡片点击“提交异常复核”，或进入“榜单管理 → 异常复核”填写来源任务和依据。待复核任务暂停入榜，受影响的已发布期数自动撤回。复核人员填写依据后选择恢复或排除；恢复原结果不会自动重新发布已撤回期数。复核及发布操作保留审计，原始成绩不被改写。

查看使用 leaderboard:view，权重与计价使用 leaderboard:edit，发布、撤回、复核分别使用 leaderboard:publish、leaderboard:withdraw、leaderboard:review；实际入口以当前账号授权为准。

### 22.7 成本与性价比口径

在“榜单管理 → 计价配置”为模型明确填写单价。费用按任务实际Token、逐样本实测耗时与配置单价估算，不再使用默认单价或按题数推算时延。缺少价格、必要用量或真实耗时时保留空值；估算费用为零时也不授予性价比排名。

每样本估算费用＝任务估算费用÷有效样本数；性价比指数＝综合原始分÷每样本估算费用。计价单位应由运营统一，费用不是供应商账单，采购与结算仍需核对合同和实际账单。

### 22.8 真实媒体结果与历史模拟链接

榜单已移除模拟切换和模拟API，旧链接中的demo=1不再加载虚构模型或分数。分类依据实际完成结果中的输入模态，而不是模型能力标签；只执行文本的视觉模型任务仍归入语言能力。

图片、音频、视频同样须满足真实调用、完整评分和同协议比较等门禁。抽帧视频保留测量范围，人工小样本验证不能代替行业基准或能力认证。

## 23 企业评测服务

### 23.1 入口与岗位分工

平台入口为“应用服务 → 评测服务”，页面地址为 /services。客户导航经过简化，可能直接显示“评测服务”。运营账号默认打开“企业与成员管理”，客户账号默认打开“需求与交付”。

运营方负责开通企业、管理成员、交付数据、审批额度和单价，并查看客户企业记录。客户方负责本企业模型服务接入、创建接入方、提交评测、跟踪任务和下载报告。同企业成员共享服务任务与资产，企业内多个工作空间不是进一步的保密边界。

本章提供操作总览；详细岗位流程见本目录《评测服务用户手册 运营方与客户方》。当前门户不再以“自动报价 → 专家报价 → 交付”和“影子采样 → 转正”作为页面操作流程，旧内部服务接口不能替代企业门户。

### 23.2 运营方开通与管理企业

1. 在“企业与成员管理”点击“开通企业”，填写企业名称、登录账号和初始密码，或生成随机密码。
2. 保存后系统创建企业、首位客户成员及默认工作空间。在列表按名称搜索，核对企业状态与成员数量。
3. 通过安全渠道交付访问地址和个人账号，建议客户首次登录后修改密码。
4. 企业行的“编辑”可修改名称、启用或停用企业；“成员与记录”打开该企业管理面板。
5. 确需结束服务时点击“删除”并确认影响；临时暂停使用“停用”。

停用或删除企业后，其成员不能登录使用服务，API网关也会拒绝新请求。这些动作不等于取消已在执行的任务，需另行核对任务最终状态。删除采用逻辑删除，保留历史资产、计量与审计归属；当前页面没有恢复已删除企业的入口。

### 23.3 运营方维护成员与密码

进入“目标企业 → 成员与记录 → 企业成员”，查看登录账号、昵称、邮箱、电话与状态。

| 操作 | 使用方法与影响 |
| --- | --- |
| 添加成员 | 启用企业中填写账号及初始密码后保存 |
| 编辑 | 修改昵称、邮箱、电话或账号状态；登录账号固定 |
| 停用 | 在编辑中选择停用；该成员不能登录，其创建的API密钥也不可用 |
| 重置密码 | 设置或生成新密码，保存前妥善记录；旧密码不再用于登录 |
| 删除 | 确认后禁止成员登录并保留历史归属；已删除账号不能重用 |
| 评测记录 | 跳转到操作记录并自动筛选该成员 |

密码至少12个字符，包含字母和数字，支持随机生成。平台存储密码摘要，不提供已有密码明文。已删除成员保留在成员表和记录筛选中用于追溯，不应重复删除。客户侧可添加本企业成员，成员编辑、停用、删除和密码重置由运营方处理。

### 23.4 数据交付 模型授权与接入额度

企业开通后不自动具备数据集或调用额度。运营先准备已发布且当前版本质检通过的数据集，再在企业行点击“交付数据集”，按名称选择启用企业和可交付数据集。交付会复制版本与样本并保留来源审计，源数据后续变化不会自动同步客户副本。

客户在本企业创建接入方后，运营进入“目标企业 → 成员与记录 → 接入方与配额”，按名称找到接入方并点击“调整额度”。也可从“企业空间与资产 → 为企业接入方分配额度”依次选择企业和接入方，不需要手填ID。

设置每日Token额度、每月Token额度、每分钟请求数和人民币分 / 千Token单价。新接入方默认额度为0，客户不能自行提高。日/月额度按北京时间重置，在途与待核量预占仍影响可用额度；调用创建时冻结单价，修改价格不会自动重算历史金额。

平台模型的“共享”只作用于所属企业，不能直接跨企业使用。运营在“企业与成员管理 → 目标企业 → 模型授权”选择平台模型及允许交付的冻结版本，点击“授权所选版本”。客户刷新后才可在“关联已有版本”中选择。支持一次授权多个版本，相同企业与源版本重复授权不产生重复快照。

授权按所选版本交付独立快照，不会自动同步或随源模型停用而撤销；上游凭据不在客户门户显示。运营可在授权列表撤销指定版本，阻止该版本的新评测，并保留历史记录。已有服务若绑定被撤销版本，需改用其他可用版本；撤销不等于取消已运行任务。

### 23.5 客户方准备接入方与模型服务

授权模型表示企业可用的模型资产，冻结模型版本表示该模型某个版本保存的接口配置。模型注册时生成初始版本及快照，访问地址、认证或请求映射等配置更新时会生成新版本和快照。仅登记版本号不一定已有可用冻结配置；冻结配置也不代表锁定供应商实际模型权重。

运营需先按第23.4节将平台模型的指定版本授权到客户企业。客户刷新后在授权模型中选择模型，再选择对应冻结版本。“服务版本名”是对外发布标签，可以与模型版本号不同。例如“客服模型 / V1.0”关联为服务版本“正式版v1”。完成关联后还要配置稳定路由，才具备提交评测的模型服务条件。

1. 登录后在页头选择企业工作空间，在“企业空间与资产”确认共享数据集和授权模型，需要时新建空间或添加成员。
2. 在“接入方与用量账单”点击“创建接入方”，填写名称。保存弹窗中的API Key只展示一次，关闭后只能看到前缀。
3. 将企业、工作空间和接入方名称告知运营申请额度。密钥丢失时新建接入方并按需撤销旧密钥，不把登录密码当作API Key。
4. 在“模型服务与版本”注册模型服务，再“关联已有版本”，或“注册模型接口”。前者按名称选择授权模型及可用冻结版本，后者填写接口地址、上游模型标识和凭据。
5. 点击“配置路由”选择稳定版本，核对卡片显示为可调用后再提交评测。

上游接口当前需兼容OpenAI协议，并使用运营允许精确域名的HTTPS地址和443端口。界面可选择地址或输入自定义路径，白名单未配置时联系运营。稳定和灰度版本必须不同；未选灰度版本时不能设置灰度比例。

灰度路由影响后续任务，已创建任务保持原版本。存在上一稳定版本时可“回滚”并关闭灰度；此动作不代表质量门禁已经通过。

### 23.6 客户方提交评测与确认执行

点击页头“提交评测需求”，填写标题，选择配置方式、接入方、模型服务和共享数据集。Token预算可选1千、1万、10万、100万档位或自定义，不能超过当前剩余额度。更换接入方会调整默认预算；无接入方、稳定版本、共享数据集或额度时按提示补齐。

自动化模式使用标准精确匹配，提交后直接入队。专家模式还需选择中文场景和裁判工具，可选精确、包含、正则或模糊匹配。定制化需求用于记录补充要求，不代表自动完成任意定制开发。

专家模式提交后先形成“待确认配置”任务，在“需求与交付”核对后点击“确认执行”。此确认用于启动任务，不代表人工专家已经完成报告复核。

### 23.7 客户方跟踪任务与下载报告

在“需求与交付”按标题搜索、按提交成员选择筛选，查看配置模式、状态、进度、实际 / 预占Token和分页总数。页面约每15秒更新一次，也可手动刷新。

草稿、排队、运行或预算暂停等允许状态可点击“取消”，继续查看最终状态；实际消耗仍会计量。失败或部分失败时先保留调用编号、标题和错误信息并联系运营，不反复提交同一需求。

正式报告就绪后任务行出现“下载报告”，当前门户下载JSON。任务完成、报告生成、用量计量和实际收款分别检查；“待核量”不能按0消耗处理。接入方与用量账单中的调用计量明细展示当前已加载任务页，完整任务翻页请回到“需求与交付”。

### 23.8 企业与成员记录查询

运营方从目标企业的“成员与记录 → 操作记录”查看客户企业记录，或点击成员行“评测记录”自动筛选。客户方从主页面“评测操作记录”查看本企业。运营主页面的记录默认属于运营账号所在企业，不是所有客户的总表。

“成员操作”可按成员、操作类型和时间查询，包含已记录的提交、确认、取消、下载及管理动作，支持分页与详情。“API访问记录”按密钥创建成员归属，展示请求方法、路径、HTTP状态和接入方名称；密钥创建人不一定是实际调用者。幂等重试、查询和错误也会形成访问记录，不能按访问条数计算新任务数。

此记录入口按北京时间显示，原有网关审计及调用计量表标为UTC，跨表对照需注意8小时时差。新补充审计从上线后开始记录，旧版本没有记录的操作不会自动补造。

### 23.9 API接入与异常处理

集成人员在“接入方与用量账单 → API接入”查看当前空间请求示例。使用X-API-Key鉴权，提交评测时携带唯一Idempotency-Key；相同键和相同请求返回原调用，不重复预占，不同请求不能复用原键。

提交路径为POST /api/service-gateway/v1/evaluations；查询和报告下载使用返回的调用编号。API提交专家模式后仍需有权成员到页面确认执行。频繁状态轮询也占用网关请求频率。

401或403先检查密钥、成员、企业状态及权限；429分别核对日/月额度和请求频率。不能查看旧密码时使用重置流程。找不到模型、数据或报告时，依次核对稳定版本、数据交付和正式报告就绪情况。报障提供企业、空间、接入方、调用编号和时间，不发送完整凭据。

## 24 工作台与系统管理

### 24.1 每天从工作台开始

工作台汇总进行中任务、待确认编排、待审任务和任务总数，并提供待办、异常任务、最近任务及快捷入口。先处理失败或预算异常，再检查等待审核与待确认计划，最后安排新任务。

点击统计卡会跳转相应列表，有些跳转带预设筛选。如果数字与列表条数看似不一致，检查筛选与权限范围，不直接认定数据丢失。点击“处理”进入待办后仍需阅读完整对象信息。

### 24.2 用户管理

有权限人员进入“用户管理”，按用户名、手机号或邮箱搜索，可使用角色、创建人、时间和排序筛选。新增用户时填写真实岗位所需信息，赋予最小必要角色。保存后用该用户自己的登录身份验证菜单与动作，而不是只在管理员账号下检查。

外部企业客户优先使用第23章的“企业与成员管理”，不要通过一般用户管理入口代替客户成员的企业归属和历史记录管理。

人员离岗或暂停操作时可“禁用”；重新启用需确认责任归属。编辑、禁用与删除是不同动作，删除前检查对象归属和历史记录要求，不因列表仍保留审计引用就重复删除。

### 24.3 权限管理

进入“权限管理”，选择角色，设置数据可见性和功能权限后“保存”。“仅自己的数据”与“全部数据”是角色数据范围选项，不能据此承诺所有历史接口都已实现完整跨租户隔离；高敏感或跨租户用途需管理员验证实际部署的对象策略。

权限矩阵可全选、清空或仅读。给岗位授权应按任务逐项配置，避免直接全选。管理员角色页面标记为不可编辑。保存后检查该岗位需要的列表、详情、创建、调用和审批是否形成完整工作流。

### 24.4 个人中心

个人中心可更新头像、昵称、手机号和邮箱并“保存资料”。修改密码需填写原密码、新密码及确认密码，按校验提示操作。不要把个人资料修改误认为管理员为其他用户重置密码。

### 24.5 通知

个人通知中心用于阅读与本账号有关的通知；通知管理用于有权限人员发送和维护通知。发送时核对标题、内容、提示/成功/警告/错误类型以及全体或指定用户目标，避免向全体人员广播仅针对单个任务的敏感内容。

发送后在列表核对目标、时间与内容；删除通知不等于撤销其中涉及的任务或审批。收到了“成功”类型通知也仍需进入对应任务检查事实。

### 24.6 操作审计

操作审计用于按操作人、资源、动作及时间排查记录。查看对象 ID、说明、IP、trace 和租户，结合任务或资源调用编号建立事件链。企业评测服务的日常查询使用第23章“评测操作记录”；运营跨企业查询应先进入目标企业。系统操作审计仍需独立的audit:list权限。当前页面“导出”按钮禁用，不能按现成功能要求普通人员直接导出审计包；需要时走管理员受控取证流程。

### 24.7 接口文档

接口文档内嵌 Swagger，支持新窗口打开 /docs。平台管理接口使用登录 JWT，当前页面会为平台接口请求带入登录凭证。Try it out 可能真实创建、修改或运行对象，不是只读演示。

使用前确认方法、路径、请求体和目标环境。GET通常用于查询；POST等操作应按具体接口语义判断，不在生产环境随意执行示例。知识候选等缺少完整页面入口的功能，可由获授权人员通过该入口操作，并留存返回编号。

## 25 运行支撑与日常运维

### 25.1 准入与探针

进入“系统管理 → 运行支撑 → 准入与探针”。查看健康状态、依赖和准入记录。有 ops:admit 的人员可运行“基础准入”或“完整准入”，逐项阅读状态和说明。

pass仅表示该项按当前实现得到的结果；failed、blocked、not_run 应分别处理。完整准入按钮不能代替企业证书、生产负载、恢复时限和组织签署等外部验证。不要把缺少证据的检查改写为通过。

### 25.2 备份与恢复演练

有 ops:backup 的人员可“立即备份”，完成后核对备份目录及结果。仅看到任务触发消息不足以证明备份可用，应按运维制度检查产物和恢复验证。

“恢复演练”用于验证恢复过程与记录，操作前确认允许的环境和演练对象，完成后检查结果、RPO/RTO证据和异常。演练记录不是授权覆盖生产数据库的指令，实际恢复按运维 runbook 和组织变更流程办理。

### 25.3 故障注入

页面提供“注入DB断连”“注入证书过期”和“清除降级”。这些动作可能影响服务状态，只在已批准的演练环境和窗口使用。先记录基线，再注入单一故障观察告警和恢复，最后清除降级并验证服务恢复，不同时注入多个不易区分的故障。

### 25.4 工单闭环

在“工单”填写标题，选择故障、变更、漏洞、请求或一般类别后“建单”。负责人可“认领”，处理后“关闭”，不再适用记录可按制度“停用”。关闭前应有问题原因、处置和验证证据，停用不等于问题已经解决。

建议标题包括模块和现象，例如“模型试调用返回401”。说明中关联任务、模型、资源、会话、Run及trace编号，写清首次时间、影响范围、已尝试措施和当前状态，避免粘贴密钥。

### 25.5 演练 授权和制度

“演练与授权”可登记 release 演练和数据授权。演练需真实证据，不能仅点击登记就填写成功。数据授权填写资产引用、SPDX或内部许可标识、授权方及用途；许可字段是记录，不会自动取得数据使用权。授权终止时按页面停用并检查后续使用。

“报表与制度”汇总工单、演练、有效授权、任务和审计等数量，制度索引指向项目运维文档。报表数量用于管理，不作为平台全部生产能力已经通过的证明。

### 25.6 值班操作顺序

上班先看探针、异常任务和预算阻塞，再看备份及未闭环工单；执行变更前记录对象版本与回退方案；下班前确认正在运行的任务、待审批计划、未恢复故障及交接负责人。需要删除快照、恢复数据库或切换服务时，使用受控入口，不直接改调度内部字段。

## 26 常见问题与处理指引

| 问题 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 看不到菜单或按钮 | 缺页面或动作权限 | 提供账号和菜单路径，由管理员检查角色 |
| 列表为空 | 筛选、页码、对象范围或确无记录 | 清筛选再查询，区分加载失败与暂无数据 |
| 数据导入失败 | 编码、文件格式或列映射错误 | 用UTF-8 CSV或XLSX重新预览，核对输入与参考 |
| 数据无法发布 | 当前版本质检不是passed | 处理问题并复检，检查审核意见 |
| 模型探测正常但无输出 | 推理路径、模型名、模板或响应映射不匹配 | 做单条试调用并核查响应结构 |
| 正式任务被阻止 | 数据未发布、质检失败、提示词未发布或模型无endpoint | 补齐门禁后重建或重新核对计划 |
| 任务一直排队 | 依赖未完成、执行器或容量问题 | 查依赖、任务事件与运行支撑 |
| 任务显示成功但结果不完整 | 跳过、未执行或状态汇总限制 | 核查逐样本执行及评分状态，不直接交付 |
| 所有得分为0 | 实际答错、精确匹配太严或裁判失败 | 区分scored与error，再看原始输入输出 |
| 预算暂停 | 已到预算、共享批次限制等 | 查Task/Run/Batch对应预算，由负责人处理 |
| 企业已开通但不能评测 | 接入方额度为0、模型未授权或未配稳定版本、未交付数据 | 按第23章完成接入方、额度、数据与模型授权及关联 |
| 平台有模型但客户无法关联 | 共享范围仅限所属企业，或目标版本未授权 | 运营进入目标企业的模型授权，选模型和冻结版本交付；客户刷新后关联并配置稳定路由 |
| 只有版本号而没有可选冻结版本 | 版本缺少可用的接口配置快照 | 由模型负责人核对版本可用状态与冻结配置，再由运营授权所需版本 |
| 客户无法登录或API失效 | 企业或成员停用、删除，密钥撤销或密码错误 | 由运营核对状态、归属和密钥，忘记密码走重置 |
| 查不到客户成员操作 | 未进入目标企业、筛选或记录权限缺失 | 运营从企业管理进入，核对service:records与时间范围 |
| 生成计划按钮不可点 | 无目标或未选规划模型 | 配置模型api_url并在评测准备中选择 |
| 计划反复要澄清 | 数据场景不匹配、资源不可用或预算缺失 | 显式选资源，检查编码和所有validation_errors |
| 审批失效 | 计划修改、过期或已消费 | 核对最新计划后重新审批，先查已有task_id |
| Runtime报planner_unavailable | 服务、认证或工具调用兼容问题 | 检查规划模型接入和真实tools协议响应 |
| Runtime报invalid_tool_schema | 模型给出未知工具或错误参数 | 查看tool.rejected，使用兼容模型并缩小目标 |
| Runtime报empty_model_response | 既没有工具调用也没有有效文本 | 检查服务响应，不接受空回复当成功 |
| Runtime报max_rounds | 持续选工具超过轮次 | 缩小目标，检查工具结果，新建受控Run |
| Runtime报409 | 同会话已有活跃Run或运行正被其他执行者持有 | 查询现有Run，等待或按需要取消，不并发恢复 |
| Runtime一直等待审批 | 尚未消费与当前计划匹配的审批 | 核对计划，审批并确认执行，不能用恢复按钮代替授权 |
| Runtime一直等待任务 | 任务未进入终态或后台执行器未运行 | 查task_id、任务事件和后台服务，不重复建任务 |
| 子Agent报subagent_planner_required | 未配置可调用的规划模型 | 给会话选择真实规划模型并验证工具调用 |
| Agent调用MCP报目录或参数错误 | 未启用连接、目录缺失或arguments不符合Schema | 在工具底座获取目录并试用，回会话启用连接，检查实际参数 |
| Run结束但目标未核验 | 只是对话完成，或试跑、模拟、结果和报告不全 | 按第16.6节检查实际任务与逐样本结果 |
| Skill某步失败 | 输入、引用或下游调用问题 | 按失败step_id定位，先单独验证工具 |
| MCP目录可读但调用失败 | Schema变更、认证或工具自身错误 | 重新取目录，查JSON-RPC及工具错误 |
| 知识审核后搜不到 | 查询词不匹配、条目过期、租户不同或模型未检索 | 用短关键词验证同租户有效条目，区分Runtime与规则计划的检索路径 |
| 报告按钮没有出现 | 报告未生成或任务仍在处理 | 看report_status及错误，必要时重渲染 |
| 影子无法转正 | 服务端观测或门禁证据不足 | 阅读门禁详情，补真实观测，不填客户端分数 |

### 26.1 报障信息模板

提供环境、发生时间、账号角色、页面路径、操作步骤、预期与实际结果；再附对象编号（dataset/model/resource/task/session/run/batch）、错误码、trace、最近事件以及是否已重试。截图应遮挡密钥和敏感样本。不要只描述“不能用”，也不要在未确认原因时删除失败记录。

### 26.2 遇到实现与手册不一致

先确认部署版本是否与本手册基线一致，再对照当前页面和接口文档。将不同按钮、返回字段和状态记录到工单，由维护人员更新手册或修复实现。设计目标不能覆盖实际错误，也不能以历史测试通过说明当前环境必然可用。

## 27 岗位操作清单

### 27.1 评测操作人员

- 开始前：核对数据授权、版本、模型连接、裁判用途和预算。
- 执行前：确认试跑或正式模式、提示词版本、样本量及审批。
- 执行中：看任务事实，区分模型失败、裁判错误和答案不通过。
- 结束后：核对覆盖率、真实输出、报告与费用口径，保留必要证据。
- 经验复用：整理知识候选，审核后验证检索，不假设自动长期记忆。

### 27.2 审批与质量人员

- 数据发布前核对质检报告与当前版本；不因工单已忽略就认定数据正确。
- Agent审批前核对计划hash对应的对象、版本、预算与用途。
- 知识审核查看完整内容、来源、有效期和适用范围。
- 安全复核填写理由，正式报告保留未执行项和争议结论。
- 榜单发布前核对cohort、来源任务和排除原因。

### 27.3 资源管理员与运维人员

- 凭证通过受控配置管理，注册时填写引用，不写进Agent目标或知识。
- Tool先单测调用，Skill逐步验证，MCP依次验证握手、目录、调用。
- 控制stdio别名与生产接入策略，副作用阻断不能靠删声明绕过。
- 检查备份、探针、告警及工单，恢复和故障注入按演练窗口执行。
- 维护当前部署能力边界，不将Mock、评测桩、模拟或未实测性能列为正式通过。

### 27.4 服务运营与企业客户

- 运营交接：核对企业、成员、数据交付、接入方额度和价格；暂停优先停用，删除前完成资料交接。
- 客户评测：确认稳定模型版本、共享数据集和剩余额度；专家模式提交后还需确认执行。
- 记录核对：成员操作、API请求、评测任务和计量是不同记录；跨企业从目标企业进入。
- 凭据管理：密码不能查看旧明文，密钥只展示一次；报障不发送完整凭据。
