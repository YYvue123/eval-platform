# 多模态执行运维

依赖通过`backend/requirements.txt`安装，其中imageio-ffmpeg提供随包FFmpeg，无需系统PATH中的ffmpeg。程序只允许file/pipe协议并使用临时目录，不主动下载外部媒体。抽帧最多8帧，音视频限制25MB及120秒，媒体处理子进程有超时。

部署后检查内置资源`builtin/media_inspect`是否已由启动种子注册，经`/api/resources/invoke`使用有权限账号执行一条有效媒体检查。该工具只测媒体结构，不返回评分。模型端点真实验收必须另外完成。

| 现象 | 检查与处理 |
| --- | --- |
| 解码失败 | 检查实际字节、声明MIME及格式是否一致，检查imageio-ffmpeg依赖；不要用文件扩展名代替格式判断 |
| 时长不合法或处理超时 | 确认媒体不超过120秒；高分辨率高帧率片段可先在受控流程转换为短片，再形成新基准版本 |
| 模态不匹配 | 对照冻结模型输入/输出能力；原生视频需video，有音轨还需audio；抽帧有音轨需image/audio |
| 1.5秒请求对应1秒帧 | 核对低帧率或可变帧率文件；实际帧PTS与请求时间分别记录，这不是额外帧覆盖 |
| 请求音频只有文本 | 供应商没有返回所需音频，按模型失败处理；检查模型ID、输出模态及voice/format |
| 新字段未显示 | 重启后端加载序列化与资源代码，刷新前端；任务创建人查User，媒体证据查结果metrics |

自动测试必须使用`tests/isolated_env.py`。真实开发演示使用业务API，先备份业务库，禁止直接修改调度状态或评分。脚本`backend/scripts/verify_multimodal_video_real.py`会创建数据和任务，不应当作CI回归运行。

音频和原生音画联合接入应参考供应商当前协议：OpenAI兼容input_audio/音频输出，或支持video_url的端点。模型能力声明不是验收凭据；音频真实验收在本轮明确未执行。
