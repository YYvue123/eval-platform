# 外部企业评测服务

更新日期：2026-09-29。

## 客户入口与权限

`/services` 现在是企业客户的服务门户：需求与交付、模型服务与版本、接入方与用量账单、企业空间与资产。客户使用独立的 `customer` 角色，不获得系统用户管理、模型后台、任务后台、运营后台等权限。客户登录与刷新页面会先加载权限；客户导航只显示可用的服务和个人设置。

服务运营（`service:admit`，默认仅平台管理员）通过页面“企业空间与资产 / 开通企业客户”创建企业租户、客户账号及默认空间。此流程没有默认密码，要求输入至少 12 字符初始密码。客户可添加同企业成员，成员拥有客户服务权限；本次协作范围为**企业级共享**，同企业多个空间不是进一步的保密边界。

新增权限：`service:workspace`、`service:credential`、`service:publish`、`service:run`、`service:admit`。内部 researcher/viewer 不自动获得密钥、企业管理和定价权限。旧 `/api/services` 内部委托接口保留兼容，但拒绝 customer 身份，外部客户不能借旧接口读取全局空间或跳转服务状态。

## 首次接入

1. 运营开通企业客户，记录返回的企业 ID 和空间 ID。
2. 运营通过“交付评测数据集”把自己有权访问的、已发布且质检通过的版本复制到客户企业。保留样本与质检信息，记录来源版本；不构造质检通过结果。
3. 客户创建接入方，保存仅展示一次的 API Key。数据库只保存 SHA-256 摘要及前缀。新接入方额度为 **0**，不能自行提高额度。
4. 运营通过接入方 ID 设置每日/月 Token 额度、每分钟请求数及单价（人民币分 / 千 Token）。调用会冻结当时单价。
5. 客户注册模型服务，可关联已授权的冻结版本，或注册模型接口版本。上游接口目前支持 OpenAI 兼容协议。
6. 配置稳定版本及可选灰度版本，随后提交评测。

客户自行注册上游接口需要部署配置 `SERVICE_MODEL_HOSTS`，值为允许的精确域名，以逗号分隔。仅接受 HTTPS、443 端口，不接受 URL 用户名/密码、查询串或片段。默认空列表拒绝客户提供的上游地址。域名应由运营核实；生产环境同时配置网络出口策略，防止已允许域名的 DNS 变化指向内部服务。上游凭据不会返回到客户资产列表。

## API

门户：`/api/service-portal`，使用登录 Bearer token 与 `require_permission`。

外部网关：`/api/service-gateway/v1`，使用 `X-API-Key`，只允许访问绑定接入方的空间及评测调用；密钥不能用来登录平台内部 API。

- `GET /services`：发现接入方所在空间的模型服务与版本。
- `GET /usage`：查询接入方额度和用量。
- `POST /evaluations`：提交评测，必须提供 `Idempotency-Key` 请求头（1–100 字符）。
- `GET /evaluations/{id}`：查询进度与计量状态。
- `GET /evaluations/{id}/report`：下载已生成的正式 JSON 报告。

提交示例（替换为本企业实际 ID）：

```json
{
  "client_id": 12,
  "route_id": 8,
  "title": "企业客服助手评测",
  "requirement": "验证共享客服数据集上的问答能力",
  "mode": "auto",
  "dataset_id": 30,
  "token_budget": 10000
}
```

自动化模式使用标准精确匹配裁判并入队。专家模式支持场景、已有内置裁判和指标权重配置，先生成草稿，再由客户确认执行。配置的模式与需求保存在服务单，任务创建复用现有校验和 TaskService；不能通过门户直接写分数或调度内部状态。

生产执行需要运行已有 worker：`cd backend && python -m app.worker`。未启动 worker 时任务会保持排队，不伪装成执行完成。报告由现有执行器和归档逻辑生成；不存在报告、未结束、trial/simulation 均不会开放正式报告下载。

## 版本与灰度

服务版本映射固定绑定模型 ID 及冻结的模型版本 ID；同名服务版本不可覆盖。灰度按接入方与幂等键的稳定哈希分桶，真正决定新任务使用的版本。变更路由不会修改已创建任务；回滚恢复上一稳定版本并关闭灰度。

这是客户控制的版本发布，不等同于自动质量准入。界面不会把灰度开启、注册成功或人工切换显示为质量门禁通过，原影子评分门禁保持独立。

## 配额、计量与审计口径

- 以北京时间划分日/月，存储 UTC 时间。历史用量归属调用提交日/月；未结束或待核量任务的预占会跨周期继续占用额度。
- 提交前按请求预算同时检查日/月额度；同一接入方通过数据库写锁序列化检查及预占，避免并发绕过。
- 幂等键唯一约束为接入方 + key。同键同请求复用原调用；同键不同请求返回 409。配额/频率不足返回 429，不创建可执行任务。
- 正常结束后按服务端任务记录的实际 Token 释放多余预占，以调用时单价计算金额，按每次调用向上取整到分。失败/取消保留已发生的用量。
- 上游成功调用缺少 Token 数据时标记 `unmeasured`（待核量），保留预占；不能把未知用量当成零费用结算。金额只是当前已知用量计量，**未接支付、扣款、发票或财务对账系统**。
- 现有执行器在样本间检查预算：单次上游请求可能超过剩余预算，实际超额仍记录并阻止后续新提交。因此目前是准入预占和样本间预算控制，不是上游逐 Token 的硬截断。
- `service_calls` 保存评测提交、拒绝、预算、路由和价格信息；`service_gateway_audits` 逐条保存网关请求的方法、路径、HTTP 状态和时间，包括幂等重试、参数错误和鉴权失败。未知密钥记录为未归属日志，不向其他企业展示。
- 网关查询和提交均检查接入方请求频率；评测提交另有事务内频率检查。多进程严格限流验证范围为评测提交，查询请求的同时突发可能略超滚动窗口阈值。

## 数据变更与验证

新增五张表：`service_clients`、`service_routes`、`service_releases`、`service_calls`、`service_gateway_audits`。由已有 `init_db / metadata.create_all` 创建，不修改已有服务单、任务及业务数据。没有在本次开发中启动业务库迁移。

后端测试：`cd backend && python -m unittest tests.test_service_portal tests.test_service_shadow -v`。使用 `tests/isolated_env.py`，不访问业务 `eval_platform.db`。外部服务测试覆盖跨租户、权限、幂等、并发预占、日/月额度、限流、密钥撤销、注册白名单、灰度回滚、专家确认/取消、资产交付和 TaskService 到报告的链路。

前端：`npm run collect-permissions`、`npm run build`。浏览器测试：`node node_modules/@playwright/test/cli.js test e2e/service-portal.spec.mjs --reporter=list`，用 `E2E_BASE_URL` 指向前端预览。浏览器 API 数据为 UI fixture；后端执行链路使用本地可控 HTTP provider fixture。这些是代码与集成验证，**不作为真实模型效果、生产收费或生产准入通过的证据**。
