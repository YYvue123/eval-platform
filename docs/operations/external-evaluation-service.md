# 外部企业评测服务

更新日期：2026-10-24。

岗位操作见[评测服务用户手册 运营方与客户方](../user-manual/评测服务用户手册_运营方与客户方.md)；本文保留部署、协议和运行核对说明。

## 客户入口与权限

`/services` 现在是企业客户的服务门户：需求与交付、模型服务与版本、接入方与用量账单、企业空间与资产，以及评测操作记录；运营方另有企业与成员管理。平台菜单路径为“应用服务 → 评测服务”，客户导航可直接显示评测服务。客户使用独立的 `customer` 角色，不获得系统用户管理、模型后台、任务后台、运营后台等权限。客户登录与刷新页面会先加载权限；客户导航只显示可用的服务和个人设置。

服务运营（`service:admit`，默认仅平台管理员）通过页面“企业与成员管理 / 开通企业”（或“企业空间与资产 / 开通企业客户”）创建企业租户、客户账号及默认空间。此流程没有默认密码，要求设置至少 12 字符且含字母与数字的初始密码，可生成随机密码。客户可添加同企业成员，成员拥有客户服务权限；本次协作范围为**企业级共享**，同企业多个空间不是进一步的保密边界。

新增权限：`service:workspace`、`service:credential`、`service:publish`、`service:run`、`service:admit`、`service:records`。内部 researcher/viewer 不自动获得密钥、企业管理和定价权限。旧 `/api/services` 内部委托接口保留兼容，但拒绝 customer 身份，外部客户不能借旧接口读取全局空间或跳转服务状态。

## 首次接入

1. 运营开通企业客户，在企业目录按名称确认企业、首位成员和默认空间；业务交接使用企业、账号与空间名称，内部编号用于API和排障。
2. 运营通过“交付评测数据集”把自己有权访问的、已发布且质检通过的版本复制到客户企业。保留样本与质检信息，记录来源版本；不构造质检通过结果。
3. 客户创建接入方，保存仅展示一次的 API Key。数据库只保存 SHA-256 摘要及前缀。新接入方额度为 **0**，不能自行提高额度。
4. 运营在“企业与成员管理 → 目标企业 → 成员与记录 → 接入方与配额”选择接入方并设置每日/月 Token 额度、每分钟请求数及单价（人民币分 / 千 Token）。调用会冻结当时单价。
5. 客户注册模型服务，可关联已授权的冻结版本，或注册模型接口版本。上游接口目前支持 OpenAI 兼容协议。
6. 配置稳定版本及可选灰度版本，随后提交评测。

客户自行注册上游接口需要部署配置 `SERVICE_MODEL_HOSTS`，值为允许的精确域名，以逗号分隔。仅接受 HTTPS、443 端口，不接受 URL 用户名/密码、查询串或片段。默认空列表拒绝客户提供的上游地址。域名应由运营核实；生产环境同时配置网络出口策略，防止已允许域名的 DNS 变化指向内部服务。上游凭据不会返回到客户资产列表。

## API

门户：`/api/service-portal`，使用登录 Bearer token 与 `require_permission`。

外部网关：`/api/service-gateway/v1`，使用 `X-API-Key`，只允许访问绑定接入方的空间及评测调用；密钥不能用来登录平台内部 API。

- `GET /services`：发现接入方所在空间的模型服务与版本。
- `GET /usage`：查询接入方额度和用量。
- `POST /evaluations`：提交评测，必须提供 `Idempotency-Key` 请求头（1–100 字符）。
- `GET /evaluations/{id}`：查询进度与计量状态。
- `GET /evaluations/{id}/report`：下载已生成的正式 JSON 报告。

提交示例（替换为本企业实际 ID）：

```json
{
  "client_id": 12,
  "route_id": 8,
  "title": "企业客服助手评测",
  "requirement": "验证共享客服数据集上的问答能力",
  "mode": "auto",
  "dataset_id": 30,
  "token_budget": 10000
}
```

自动化模式使用标准精确匹配裁判并入队。专家模式支持场景、已有内置裁判和指标权重配置，先生成草稿，再由客户确认执行。配置的模式与需求保存在服务单，任务创建复用现有校验和 TaskService；不能通过门户直接写分数或调度内部状态。

生产执行需要运行已有 worker：`cd backend && python -m app.worker`。未启动 worker 时任务会保持排队，不伪装成执行完成。报告由现有执行器和归档逻辑生成；不存在报告、未结束、trial/simulation 均不会开放正式报告下载。

## 版本与灰度

服务版本映射固定绑定模型 ID 及冻结的模型版本 ID；同名服务版本不可覆盖。灰度按接入方与幂等键的稳定哈希分桶，真正决定新任务使用的版本。变更路由不会修改已创建任务；回滚恢复上一稳定版本并关闭灰度。

这是客户控制的版本发布，不等同于自动质量准入。界面不会把灰度开启、注册成功或人工切换显示为质量门禁通过，原影子评分门禁保持独立。

## 配额、计量与审计口径

- 以北京时间划分日/月，存储 UTC 时间。历史用量归属调用提交日/月；未结束或待核量任务的预占会跨周期继续占用额度。
- 提交前按请求预算同时检查日/月额度；同一接入方通过数据库写锁序列化检查及预占，避免并发绕过。
- 幂等键唯一约束为接入方 + key。同键同请求复用原调用；同键不同请求返回 409。配额/频率不足返回 429，不创建可执行任务。
- 正常结束后按服务端任务记录的实际 Token 释放多余预占，以调用时单价计算金额，按每次调用向上取整到分。失败/取消保留已发生的用量。
- 上游成功调用缺少 Token 数据时标记 `unmeasured`（待核量），保留预占；不能把未知用量当成零费用结算。金额只是当前已知用量计量，**未接支付、扣款、发票或财务对账系统**。
- 现有执行器在样本间检查预算：单次上游请求可能超过剩余预算，实际超额仍记录并阻止后续新提交。因此目前是准入预占和样本间预算控制，不是上游逐 Token 的硬截断。
- `service_calls` 保存评测提交、拒绝、预算、路由和价格信息；`service_gateway_audits` 逐条保存网关请求的方法、路径、HTTP 状态和时间，包括幂等重试、参数错误和鉴权失败。未知密钥记录为未归属日志，不向其他企业展示。
- 网关查询和提交均检查接入方请求频率；评测提交另有事务内频率检查。多进程严格限流验证范围为评测提交，查询请求的同时突发可能略超滚动窗口阈值。

## 数据变更与验证

新增五张表：`service_clients`、`service_routes`、`service_releases`、`service_calls`、`service_gateway_audits`。由已有 `init_db / metadata.create_all` 创建，不修改已有服务单、任务及业务数据。没有在本次开发中启动业务库迁移。

后端测试：`cd backend && python -m unittest tests.test_service_portal tests.test_service_shadow -v`。使用 `tests/isolated_env.py`，不访问业务 `eval_platform.db`。外部服务测试覆盖跨租户、权限、幂等、并发预占、日/月额度、限流、密钥撤销、注册白名单、灰度回滚、专家确认/取消、资产交付和 TaskService 到报告的链路。

前端：`npm run collect-permissions`、`npm run build`。浏览器测试：`node node_modules/@playwright/test/cli.js test e2e/service-portal.spec.mjs --reporter=list`，用 `E2E_BASE_URL` 指向前端预览。浏览器 API 数据为 UI fixture；后端执行链路使用本地可控 HTTP provider fixture。这些是代码与集成验证，**不作为真实模型效果、生产收费或生产准入通过的证据**。

## 使用手册：平台用户如何开通客户

下面的流程适用于平台管理员或被授予 `service:admit` 的服务运营人员。平台用户负责企业开通、资产交付、额度审批和服务版本管理；外部客户只负责本企业内的配置和调用。

### 1. 开通外部企业

登录平台后进入“应用服务 → 评测服务 → 企业与成员管理”，点击“开通企业”。填写企业名称、客户登录账号和初始密码。初始密码至少 12 个字符，没有默认密码，可通过“生成随机密码”生成本次初始密码。

提交后在企业目录核对企业和默认工作空间，并通过安全渠道把登录账号和初始密码交给客户。客户首次登录后应立即修改密码。平台用户不应把自己的管理员账号交给客户，也不应让客户直接使用 `/api/services` 这组内部委托接口。

### 2. 交付企业评测资产

在目标企业行点击“交付数据集”（也可从“企业空间与资产”进入），按名称选择启用企业和数据集。只有同时满足以下条件的数据集才可以交付：

- 数据集状态为已发布；
- 当前版本已经完成质检并为 `passed`；
- 当前版本存在至少一条可执行样本。

系统会把发布版本和样本复制到客户租户，并在审计日志中记录来源数据集、来源版本、目标企业和操作人。复制不会伪造质检结果，也不会把平台内部未发布数据暴露给客户。客户看到的是自己的共享副本。

### 3. 分配额度和价格

客户创建接入方后，运营在“企业与成员管理 → 目标企业 → 成员与记录 → 接入方与配额”按名称选择接入方，再设置：每日 Token 额度、每月 Token 额度、每分钟请求数和每千 Token 单价。新建接入方的额度默认为 0，在平台用户分配额度前不能提交有效评测。

额度单位是 Token；单价使用人民币“分 / 千 Token”。配置修改只影响后续调用，已有调用保存提交时的单价。额度不是充值余额，也不会自动发起支付、扣款或开票。

### 4. 准备模型服务

平台用户可选择两种方式：

1. 客户已经在平台共享了一个模型和冻结版本，平台用户在“模型服务与版本”中注册服务，并通过“关联已有版本”添加版本。
2. 允许客户自行填写上游接口。部署时先配置 `SERVICE_MODEL_HOSTS`，例如 `api.example.com,model.example.com`。页面注册接口时只接受白名单中的 HTTPS 443 地址；不允许 IP、非 443 端口、URL 用户名密码、查询串或片段。

注册接口后，系统创建模型记录和不可覆盖的访问配置快照。上游 API Key 只用于服务端请求，不会出现在模型列表、客户资产列表或服务发现响应中。平台用户应先确认域名归属、TLS 证书、出口网络和上游限流策略，再把域名加入白名单。

### 5. 配置稳定版本和灰度版本

打开服务卡片的“配置路由”，选择稳定版本；如需灰度，再选择不同的候选版本并设置 1–100 的灰度比例。灰度按“接入方 + 幂等键”稳定分桶，同一调用重试不会因为随机数改变版本。

灰度只改变新建评测任务的版本绑定，不会改变已经提交的任务。灰度发布也不等于质量门禁通过；平台用户仍要查看独立影子评测和真实证据。出现问题时点击“回滚”，系统会恢复上一稳定版本并关闭候选流量。

## 使用手册：外部客户如何操作

### 1. 登录和准备空间

客户使用平台运营提供的账号登录 `/services`。页面包含“需求与交付”“模型服务与版本”“接入方与用量账单”“企业空间与资产”四个区域。客户只能看到本企业的工作空间、成员、共享数据集、模型服务和调用记录。

客户可以在“企业空间与资产”中添加同企业成员。成员共享企业资产和服务调用记录；当前系统按企业租户隔离，不把同企业不同工作空间作为独立保密边界。

### 2. 创建接入方并保存 API Key

在“接入方与用量账单”点击“创建接入方”，填写接入方名称。系统只展示一次 API Key，格式类似 `evs_...`。关闭弹窗后平台无法恢复原始密钥，只能撤销旧接入方并创建新密钥。建议把密钥放在企业自己的密钥管理系统中，不要写入前端代码、日志、工单或浏览器截图。

客户可以查看前缀、有效状态、额度、使用量和计量金额，但不能自行修改额度、单价或频率限制。密钥撤销后，所有新网关请求会被拒绝；已提交的评测调用仍保留审计记录。

### 3. 注册服务和版本

如果平台已经交付模型服务，客户可以在“模型服务与版本”查看服务 ID、稳定版本和灰度比例。若拥有 `service:publish` 权限，客户可以注册自己的服务或接口版本；否则应让平台用户完成注册并授权共享模型。

注册接口时填写 OpenAI 兼容接口地址、上游模型标识和上游 API Key。接口必须符合平台白名单和 HTTPS 校验。提交后版本会被冻结，后续修改接口配置需要创建新版本，不能覆盖已有版本。

### 4. 提交自动化评测

在“需求与交付”点击“提交评测需求”，选择接入方、模型服务、共享数据集和 Token 预算，配置方式选择“自动化模式”，填写标题和定制化需求后提交。系统会检查：接入方有效、额度充足、服务有稳定版本、数据集属于本企业且已发布、请求预算合法。

通过检查后，调用进入排队状态并预占预算。页面会显示调用 ID、排队/运行/完成状态、进度、实际 Token、预占 Token 和报告状态。后台 worker 未启动时，调用会保持排队，不会伪装成已完成。

### 5. 提交专家评测

选择“专家模式”时，可填写场景、内置裁判工具和指标权重。提交后先产生草稿，不会自动执行；确认配置无误后点击“确认执行”。专家模式适用于定制化指标、特殊场景或需要人工复核的需求。

专家任务可以在开始执行前取消。取消后已经发生的真实调用仍会计量，未发生的预占不作为实际费用。客户不能通过请求体提交分数、影子观测或调度内部任务状态。

### 6. 查询调用和下载报告

调用完成后，只有正式任务生成了真实报告、不是 trial/simulation、且任务已经结束，页面才会开放“下载报告”。失败、排队、运行中和缺少报告文件时，下载会返回明确错误。

如果上游成功响应没有提供 Token 用量，调用会显示“待核量（unmeasured）”，系统保留预占，不会把未知用量当作 0 Token 或 0 元结算。平台用户核实上游计量后，再按实际流程处理。

## 外部 API 的完整调用方式

API Key 只用于 `/api/service-gateway/v1`，不能用于平台登录和其他后台接口。所有提交都必须携带唯一 `Idempotency-Key`；建议使用业务订单号或 UUID，并在同一业务重试中保持不变。

```bash
curl -X POST "https://platform.example.com/api/service-gateway/v1/evaluations" \
  -H "X-API-Key: evs_xxx" \
  -H "Idempotency-Key: customer-order-20261001-0001" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": 12,
    "route_id": 8,
    "title": "客服助手月度评测",
    "requirement": "验证共享客服数据集上的问答能力",
    "mode": "auto",
    "dataset_id": 30,
    "token_budget": 10000,
    "scene": "qa"
  }'
```

提交成功后，保存返回的 `id`。使用下面的接口轮询，建议间隔 5–15 秒：

```bash
curl "https://platform.example.com/api/service-gateway/v1/evaluations/123" \
  -H "X-API-Key: evs_xxx"

curl -L "https://platform.example.com/api/service-gateway/v1/evaluations/123/report" \
  -H "X-API-Key: evs_xxx" \
  -o evaluation-123.json
```

状态含义：`draft` 表示专家配置待确认，`queued` 表示已入队，`running` 表示执行中，`success` 表示完成，`partial_failed` 表示部分样本或裁判失败，`failed` 表示任务失败，`cancelled` 表示已取消，`paused_budget` 表示达到任务预算。`billing_status=settled` 才代表服务端已经取得可计量用量；`pending` 表示仍在执行，`unmeasured` 表示结果完成但 Token 数据不完整。

常见响应：401 表示 API Key 无效、撤销或主体已停用；403 表示权限不足；404 表示资源不属于当前企业或不存在；409 表示幂等键重复但请求内容不同，或版本/路由冲突；429 表示额度、每分钟频率或其他准入限制；409 报告错误表示任务尚未产生正式报告。

## 日常运营检查清单

平台用户每天检查新企业是否完成资产交付、接入方是否仍有额度、worker 是否正常运行、`unmeasured` 调用是否有待核对记录、灰度版本是否有真实证据，以及网关审计中是否出现异常 401/403/429。客户每天检查额度趋势、排队时间、失败率、待核量调用和报告下载是否完成。

遇到“没有可用数据集”，先确认数据集已交付到客户租户、状态为已发布、质检为 `passed`，并且当前版本有样本。遇到“没有稳定版本”，先在模型服务页添加服务版本并配置稳定路由。遇到“额度不足”，查看日额度、月额度和仍在途调用的预占；取消调用不会抹掉已经产生的真实用量。遇到“报告不存在”，确认任务已结束、worker 已运行、报告归档没有失败，并检查是否为 trial/simulation。
