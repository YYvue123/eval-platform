# 强制要求：删除 Mock，完成真实业务链路

用户最新要求（2026-09-28）：去掉所有 Mock 数据；所有真实流程不许使用 Mock。缺少信息可向用户索取，AI 可自行开发所需真实工具。本要求优先于历史交付报告及允许“演示模式”的旧建议。

## 1. 不可妥协的完成定义

所有用户可触达流程，包括开发环境页面、试跑、工具试用、MCP 探测、Agent、健康检查、评分、影子、榜单、报告、准入和演练，都必须来自实际执行。**trial 表示真实的小规模试运行，不再表示 Mock。** 不保留可切换的 Mock/演示 provider，不把演示模式藏到高级设置。

必须删除业务运行链中的假输出、固定评分、虚假 token/延迟、硬编码 pass/ok、默认答案代替候选、异常回退到内置假结果，以及启动时自动灌入的演示业务记录。配置缺失/真实调用失败应返回明确错误或 blocked/not_run，不返回成功占位。

真实本地算法和自行开发的工具允许使用：精确匹配、计算器、文件解析器、受限代码执行器、真实本地 MCP 服务等。它们必须实际计算/执行，返回真实结果与证据；“不用外部服务”不等于 Mock，“写了一个 MCP echo 服务”也不等于完成所有业务工具能力。

AI 可以产生候选题目/工具代码，但不能编造生产观测、专家签字、授权文件、用户事实和模型输出。AI 生成数据需明确来源并审核；不能将同一模型自答自评当独立金标。默认不自动填入业务样本；空库呈现真实空状态。

## 2. 按调用链清除，不做关键词式误删

| 位置 | 必须整改 |
|---|---|
| `model_client.py:invoke_model/health` | 无 api_url 不再返回 mock 文本或 ok=True；真实健康探测与真实调用分别记录 |
| `agent_runtime.py:create_run/step_once` 及 Agent API | 删除 mock provider 和 live→mock fallback；实现模型工具调用循环；usage 来自实际响应，未知明确标记 |
| `Agents.vue:startRuntime` | 删除写死 mock；选择真实已授权规划模型；缺配置引导补齐并禁止执行 |
| `Models.vue` | 删除“留空使用本地 Mock”；明确连接字段要求，空配置不可判健康 |
| `task_runner.py` | trial 同样禁止 mock；真实样本→模型→裁判→持久化→报告，不允许失败后拼假输出继续成功 |
| `database.py:seed_db`、`eval_packs.py`、fixtures 与初始化入口 | 盘点所有自动填充业务样本、知识、模型、任务和结果；停止演示业务 seed；保留经核实的权限定义/规则/真实工具元数据等必需系统配置 |
| `skill_runtime.py`、MCP client、builtin 工具、side_effect_policy | 禁止远程失败后伪本地成功；被禁止的副作用应 blocked/denied；真实隔离环境也必须实际执行，stub 返回不能算业务完成 |
| `scenario_simulators.py`、`media_adapter.py`、benchmark readiness | 缺候选不可用 reference 填充；代码真实隔离执行并验证测试；媒体实际解码并传入模型；缺执行器不可 ready |
| `EvalServices.vue`、`shadow_router.py`、服务 API | 删除前端常量分数，服务端真实双路观测；缺成对数据禁止以延迟代理通过 |

以上是已定位入口与必须扩展检查范围，不是穷尽清单。对 API→service→adapter→storage 全链路检查。重命名 mock 变量、把常数搬到 fixture、标记 simulation 后继续走流程，都不算整改。

## 3. 存量假数据的处理

先只读盘点：来源、数量、依赖、被哪些任务/报告/榜单引用。不能因数据“看起来像示例”就删除，也不能把 simulation 改为 false 洗白。

自动 seed 与 runtime fallback 从新业务链路移除。存量明确演示数据从活跃选择器、正式统计和任务引用中排除；提供限定对象的迁移/清理脚本，默认 dry-run，记录备份与影响明细后再执行。历史审计证据仍可保留为只读隔离历史，绝不能冒充当前真实结果。存在来源不明或混合真实数据时让用户确认精确范围，不做整库清空。

## 4. 缺少信息时向用户索取什么

先检查现有非敏感配置和可用能力，不在日志或文档打印密钥。不重新索取已有且有效的信息；把确实缺失的内容一次整理成阻塞表。

| 能力 | 所需信息/资源 | AI 可自行实现的部分 |
|---|---|---|
| 规划模型/被测模型/裁判 | endpoint、模型名、认证配置位置、工具调用/多模态支持、额度和使用上限 | 协议适配、Schema 校验、受控调用、重试与证据记录 |
| MCP | 实际服务地址、认证方式、允许工具与出口范围；或需要自建的具体能力 | 开发实际查询/解析/计算等 MCP 工具与服务、连接管理 |
| 数据集/金标 | 真实样本、来源许可、隐私要求、评分标准、专家审核安排 | 导入、版本化、格式校验和质量检测；候选数据须审核 |
| 代码评测 | 可用容器/沙箱环境、资源和网络限制 | 隔离执行器、测试报告采集与超时控制；不可用宿主裸 exec 代替 |
| 媒体评测 | 可合法使用的实际文件、模型模态能力和指标 | 真实解码/转码/输入适配与可重复校验 |
| 影子/演练 | 可隔离的真实服务版本、观测数据源、测试环境与准入条件 | 实际分流/隔离/观测/报告；不能创造生产历史 |

凭证通过本地安全配置或凭证管理注入，文档只记引用名称。未经明确额度限制不自动做大规模付费评测；缺少条件的项目精确标 blocked，同时继续可完成的工具开发与 UI 工作。

## 5. 验收门禁

1. 所有用户入口不存在 Mock 模式，也不存在空配置→假成功回退。缺配置真实失败且可修复。
2. 从真实样本发起任务，关联真实模型请求、实际裁判输入输出、工具调用、持久化结果与报告；每个步骤有可追溯 ID、版本和时间。
3. Agent 的工具调用来自真实模型响应，工具实际执行；无真实 usage 标未知，不能常量计数冒充消耗。
4. 工具/MCP 停机、密钥错误、拒绝权限、超时、非法参数都产生对应失败；不得自动返回 builtin 示例完成流程。
5. 代码候选确实执行测试、媒体确实解码并调用对应模型；金标不代替候选。
6. 影子统计只来自真实服务端观测；空观测、客户端伪造和仅时间经过均不可转正。
7. 准入/演练每一 pass 都有执行证据；人工签署由实际审核者提交。
8. 测试数据库隔离。单元测试可以使用明确的合成输入或故障注入验证边界，但这不属于真实业务数据，也不能代替真实流程验收；最终用户流程 E2E 不使用拦截响应/Mock provider 充当通过证据。真实外部条件缺失必须 blocked。
9. 缺陷和真实 E2E 证据与代码版本关联。继续执行原 AC01–46，不得把要求变成“演示可用”。

## 6. 给实施 AI 的优先指令

先完成 Mock 与假成功调用链清单、现有配置能力盘点和缺失信息表；立即修复无配置也成功、伪造观测和无证据 pass。然后实现真实 provider/工具/数据/执行器闭环，再按全站交互指南完成全部页面。缺信息时提出具体问题，不能以 Mock 绕过。最终汇报必须同时给出“移除了什么假实现”和“真实替代链路的执行证据”。
