# FlagEval 与本项目模型榜单功能对比

调研日期：2026-10-24。参考站点采用浏览器实际访问、点击筛选与菜单；本项目以当前工作区源码为依据，未运行本地页面或业务数据库验证。本文不代表测试验收结论。

## 结论

可以实现类似的数据维度组织和图表展示，现有 Vue、Element Plus、ECharts、FastAPI 和结果明细可以复用。主要缺口是按评测体系组织的多维分数矩阵、可追溯的版本化汇总，以及竞技场真实对战数据。页面样式可以先完成，但有列、有图不能代替真实测量。

## FlagEval 功能清单

### 榜单门户与公共交互

总览展示模型累计数量、开闭源数量、评测期数、榜单访问统计和分类排名预览。语言与多模态具有不同入口，专项包括 K12、金融、安全和角斗场。详细榜单具有榜单切换菜单；多个榜单支持全部/开源/闭源筛选及评测期数。模型行显示机构、版本或参数规模，部分模型有推理模型标签。

### 数据维度

| 榜单 | 实际看到的数据维度 |
| --- | --- |
| 对话能力 | 综合评分、除内容安全综合评分、学科知识、任务解决、事实性、多轮对话、算法编程、内容安全 |
| 视觉语言 | 综合、图形解谜、空间推理、长尾识别、多图分析、图表理解、地理推理、场景理解、学科知识、中英文文字理解 |
| 文生图 | 主观综合、中英文主观分、中英文一致性、中英文图片质量、分辨率；方法说明另含美学和安全维度 |
| 文生视频 | 总分、图文一致性、真实性、视频质量、美学质量、长度、分辨率 |
| 语音 | 总分、音频感知、语音感知、语音生成、口语理解 |
| K12 | 模型类型、学科、年级、卷面/能力分数、学习理解/应用实践/迁移创新；卷面视图有学生平均水平参照行 |
| 金融量化 | 问答得分、交易策略跑通率/夏普指数、指标计算跑通率/准确率、计算性能跑通率/运行时间 |
| 安全价值观 | 总合格率、主客观题合格率、总拒答率及五类安全维度 |
| 实时语言榜 | Average、C-ARC、C-HellaSwag、C-TruthfulQA、C-Winogrande、C-GSM8K、C-SEM、C-MMLU、CLCC-H，以及更新时间 |
| 角斗场 | 模型等级、评分排名、竞技场评分、95%置信区间、有效投票数、更新时间；平均胜率、两两胜率矩阵、对战场次矩阵 |

### 展示方式与规则

普通能力榜主要是宽表、条纹行、模型标签、多指标并列和说明区；不能把它描述为所有页面都有丰富图表。角斗场包含评分统计图、胜率分析、热力矩阵等。已直接截图确认胜率矩阵的蓝青配色、格内数字和色标。

不同榜单采用不同计分尺度和汇总规则：视频显示 0–1 范围的数值；语言能力显示百分制；语音说明四种能力按 4:3:2:1 汇总；视觉语言说明依据能力维度平均排名确定最终排名。因此实现时需区分展示分、排序分和排序规则。

角斗场算法说明使用修改后的加权 Bradley–Terry 模型，胜负强度区分“稍好”“远好”；置信区间来自自举采样分布；模型等级与分数排名分开。页面关于低投票数量排除的文字与部分表格记录存在不一致，不宜直接照搬其阈值说明作为我们的验收规范。

## 本项目当前能力

源码：frontend/src/views/Leaderboard.vue、backend/app/services/leaderboard.py、backend/app/api/tasks.py。

- 页面有综合、单项、专项、性价比四类入口，以及比较组、行业、场景筛选。
- 有前三名卡片、排名表、平均分、归一化分、通过率、来源任务；性价比榜显示成本。
- 支持选择 2–5 个模型进行场景雷达对比；有成本单价编辑和 CSV 导出。
- 后端实现比较组、试跑/模拟排除、部分评分错误检查、并列排名、快照、冻结尺度、发布和回滚。
- 趋势接口只返回最近快照的榜首模型和分数，前端榜单页未接入；发布回滚接口也未在该页提供操作入口。
- 模型资料已具备模态、参数规模、版本、机构等部分字段；结果明细有 metrics_json 与 latency_ms，可以作为扩展基础，不等于已经具有完整能力分数。

| 方面 | FlagEval | 本项目 | 判断 |

| 模型属性 | 机构、开闭源、版本、参数、推理标签 | 榜单只展示名称等少量字段 | 关联已有元数据并补字段语义 |

## 扩展前应修复的问题

以下为源码分析，未在运行环境复现：

1. 雷达图把 null 转 0，与页面“缺指标不补 0”冲突；应使用缺测标识、共同维度或其他不伪造零分的表达。
2. 雷达请求只传 model_ids，后端按模型与场景取最新成功任务，没有沿用当前比较组，也未调用主榜的评分错误检查，可能混用评测条件。
3. 主榜在部分路径先按模型取最新任务，再筛比较组，会遗漏同一模型在目标组内较早的有效结果；应先限定比较条件再选各模型版本的有效结果。
4. 综合榜未指定行业的分支没有使用 scene 参数筛选，可能与页面场景选择不一致。
5. CSV 前后端未传递/接收 cohort_id，导出结果可能与当前所选组不一致。
6. 性价比成本时延为 max(total,1) × 0.2 秒，未使用真实结果时延；缺单价还采用默认价格，不能称为实测成本榜。
7. 雷达固定最大值为 1，只配两种颜色；扩展不同尺度和五模型对比时需按指标配置范围与颜色。
8. 单项榜目前使用任务 avg_score 且截取前十；它不是可选任意能力指标的排行榜。专项无目标类型结果时会回退普通任务，需明确展示口径。

## 可实施路径

### 第一阶段：可信基础和页面能力

修复比较组、雷达缺值、导出条件和真实成本；将模型版本作为排名实体的一部分。增加门户统计、模型属性、排序、筛选、历史发布入口、方法说明。复用 ECharts 增加横向条形图、能力雷达和能力热力图；没有实测数据的列保持缺测状态。

### 第二阶段：多维指标榜单

建立版本化评测套件与指标目录。每个指标定义名称、单位、尺度、越大/越小越好、汇总方式、权重、缺测策略、样本门槛与展示格式。将明细结果按模型版本、评测发布、比较条件、数据集、能力、行业、场景汇总，保留任务和样本证据来源。

不能把场景简单重命名为“事实性”“算法编程”来假装已有对应能力数据。K12 需要学科、年级、能力题目标签与学生基线；多模态需要可用的评测输入、推理适配、评分器，人工质量评分还需标注流程。只有正式真实评测或合规且明确标注来源的结果才能进入相应榜单。

### 第三阶段：竞技场

建设模型两两对战、题目与模态、匿名左右顺序、胜负/平局/偏好强度、投票去重和质量审核。再实现版本化 Bradley–Terry 拟合、自举置信区间、有效样本门槛，输出分数区间图、平均胜率、两两胜率热力图、对战次数热力图。现有平均分不能替代这些输入。

新增页面、按钮、接口时同步完成 AGENTS.md 规定的权限、角色分配与权限收集；评分事实通过受控工具/TaskService 产生，测试使用隔离环境。
