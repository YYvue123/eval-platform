# 全站 UI 与交互优化实施指导

用户最新硬要求：[所有业务流程删除 Mock，完成真实实现](../delivery/NO-MOCK-REAL-IMPLEMENTATION.md)。本指南禁止以演示模式代替真实能力；trial/工具试用也必须真实执行。历史 simulation 标签只用于识别并排除旧数据。

## 1. 产品目标与实施边界

让首次使用平台的评测人员能理解“我现在处于哪一步、下一步做什么、为什么被阻止、完成后去哪里看结果”。主要路径不要求记资源 ID、编写 Manifest、理解 checkpoint/egress 等实现名词。高级用户仍可展开原始请求、Schema、trace 和版本信息。

继续使用 Vue 3、Element Plus、Pinia、Vue Router、现有 API 封装。避免换框架、大型低代码设计器、全量重写和无必要依赖。不得覆盖其他模型未提交的工作。任何后端新增能力先列契约和权限，再实现界面；尚未实现的能力显示未支持，不做可点击假按钮。

角色：评测人员关注创建、执行和解释结果；资源管理员关注接入、测试、版本和健康；审核者关注证据与风险；运维关注真实故障和恢复。默认界面按当前任务渐进呈现高级细节。

## 2. 信息架构

保留现有 URL 和权限语义，优先在原页面拆分组件、Tab 与可分享查询参数，减少迁移成本：

| 导航组 | 页面 | 用户目标 |
|---|---|---|
| 工作台 | Dashboard、Agents | 看待办，提出目标，恢复最近评测 |
| 评测执行 | Tasks、TaskDetail、TaskTemplates、Benchmarks、Safety | 选择方案，执行，复核证据 |
| 评测资产 | Datasets、DatasetDetail、Quality、Models、Prompts | 准备可用且可追溯的版本 |
| 工具中心 | Resources 中的全部资源/工具/Skills/MCP 连接 | 接入、发现、试用、诊断资源 |
| 结果与交付 | Leaderboard、EvalServices | 比较可信结果、交付服务 |
| 管理与运维 | Ops、Users、RolePermission、AuditLog、NotificationManage、ApiDocs | 运维、授权、查证 |
| 个人与系统 | Profile、Login、NotFound | 身份与基础导航 |

不要为了拆“工具/MCP/底座”复制三套注册和调用实现。建议 `/resources?tab=tools|skills|mcp|all&resource=...`；Agent 使用 `/agents?session=...`。这是建议契约，不是现存接口。刷新/后退保留选中对象与筛选；非法或无权访问的查询参数明确提示并安全返回列表。

数据批次冻结入口迁至任务创建或数据集详情；工具中心旧入口可保留跳转，避免打断熟悉旧版的用户。

## 3. 全站视觉与交互规范

采用克制的专业评测工作台：强调清晰的数据层级和操作状态，减少装饰。统一浅色纸白/石板灰背景、深色文字、单一靛蓝主色，语义色只表达成功、提醒、失败。沿用并补全 `styles/variables.css`，统一覆盖 Element Plus 与自定义组件；暗色逐页验证，不通过局部硬编码白底实现。

| 项目 | 实施要求 |
|---|---|
| 排版 | 标题 22–24px、区块 16px、正文 14px、辅助 12–13px；中文字体优先本地可用，数字对齐，技术信息使用等宽字体；不依赖 Google Fonts 外链才能正常显示 |
| 间距 | 4/8/12/16/24/32px；同级信息用一致间距；页面外边距桌面 24、窄屏 16 |
| 层级 | 页面标题 + 一句任务说明 + 一个主要动作；其余动作降为次要/更多；不堆四张无意义统计卡 |
| 表格 | 名称可进入详情，状态中文标签，长内容可展开/复制；每行常驻不超过两个动作，其余进入更多；筛选与服务端分页联动，删除末条后校正页码 |
| 表单 | 永久 label、必填标记、字段校验、示例和必要提示；错误定位到字段；请求失败保留已填内容；不把 placeholder 当唯一标签 |
| 弹窗/抽屉 | 复杂详情用抽屉/专页，短操作用弹窗；最大宽度受视口限制；长表单底部主操作可达；Esc 关闭，关闭后焦点返回触发元素 |
| 动效 | 150–200ms 的状态/面板过渡；尊重 reduced-motion；不采用全屏炫光、频繁闪烁或影响阅读的入场动画 |
| 可访问性 | 键盘走完整主流程、可见焦点、图标按钮有名称；错误不只靠颜色；正文对比度目标 4.5:1；图表有文字摘要；移动触控目标建议至少 44px |
| 响应式 | 1440 主布局，1024 折叠次要区，390 单列/抽屉；表格局部横滚，整页不横向溢出 |

通用六态：首次加载、空数据、筛选无匹配、局部失败、无权限、正常数据。后台刷新保留旧数据并显示更新时间，不闪空表。每个失败态都给出原因和可行下一步；404 不伪装空数据，403 不跳转到同样无权的页面。

状态不可混用：`unknown`=未知，`not_run`=未执行，`simulation`=演示，`inconclusive`=证据不足，`failed`=失败，`cancel_requested` 或等价后端状态=取消中。null 指标显示“未测/—”，真实 0 显示 0。健康未知不能变绿，任务结束不能等同于评测通过。

错误提示用“发生了什么 + 能做什么 + 可展开的错误码/trace”。请求层和页面层只由一个地方弹 Toast；422 字段错误留在表单；轮询错误显示连接条，不每两秒弹窗。429 根据服务端策略退避，401 保留安全的返回地址，403 展示无权限说明。

危险或有成本的操作需要应用内确认摘要：资源、版本、范围、是否真实执行、预算与不可逆影响。普通查询/筛选无需确认。提交中禁止重复提交；失败后可重试同一意图，不自动重复有副作用的调用。

## 4. Agent：从调试台改成评测助手

### 4.1 布局

桌面采用会话列表（约 260px）+ 主工作区（弹性）+ 按需展开的计划/证据抽屉。1024 时收起会话侧栏，390 时单列，计划在独立抽屉中查看。

主区：会话标题、模式徽标、状态与预算 → 需求/澄清消息 → 计划卡 → 执行时间线 → 结果卡。知识候选审核、运行内部参数归入独立 Tab/高级面板，不挤在首次进入界面。

无会话时显示“描述你想完成的评测”和真实资源准备状态；不自动填充假会话或业务结果。显示“真实模型未配置”及有权限的配置入口，配置完成前不可执行，不提供演示模式。

### 4.2 状态与主动作

下表是产品态，应映射后端现有状态；不能只在前端虚构状态推进。

| 产品态 | 主要内容 | 唯一主动作 | 辅助动作 |
|---|---|---|---|
| 尚未开始 | 目标输入、示例、模式 | 生成计划 | 高级预算设置 |
| 正在规划 | 可见进度、耗时、可取消 | 无/取消 | 查看已有事件 |
| 待补充 | 自然语言问题与对应字段 | 补充并更新计划 | 保留草稿 |
| 待审批 | 计划摘要、资源版本、预算、风险 | 审批计划（有权者） | 修改计划 |
| 已审批 | 有效期与绑定版本 | 确认并执行 | 查看审批记录 |
| 执行中 | 当前步骤、已完成数、费用/用量 | 查看任务 | 取消执行 |
| 预算暂停 | 消耗、限制、暂停原因 | 有权限且后端支持时申请/调整额度 | 取消/导出诊断 |
| 执行失败 | 失败阶段、影响范围、恢复条件 | 安全恢复（可恢复时） | 查看证据/重新规划 |
| 已完成 | 结论、证据、试跑/正式标签 | 查看报告 | 基于此计划新建 |

“签发审批”和“执行”可以是连续步骤，不能为了少点一次绕过审批。需要第二个审核者时显示等待审核，不自动代签。

### 4.3 表单和证据

数据集/模型使用有搜索和分页的选择器，展示名称、版本、可用性；后台继续传 ID。不能读取其他租户资源，未发布/不可调用资源解释为什么不能选。切换数据集后清空不匹配版本。预算显示单位、是否有限额；0 的语义来自后端，不擅自显示为无限。

澄清按本次缺失项动态生成，不常驻所有字段。需求和 objective 尽量合并成一个用户目标；高级模式才允许补充结构化目标。资源缺口提供对应的配置入口，再返回原会话。

计划卡显示目标、数据样本范围、模型和工具版本、试跑/正式、预计步骤和预算；hash 折叠在技术详情。修改后对比差异并明确旧审批失效。

时间线显示“正在检索可用资源/等待确认/执行第 n 个步骤”，工具详情可展开输入、输出摘要、耗时、状态与 trace；敏感字段脱敏。展示实际执行事件，不展示或编造隐藏思维链。子任务按父子关系呈现，结果引用可跳转到有权限的证据。

会话切换必须先隔离状态再请求，慢网响应不能覆盖别的会话；事件增量去重、有界展示、可加载历史；断线可重连。所有操作状态由后端返回驱动。

## 5. 工具中心、MCP 与工具底座

### 5.1 资源目录和详情

顶栏“添加资源”，下方全部/工具/Skills/MCP 连接 Tab，名称搜索、类型/状态/来源筛选、分页与总数。名称是首列，说明、来源、版本、健康状态、最近探测时间是辅助信息。调用统计没有真实来源时不展示假成功率。

详情包含概览、输入输出、版本、试用、调用记录。接口缺少版本列表/调用记录时先补受控 API 或明确未支持，不能拿静态数组充数。内置资源标记只读；新版本与现有任务冻结版本区分，更新前解释影响范围。

### 5.2 新增资源向导

1. 选择工具 / Skill / MCP，介绍适用场景与当前支持范围。
2. 填名称、说明、版本、调用方式；选择凭证引用；连接地址和白名单用人能理解的标签。
3. 配置参数：常见 string/number/boolean/enum/array/object 字段用 Schema 表单；复杂结构可切高级 JSON；切换模式不能丢字段。
4. 校验与测试：分别展示结构合法、连接成功、实际调用通过，未执行的检查保持灰色。
5. 确认注册：摘要显示权限、副作用、实际连接与版本影响；完成后进入详情并提供“试用/用于任务”。

保留“导入 Manifest”专业入口，附可用模板、格式化和错误位置。不要在客户端保存原文密钥到 localStorage、URL、草稿或日志；凭证展示“已配置/需重新输入”，关闭临时连接面板清除临时 token。

### 5.3 工具试用台

左侧真实参数输入表单，右侧结果摘要、输出结构、耗时、错误码、trace。Schema 校验失败不发请求；试用必须实际调用工具，真实副作用给出确认范围。可在受限测试环境实际执行，但不得用 stub 假结果。超时结果显示“结果未知”并允许查询 invocation 状态，不无条件重发。

响应应用层 failed/error 必须显示失败；HTTP 成功仅意味着请求返回。保留原始 JSON 的复制/下载高级功能并脱敏，不能只弹一次 Toast 然后丢掉结果。

### 5.4 MCP 连接工作台

流程：选择已注册连接或输入临时地址 → 验证连接 → 获取工具目录 → 选择工具 → 填参数 → 测试 → 保存为可复用资源（有权限且后端支持时）。

连接摘要显示实际 endpoint、支持传输、认证是否配置、连接状态和最后检测时间；无法识别的传输禁用并解释。端点与注册资源必须互斥。连接成功、工具目录已发现、某工具调用成功是三个独立状态。

工具目录展示名称、描述、输入 Schema 与实际声明能力。工具更新后说明变化和运行中版本，后端未实现 generation/list_changed 时显示未支持，不能假装自动热更新。错误分连接不可达、认证失败、服务端错误、非法参数、工具执行失败，分别给出建议。

禁止浏览器直接跨域连接 MCP 或绕过平台网关；服务端落实出口、凭证和工具权限。仅发现工具不代表有执行权限。

### 5.5 Skill 工作流

先提供顺序步骤编辑器：添加已授权工具、配置参数、从前序输出选择引用、验证并试跑；无需第一期实现拖拽画布。引用显示人类可读路径，高级视图显示 `$ref`；防前向/循环引用；失败步骤可展开原因。仅暴露服务端已支持类型，code/agent 等未实现类型不可保存成可执行资源。

## 6. 全部 24 个页面的整改目标

以下是覆盖清单，其中非重点页面是本次后续改造要求，不一概断言现有功能全部缺失。每页实施前读取现有实现，保留已经满足的部分。

| 文件 | 改造目标 | 该页最低验收 |
|---|---|---|
| Agents.vue | 按第 4 节构建目标→澄清→审批→执行→结果 | 新手无需 ID 完成真实流程；切会话不串状态；无 Mock 回退 |
| Resources.vue | 按第 5 节区分资源目录/工具/Skill/MCP | 三类接入可操作，错误可修复，第 101 条可访问 |
| Dashboard.vue | 以待处理审批、进行中任务、异常、最近结果组织工作台；按角色呈现快捷入口 | 数字可下钻到同筛选列表；无权限不出现写入口；无数据有起步动作 |
| Datasets.vue | 保留搜索/分页，补清晰版本/质量/发布状态，创建后导入引导；规范任务类型和领域选择 | 创建→导入→检测→发布可顺序完成，失败保留数据 |
| DatasetDetail.vue | 概览/样本/版本/质量/历史分区；字段映射预览与错误行反馈；版本差异和回滚摘要 | 切版本不混样本；重复导入行为明确；发布/回滚后状态一致 |
| Quality.vue | 问题严重度、原样本与修改后对比、修复预览、复检结果；替换裸 dataset_id | 处理动作有理由/影响范围；修复后能追到新版本与复检 |
| Models.vue | 基本信息/连接/版本/权限分层，删除 Mock 接入；模型 ACL 用人员选择器；连接测试持久结果面板 | 错密钥可恢复；留空是否保留密钥清晰；无有效连接不可执行 |
| Prompts.vue | 模板变量即时检查与渲染预览；版本 diff；实验独立面板展示基线/候选/保留集结果 | 缺变量提示；无收益不推荐发布；保留答案不暴露给优化流程 |
| Tasks.vue | 搜索筛选分页；创建向导：类型→资源版本→参数预算→确认；依赖任务可搜索 | 超过 50 条可翻页；草稿/试跑/正式可辨；动作按状态可用 |
| TaskDetail.vue | 顶部状态与进度，失败样本/评分/费用/制品分区；取消中与重试范围明确 | null≠0；评分失败不显示正常成功；报告生成失败可单独重试 |
| TaskTemplates.vue | 按用途搜索、展示适用场景与 readiness；选模板后显示将预填什么 | 未就绪模板不可正式执行；返回列表保留筛选 |
| Benchmarks.vue | 金标样本结构化预览、媒体预览、能力与证据状态；模拟器和正式基准分区 | 缺候选不可默认参考解跑出正式通过率；ready 说明适用范围 |
| Safety.vue | 争议队列→证据详情→人工标签与理由→复核历史；试评可输入实际候选 | 可驳回/需补证；固定集与探索集清楚隔离 |
| Leaderboard.vue | 保留 cohort/frozen scale 的正确语义，统一主题；补筛选解释和可比性说明、无数据态 | 缺指标不补 0；模拟结果不混正式榜；离线字体回退正常 |
| EvalServices.vue | 服务生命周期分步办理；常驻两个动作以内；报价、交付、影子证据分别进详情 | 不提交硬编码分数；条件不足不可转正；交付关联真实报告 |
| Ops.vue | 健康摘要+告警待办，准入/恢复/演练独立流程；危险操作确认和执行日志 | 无证据演练不 pass；故障注入环境/范围醒目；准入未测不变绿 |
| Users.vue | 账户状态、角色、范围、查询；敏感操作呈现目标账户和影响 | 无权操作不可提交；禁用/重置反馈明确；分页筛选不丢 |
| RolePermission.vue | 角色搜索、分组权限、权限搜索、变更 diff、未保存提醒；数据范围独立说明 | 保存后菜单/路由/按钮/API 一致；不可绕过自身授权边界 |
| AuditLog.vue | 行为中文化、结果/时间/操作者筛选，详情显示对象与 trace，支持关联跳转 | 分页与筛选正确；敏感信息脱敏；不以失败查询显示无记录 |
| NotificationManage.vue | 发送范围摘要、预览和发送中锁；保留现有筛选分页 | 全体/指定用户范围不混淆；失败保留内容，成功可定位记录 |
| ApiDocs.vue | 说明面向开发者，加载失败/重新加载/在新窗口打开，暗色适配 | Swagger 加载失败有解释；不自动把密钥注入非信任来源 |
| Profile.vue | 基本资料、头像、密码独立保存，清楚成功状态和校验 | 错误不清空整个表单；密码不回显；键盘可操作 |
| Login.vue | 清楚的输入校验、密码显示、加载、过期提示与安全回跳 | Enter 提交一次；错误定位；登录后回到可访问页面 |
| NotFound.vue | 提供返回上一页/可访问工作台；无权访问使用不同说明 | 不落入重定向循环；首次直接访问未知 URL 可恢复 |

公共框架同时检查 MainLayout、menu、router、NotificationCenter、EmptyState、ActiveFilterHint、request。无权限访问 dashboard 时不能继续强制跳 dashboard；选首个有权路由或显示无可访问模块页，加载权限完成前避免错误重定向。

## 7. 组件拆分与接口落地

建议逐步复用：PageHeader、StatusBadge、AsyncState、SearchToolbar、ResourcePicker、SchemaForm、ExecutionTimeline、ResultPanel、ConfirmAction。先在 Agent/Resources 两页验证，再推广；别先造一套庞大组件框架。保持领域状态逻辑靠近领域组件。

实现前建立接口盘点表，分“已存在/需扩展/新增”，明确请求、响应、空值、分页、错误、权限与对象范围：

| 用户能力 | 当前线索 | 需核查/补齐 |
|---|---|---|
| 资源目录 | resources.list 已支持 search/status/page | 前端分页筛选接通，返回 manifest 脱敏与对象范围 |
| 资源接入 | register 接收 Manifest | 表单生成合法 Manifest；版本冲突/内置只读/校验与健康区分 |
| 工具试用 | invoke + 网关信封 | Schema 来源、业务状态映射、调用证据、稳定重试键 |
| MCP 探测 | mcpProbe | 来源互斥、真实 endpoint 回显、发现工具与调用能力矩阵 |
| Agent 流程 | sessions/clarify/approve/confirm/runs/events | live 能力、可用动作原因、真实 usage、审批有效状态 |
| 批次 | batch.run/status/cancel | 数据集版本选择器、恢复查询入口、真实取消状态 |
| 影子观察 | shadow/promote | 改为服务端观测链，前端只传配置或受控引用 |
| 演练 | createDrill | 草稿/未验证与正式签署区分，证据校验 |

对象权限是服务端职责，不能靠过滤前端列表实现。新增页面/按钮/API 的同一变更必须完成 AGENTS.md：v-if/v-permission、meta.permission、require_permission、permissions.json、ACTION_NAMES（新动作时）、RESEARCHER/VIEWER 权限和 `npm run collect-permissions`。不要为所有新功能直接授予 viewer 写权限；复用权限前确认实际业务一致。

## 9. 必须执行的交互验收

后端测试必须先显式配置独立数据库、上传、日志、备份目录，再导入 app；使用 `tests/isolated_env.py` 或等价隔离入口，并检查最终解析路径。该文件使用 setdefault，继承环境若指向业务库不能被它自动修正。绝不使用业务 eval_platform.db。浏览器端到端也只能连隔离后端，不在真实业务环境批量造数据或做故障注入。

| 编号 | 场景与断言 |
|---|---|
| UX01 | 首次用户用名称搜索资源、补齐澄清、审批和执行；全程不需要输入内部 ID/Manifest |
| UX02 | 切换有 run 的 A 到空 B，刻意让 A 响应晚到；B 无 A 的状态/按钮目标 |
| UX03 | 审批过期、修改计划、重复执行与断响应重试；只有一次服务端副作用 |
| UX04 | 断网/429/500/慢网大于轮询周期；不刷屏、不并发堆积、可重连、事件无重复 |
| UX05 | MCP 临时地址与已注册模式互斥；拦截请求证明实际访问正确目标 |
| UX06 | 注册错误 JSON/Schema；局部错误可见，输入保留；合法表单和 JSON 模式无字段丢失 |
| UX07 | 工具 HTTP 200 但业务 failed；显示失败与原因，无绿色成功 Toast |
| UX08 | 三种不同 Schema 的工具可试用；副作用模式明确；超时结果未知不会自动重发 |
| UX09 | 资源超过 100、任务超过 50；分页、筛选、刷新/返回保持状态 |
| UX10 | admin/researcher/viewer 及 A/B 租户，菜单、路由、按钮、直接 API 四层验证 |
| UX11 | 影子证据不足/客户端伪造、演练无证据、缺候选代码、未解码媒体，不产生正式 pass |
| UX12 | 安全复核查看证据→拒绝/补证/给出标签和理由；持久化且可审计 |
| UX13 | 每个页面：加载/空/筛选空/失败/无权限/正常；null 与 0 显示不同 |
| UX14 | 24 页在 1440/1024/390 和明暗主题记录；重点表单键盘走通、焦点正确、主操作可达 |
| UX15 | 凭证不出现在 URL、浏览器存储、列表响应、截图与导出日志中 |
| UX16 | 真实模型 Agent 工具循环和远程 MCP 分别留完整 trace；缺外部条件写 blocked，禁止用模拟 E2E 关闭真实流程验收 |

新增组件/状态机测试与浏览器关键流程测试应针对实际风险，不写只镜像实现的断言。现有 package.json 只有构建和权限采集，需明确补充可运行交互测试入口。`npm run build` 只证明可构建，不能代替 UX01–16。

交付目录建议 `docs/delivery/frontend-ux/`：页面覆盖矩阵、缺陷关闭表、测试命令与日志、关键页面改前/改后截图、真实链路 trace（脱敏）。每条证据包含代码版本或工作区文件 hash、环境、角色、视口、输入、预期、实际、pass/fail/blocked/not_run。尚未执行的格子不得默认打勾。

最终用户验收建议：让一位不了解项目实现的人在不接受开发者口头指导的情况下，完成一次 Agent 发起评测、一次工具接入、一次 MCP 连接和失败修复。记录卡点再改；时间目标可作为改善指标，未经实际观察不宣称“效率提升”。
