# 验收与发布门禁

## 1 验证层级

L0静态与契约：Schema、类型、权限路由、迁移检查。L1单元：纯函数/状态机/幂等。L2集成：独立PostgreSQL/Redis/对象存储、可控HTTP/MCP服务、两个worker。L3真实联调：真实规划模型、裁判、企业模型和证书、真实媒体与金标。L4生产演练：压测、故障恢复、灰度与回滚。L0/L1通过不能代替L3/L4。

本次已完成：70个应用Python文件AST解析，前端Vite构建，独立裁判/信封探针，5份Schema和2份样例验证。恢复隔离Python环境并补greenlet后，11项基础/接口测试通过；端到端任务测试45秒超时，任务模板队列测试未完成验证。环境与日志见verification/TEST-RESULTS.md。本文件的46项新验收场景是目标计划，不因此标记已通过。后续CI固定测试数据和隔离数据库，不读取或写入backend/eval_platform.db。

## 3 Agent效果评估

按03定义的200唯一场景与三次重复，划分开发/保留集。Agent金标是合法计划/最终业务状态/授权约束，不是固定自然语言答案。判分由确定性校验、工具/环境oracle和盲审组合。报告合法计划≥95%、可执行目标达成≥90%、澄清召回≥90%、内部恢复无重复副作用100%、数值与引用准确100%，另给各子类指标和95%区间。

安全门禁按有限测试集零容忍：未授权副作用、跨租户泄漏、审批绕过均必须0；不能把测试中0次解释为对所有输入绝对安全。增加恶意工具输出、文档提示注入、编码绕过、旧审批重放、并发审批、权限运行中撤销用例。所有回归用例固定，不能只保留有利prompt。

成本和性能对照规则基线、单Agent、按需多Agent，同模型/同目标/同工具与上限，统计完成率、质量、P50/P95耗时、费用、重复工具率。多Agent启用条件是复杂子集有预先定义的效益且成本可接受；若无收益，保留单Agent默认，修分工而不是盲目增Agent数。

## 4 性能目标与测试口径

原文硬目标保留：D P2832榜单1000在线用户、查询3秒内；D P2911同时100任务、队列容量1000、网关500请求/秒、审计丢失率≤0.1%；I15规定的准入时延等见04。原文“单任务队列容量1000”有口径歧义，本设计暂定义每调度队列1000待执行项，需业务确认，不偷偷改成已满足。

测试报告必须记录机器CPU/内存、实例数、数据库规格、网络、数据量、缓存冷/热、样本长度、模型响应延迟/限流。无目标生产硬件时先容量曲线，不给虚假达标结论。

| 测试 | 建议负载口径 | 门禁 |
|---|---|---|
| 榜单 | 1000在线虚拟用户，思考间隔5—15秒，读多种cohort，持续30分钟 | 保留原文3秒目标，同时报告P50/P95/P99/最大值及超限请求比例；任何例外需批准 |
| 网关 | 控制端与可控回显上游500RPS，30分钟；另单独真实模型负载 | 在声明限额内稳定，无绕过授权；超限429；不能用回显吞吐证明LLM推理吞吐 |
| 调度 | 100同时运行任务，每任务1000样本，分层模型限流，至少2worker | 无重复有效结果/孤儿任务，公平排队，预算和取消有效 |
| 队列 | 1000待执行项后继续提交 | 明确backpressure/429/排队策略，无静默丢任务 |
| 审计 | 记录预期event_id集合，对比持久记录与导出 | 普通审计丢失≤0.1%；审批/计费/权限变更审计设计目标0丢失 |
| Agent流 | 100并发会话，其中10规划、其余等待/订阅 | 连接不绑worker，预算受控，首状态事件P95≤2秒为建议目标，不要求LLM首token2秒 |
| 恢复 | kill worker/API、DB短断连、对象写失败 | 已提交结果不丢，幂等有效；默认≤120秒回收失联worker为建议目标 |

D P2946/P2984的“毫秒级告警、数十节点部署、效率提升90%”需要明确定义起止点与人工基线，不能把采样间隔当告警端到端时延。记录为生产专项验收，不在没有规模环境时判通过。数据库读写分离、集群注册中心与消息队列解耦也需部署配置/故障测试佐证；初期DB outbox轮询不等于已完成独立消息中间件集群。

## 5 发布和迁移门禁

1. P0正确性/权限/审批/隔离用例全过，无未处置高危问题。
2. 全量Schema/契约回归与现有业务回归通过；前端权限收集差异人工审查。
3. 数据迁移先expand再backfill再validate，最后contract；历史无法验证结果保留legacy_unverified。
4. 真实LLM/企业模型/MCP/媒体每类至少一个完整链路，明确未接入场景不发布ready。
5. 基准人工校准、许可和指标定义审核完成；统计与报告可复算。
6. 备份恢复、取消、预算、崩溃恢复、灰度回滚实测；审计包含who/what/when/tenant/trace/outcome。
7. 准入报告关联版本和制品hash；任何升级模型/prompt/judge/tool必须跑对应回归，不继承旧版通过状态。

## 6 验收记录模板

每条记录包含case_id、需求ID、工作包、代码commit、环境版本、fixture hash、执行时间、输入摘要、预期、实际、断言、日志/trace/artifact链接、pass/fail/blocked/not_run、审核人。blocked/not_run不能算通过率分母中的通过。失败复测保留原记录并关联新attempt。

最终签署分产品功能、数据/标尺质量、工程可靠性、信息安全、运维交付五类负责人；AI输出作为研发证据，不替代领域专家、数据授权方和生产负责人决定。
