## 结论

当前系统是具备较完整管理页面和单机业务骨架的原型，已有数据、模型、提示词、质量规则、任务、资源、榜单、服务单、RBAC 和审计等可复用实现。但它尚不能按两份原始文档作为完整平台验收：真正的模型驱动 Agent、多智能体协作、可靠任务执行、完整标准协议、可信评测基准、租户隔离和生产运维仍有实质缺口。若只继续补页面，会掩盖评分和执行链路的问题。

建议顺序：**先恢复结果可信性与权限边界，再建设标准工具网关和可恢复执行，随后交付真正的 Agent，最后扩展场景基准与生产交付。** 本次不修改业务代码，交付的是可执行的设计与研发工作包。

## 已确定的设计边界

- 保留 Vue 3、FastAPI、SQLAlchemy，采用渐进重构；生产建议 PostgreSQL、独立 worker、Redis 共享限流和对象存储。SQLite 只保留开发与轻量演示。
- 被测模型、平台规划模型、裁判模型是三种职责，配置、凭证和预算分别管理；不建设训练或 GPU 模型托管平台。
- 企业模型默认远程加密访问。Eval Kit 属历史兼容与另行范围，不作为默认交付路径。
- Agent 不直接写调度内部表、不修改评分事实、不拥有系统凭证。关键写操作通过确定性业务工具执行。
- “达到当前主流智能体水平”落实为可测的工程能力与场景效果门禁，不以角色数量或未经实测的商业产品等同性承诺代替验收。
