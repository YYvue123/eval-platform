# 无 Mock 业务库与真实测试数据方案

本文件是后续执行规格；本轮没有删除数据或调用模型。

## 数据真实性定义

真实测试指实际发生的模型请求、工具执行、用户操作及可追溯结果，失败/拒绝/不可判定也是真实记录。AI 可以生成测试题和小工具，但必须标注来源为 AI 生成，不能冒充真实客户/行业金标。确定性计算工具实际执行不是 Mock；把常量答案、随机分数、stub 或 reference 当模型输出则是。

三类数据必须区分：

1. 产品必需配置：角色、权限、内置工具定义、评分规则、模板、基准规格、系统策略。不能因是 seed 就全部删除；定义也不能当成执行证据。
2. 真实业务与实测：有输入、执行路径、输出、时间、版本、trace/制品可核验。通过和失败均保留。
3. Mock/模拟成绩/测试替身及不可信衍生数据：从活动业务库清除；先备份和形成清单。证据不足的 legacy 数据不直接判真，也不凭名字直接判假，进入独立隔离归档并从活动报表排除。

隔离单元测试中可以使用 test double，测试库不得成为业务数据源。不能删掉负例测试来让 Mock 搜索“变绿”。“所有页面有真实数据”是每个业务模块走真实操作链并能刷新查回，不是给每张表插一行。

## C0：盘点、冻结和可恢复清理

先实现管理脚本的 plan/apply/verify 模式，默认只生成清单。不要执行 `DELETE ... LIKE '%mock%'`，也不要删除整个数据库。

1. 解析实际服务的 DATABASE_URL，确认绝对路径/实例、环境、租户和当前用户；本轮盘点的仓库文件不自动等于实际目标。禁止打印密码或完整连接串。确认 worker/健康探针等写入者，进入维护窗口并停止对目标的写入。
2. 使用数据库支持的一致性备份（SQLite backup API，兼顾 WAL；不是只拷主文件）；相关制品按 hash 清单备份到受限目录，执行一次独立恢复与完整性检查。备份包含历史 Mock 是恢复证据，不作为活动业务数据库接入。
3. 输出机器可读清理清单：表、主键、来源标志、关联对象、分类依据、删除/隔离/保留、受影响聚合、清单 hash、目标指纹。不要在清单输出请求秘密。
4. 确认候选：simulation=1、provider=mock、明确 stubbed/mocked 标志及已知假数据生成器记录；追踪 eval_results→task→lineage→模型/版本/调用记录，以及 Agent events/messages/checkpoint、批次、报告、榜单快照/发布、服务单、用量、幂等缓存。逐表确认，不仅删除主任务。
5. 保留真实账户、RBAC、审计及合法配置；测试账号若仅为真实权限验收可以保留并明确身份，不冒充客户。审计若引用被删对象保留删除标识与清理事件；确属伪造事件的内容移到受限归档，不继续显示成真实审计。
6. apply 必须验证目标和清单 hash 未变、快照可恢复、无活动任务。按依赖顺序在事务内处理；有真实/假混合依赖则拆分或隔离，不能批量连坐。无证据历史成绩不得重新标记 real。
7. 验证 foreign_key_check/integrity_check、逻辑孤儿、聚合一致性；清空或重建受污染幂等缓存/榜单/报告缓存；重新从保留的真实执行结果计算聚合，不直接填评分字段。启动后的 seed 不得重建示例业务记录。
8. 输出清理前后数量、移除/归档原因、保留例外及恢复命令。失败回滚；回滚后“无 Mock”验收重新失效，不能沿用旧验收结论。

没有发现关键词不等于无 Mock。最终同时验证结构化标志、历史生成器来源、执行证据和下游衍生链；保留明确的清理记录。

## C1：建立真实性与证据契约

优先复用 EvalTask/EvalResult/EvalLineage、AgentRun/Event、ResourceCallLog 和制品表；必要时增补统一 execution evidence 记录，避免每页自造“测试结果”。字段至少包含：

| 字段组 | 必需信息 |
|---|---|
| 身份与来源 | evidence_id、tenant_id、actor_id、source_kind（real_execution/configuration/ai_generated_input）、关联 task/run/resource/sample |
| 固定输入 | 数据版本/hash、prompt/judge/tool/model 配置版本；凭证引用而非原文 |
| 执行 | 开始/结束、attempt、status、error_code、trace/correlation、服务端实测耗时 |
| 输出证据 | 脱敏输入输出/受控制品引用及 hash；模型 response_id 有则保存，没有不编造 |
| 度量 | 真实 usage、未知标志、估算/实测成本来源；执行状态与评分状态独立 |
| 验证 | 用例 ID、预期、实际、断言、版本/commit、环境标识、审核状态 |

秘密可出现在请求内存中，但不得进入响应/日志/Manifest 快照/可下载证据。证据接口按租户及对象过滤。拒绝请求、失败尝试、取消和重试都保留，不能只保存成功。

系统测试始终使用 tests/isolated_env.py 或等价硬隔离；现有 setdefault 无法覆盖预先设置的业务 DATABASE_URL，测试启动器应显式设置隔离路径并断言不是业务库。**真实业务演示数据生成使用独立的受控 API 工作流脚本**，不运行单测去污染业务库；它通过真实应用 API/TaskService 创建、执行并保存到明确的目标库。

## C2：模型与自建工具准备

可读取 `backend/.env` 已有 L3_MODEL_API_URL / KEY / PRIMARY / SECONDARY / CHANNEL。执行 AI 先检查支持能力、脱敏连通性、剩余预算策略，不在回复/截图/证据显示 Key。模型可用时不要求用户重复提供；缺字段、权限、预算或多模态能力才一次性列出缺口。

注册模型通过业务 API，凭证存引用；实际请求确认 served model name、chat/tools 能力、usage 返回。已有历史 L3 脚本固定写隔离库，不能直接运行它后宣称业务页面填充完毕；也不能把隔离库整体复制进业务库。

建议 AI 自建一个无外部副作用的确定性 HTTP 工具：输入带单位的数值数组，返回统计及单位转换；实际计算，不按样例硬编码答案。提供独立断言（例如计数、和、均值范围），用多个未预置输入验证；服务放受控进程/端口，版本化接口。再将其封装成独立 MCP 服务，完成协商/发现/工具调用；声明“自建本地 MCP 实测”，不能冒充公有服务互操作验收。

Skill 将“文本解析→数值统计”连接成实际两步，独立校验中间结果。Agent 调用这些资源必须经工具白名单、网关、权限、超时和预算，不可写调度器内部表或评分事实。

AI 生成的题目先用确定性 oracle 校验；行业/安全标签需要专家复核时保持待审。缺真实媒体/沙箱/外部服务授权时记 blocked；可自行生成真实可解码图片/音频等制品测试传输，但不能因此声称真实行业代表性或模型已消费未支持模态。

## C3：真实运行场景与页面填充顺序

| 场景 | 实际操作 | 持久化及页面 |
|---|---|---|
| REAL01 基础配置 | 创建/校验真实验收账户、角色、租户；登录与一次被拒绝动作 | Users/RolePermission/Profile/Login/Audit；权限不够时清晰失败 |
| REAL02 数据与质量 | AI 生成标明来源的小型确定性题集；导入→质检→修复→新版本→发布 | Datasets/Detail/Quality，保留真实发现和复检记录 |
| REAL03 模型连通 | 已配置主/副模型各一次真实请求，缺第二模型则明确缺口 | Models/health/call logs；使用实际返回而非默认 online |
| REAL04 工具底座 | 自建 HTTP 工具至少三种输入；真实失败输入；两步 Skill | Resources、版本、调用日志、trace；独立断言实际计算 |
| REAL05 MCP | 独立进程 initialize→tools/list→tools/call；一次真实无效参数 | MCP 工作台与调用证据；失败不能绿，实际目标可见 |
| REAL06 Agent | 一个简单目标和一个需工具目标，澄清→审批→真实循环→任务 | Agents 历史、事件、工具记录、Tasks；没有工具调用不能算该场景通过 |
| REAL07 正式评测 | 合格数据版本+冻结模型/裁判，通过 TaskService 执行 | Task/Detail/Template、逐样本输出、成本、报告；至少覆盖真实评分通过和不通过 |
| REAL08 提示词实验 | 同数据集两个 prompt 版本实际调用，保留集不泄漏 | Prompts 实验、版本、报告；不保证改版必胜 |
| REAL09 基准/安全 | 支持的文本基准和安全项真实执行，产生需复核样本 | Benchmarks/Safety；人工标签待审，不由 AI 假签 |
| REAL10 榜单/服务 | 从合格正式结果形成 cohort、报告、服务交付和幂等结算 | Leaderboard/Services；不存在合格结果则不可发布 |
| REAL11 影子 | 实际两个版本、相同输入、真实裁判及持续窗口观测 | Services 真样本与门禁；未满七天显示证据不足，不回填历史时间 |
| REAL12 运维/通知 | 实际备份→隔离恢复→校验→真实工单；任务实际触发通知 | Ops/NotificationManage/Audit/Dashboard，签署保持真实身份 |

各场景先做小规模、受预算限制的验证集，输入固定并保留失败；不能反复换题直到全过。实际验收样本量在开跑前记录。原计划 200 唯一 Agent 场景×3 次、L4 性能另设阶段，以上小规模场景不能替代原验收。

## 最终验收

- 活动业务库确定 Mock/模拟成绩清零，未知来源被隔离，不存在 Mock/stub 业务成功路径；保留配置/合法测试题不算 Mock 成绩。
- 所有结果可追溯原始真实执行，失败也保留；同一 trace 在 Agent→工具→任务→报告可以核对。
- 02 中所有页面都有适合该页面的真实配置、活动或执行记录；刷新/重新登录后存在，并确认 UI 实际连接的库即数据落库目标。
- 正式榜/报告不包含 trial、模拟、未知来源与缺指标的不可比记录；真实 trial 保留真实属性但不自动升级 formal。
- 每项输出数据库主键、trace、脱敏制品路径、预期/实际断言及截图。若被模型配额、人工签署或七天窗口阻断，明确尚未满足，绝不以静态卡片补足。
