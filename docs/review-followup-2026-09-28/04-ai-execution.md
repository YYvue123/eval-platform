## 验证执行约定

1. D0 先校验实际 Python 可执行文件及依赖；不要照抄失效的 `.venv`。测试前显式配置独立 DATABASE_URL/UPLOAD_DIR/LOG_DIR/BACKUP_DIR，启动即检查绝对路径和 APP_ENV。测试不得读取业务样本或凭证作为默认 fixture。
2. 各阶段跑最相关回归，失败修复后再继续；代码都落定后跑全量隔离回归。禁止把测试中的 AsyncMock 路径命名为“真实模型已通过”。
3. 前端变更运行 `npm run collect-permissions`、`npm run verify:ux-static`、`npm run build`；审查生成的权限差异。再运行真实可操作流程的 Playwright/等价 E2E；仅 build 不能关闭交互项。
4. 真实模型测试单独 opt-in，运行前读取受控配置、限制样本量/最大轮数/总 token/并发/超时；费用上限未知时明确阻断额外高耗费场景，不无限重试。usage 缺失不补零，不把估计费用标为账单实测。
5. 所有运行记录 environment、代码版本、用例版本、输入 hash、预期与断言、时间、数据库对象和 trace。测试预期允许“正确拒绝/失败”，不能要求所有模型输出都得满分。
6. 启动服务前确认是否已有实例和占用端口；记录本轮启动进程与清理方式，不停止用户其他工作。数据库维护期间停止写入者，恢复后检查实际页面连接目标。

## 交付记录格式

每个工作包包含：问题→最终行为→修改文件/迁移→实测证据→仍未完成；避免仅报测试数量。

建议 evidence-index.json 条目：

```json
{
  "case_id": "REAL06",
  "requirement_ids": ["AC27", "AC28", "REV05", "REV06"],
  "commit": "执行时填写",
  "environment": "执行时填写非敏感环境标识",
  "result": "not_run",
  "executed_at": null,
  "task_id": null,
  "run_id": null,
  "trace_id": null,
  "assertions": [],
  "artifact_refs": [],
  "blocking_reason": "尚未执行"
}
```

执行后填写真实值；不得把模板示例写为实际执行记录。pass/fail/blocked/not_run 单一枚举，partial 拆成可验证子项。截图只是 UI 证据，不能替代服务端执行；JSON ok=true 也必须有实际断言。

最终报告须回答：

- 哪些旧交付结论被维持、降级或重新打开？哪些 R01–R12 已用新证据关闭？
- 24 页哪些操作真正变友好？核心流程截图、失败恢复和响应式证据在哪里？
- 从哪一个确认过的业务库移除了哪些 Mock/衍生数据？备份怎样恢复？有没有未分类遗留？
- 哪些模型和工具真的被调用？多少成功/失败/拒绝？结果存在哪些 task/run/trace？页面能否刷新查回？
- 哪些仍需用户提供（仅缺失的配置、预算、权限、领域标签、媒体/外部服务、签署）？哪些是时间窗口/生产环境限制？

不要宣布“WP00–WP16 全部完成”后把主要缺口藏在末尾。未完成的原规格继续列明，交付状态与当前证据一致。
