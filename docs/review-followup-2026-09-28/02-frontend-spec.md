# 全站前端体验开发规格

目标：第一次进入的研究人员能完成“准备数据和模型→描述目标→核对计划→批准执行→检查证据”，工具开发者能完成“配置可执行工具→校验→真实试用→供 Agent 使用”。保留 Vue 3 + Element Plus、现有路由与权限，不进行无关框架迁移。

## 统一设计与交互约束

- 视觉方向：清晰、克制的评测工作台。深石墨导航、浅灰主画布、青蓝主动作；琥珀表示待处理，红色表示失败，绿色只表示有依据的成功。可沿用现有主色，重点统一语义色、间距、层级和明暗主题；不另造一套榜单皮肤。
- 所有背景/文字/边框通过 `variables.css` 语义变量；中文采用可靠本地字体栈，正文 14–16px、辅助文字不少于 12px，日志可用等宽；不为换字体引入外部网络依赖。
- 页面顶部：标题、用途一句话、一个主要动作；下面为状态摘要、筛选、主体与分页。内部 resource_id/trace/hash 放到详情高级区，可复制，主界面优先名称和业务状态。
- 所有异步区独立显示加载、空结果、未创建、失败、无权限、成功六态。请求失败不能 catch 后伪装 items=[]。错误消息给原因和下一步，保留输入；后台轮询不连续弹 Toast。
- 长任务：提交后快速返回 ID，显示排队/运行/取消中/终态；切换、刷新后可恢复。前端不得从“无 active_run”推断任务成功；状态由服务端事实驱动。
- 表单必填项、错误位置、跨字段约束和保存状态明确；写操作单飞；同一次重试保持幂等键，修改意图才换键。带副作用动作按业务规则确认，普通浏览/切换不额外确认。
- 1440/1024/390 宽度均可用；窄屏主区不整体横滚，宽表在表格容器滚动；弹窗 `min(可用宽度, 目标宽度)`，工具试用两栏窄屏叠放；固定 footer 不遮挡内容。
- 键盘能访问主要操作、表单和抽屉；焦点进入/退出正确，图标按钮有名称；不能只用颜色表达状态。明暗主题均核查文本、禁用态、错误提示。
- 不在产品页写“禁止 Mock 假成功”“API 尚未完整开放”等研发口号。转换成可操作文案，如“尚无调用记录，完成一次试用后可查看”“该连接方式暂不支持”。开发边界放帮助/支持矩阵。
- 服务端分页与名称搜索覆盖全部选项，不能首 50/100 条充当全量。筛选写入 URL；详情返回列表保留筛选和页码。

## Agent：以目标和证据为中心

布局：左侧会话列表（搜索、状态、更新时间、分页、窄屏抽屉）；中间目标与计划、澄清、执行时间线；右侧/抽屉证据与资源。高级事件 JSON 收到折叠区。

1. 新建：输入目标，显示数据、被测模型、规划模型、预算准备情况。无可用资源时有权限者可跳转创建，回来保留草稿。规划模型和被测模型作用说明清楚，不能默认把第一条配置当用户确定选择。
2. 澄清：由当前计划的缺口生成字段和解释；数据/模型用远程选择器，显示版本、质量和可用状态。AI 提议不自动冒充用户确认。修改后旧审批失效，界面立刻同步。
3. 计划：显示目标、步骤、冻结资源版本、预计成本区间/未知、停止条件及副作用。审批与执行分开，按钮随权限和状态变化，禁用说明原因。
4. 执行：时间线显示“模型规划→调用工具名称→取得结果→创建/监控任务”。每步包含实际起止时间、执行状态与可见证据；默认隐藏参数原文，按权限查看脱敏内容。
5. 完成：分开显示 Agent 回复完成、评测任务完成、报告生成完成。历史运行可选；刷新后保留终态、最终回答、工具结果和失败原因。
6. 恢复：明确可重试的步骤和已完成步骤；取消后等待后端确认；预算暂停展示已用/未知用量、策略和下一步，不暗示一个新 run 可绕开累计上限。

API 配套：会话摘要含真实 task_status/report_status；运行历史分页；稳定 last_run_id；事件按 run_id/seq 增量；所有异步写回绑定 sessionId/runId/generation，包括名称解析。后台执行与轮询支持断网恢复，跨路由停止订阅。

关键验收：完整创建→澄清→审批→执行→报告；真实工具循环；终态刷新；无数据/无模型；失效审批；快速双击；A/B 会话慢网乱序；任务还在 running 时不能显示完成；真实失败和取消不呈绿。

## 工具中心、工具底座与 Skill

统一入口保留 `/resources`，页内分类“工具 / 工作流 Skill / MCP 连接”，避免把三者当同一种参数对象。目录显示名称、用途、来源、执行能力、最近真实运行、可用状态；详情提供概览、版本、输入输出、运行记录、权限与连接配置。

注册向导按资源类型分支：

| 类型 | 用户必须能配置 | 校验与最终试用 |
|---|---|---|
| HTTP 工具 | URL/方法、凭证引用、输入 Schema、输出与错误映射、超时、幂等、副作用声明 | 契约校验→网络连接→真实输入调用→保存可回查记录 |
| Skill 工作流 | 选择已授权且冻结版本的工具、步骤顺序、上一步结果绑定、输出定义、失败处理 | 引用/循环/类型检查→实际逐步运行，每一步可看输入输出与状态 |
| MCP | 已支持传输、实际地址、凭证引用、协商参数/超时 | initialize→工具发现→选择工具→实际调用，分步留痕 |

能力未实现时在选择阶段禁用并解释，不能生成 local:// 空壳。Schema 检查使用完整契约；修改 endpoint、schema、token 引用等后清空上次检查结论，结论关联 manifest hash。确认页永不显示明文 token。

试用台：

- 输入采用 Schema 驱动：必填、enum、integer、number、boolean、array/object、范围、格式。支持子集以外用高级编辑器并明确提示，后端仍做完整 Schema 校验。
- JSON 与表单共享无损对象模型；非法 JSON 保留原文和错误路径，不悄悄转字符串；切换不会丢 enum/default/description/嵌套。default 真正初始化而非仅作 placeholder。
- 结果分层：调用执行状态、业务/评分结果、实际输出、耗时、usage（可未知）、时间、版本、trace。顶层 HTTP 200 不代表成功；工具评分 false 不代表工具未执行。
- 侧效工具展示实际将影响的对象，后端授权和隔离独立生效；缺执行环境显示 blocked。
- 最近记录由 API 读取，不只存 Vue 内存。详情可重试并保留关联 attempt；复制成功须等待 clipboard 实际返回；输出、下载和证据接口受相同对象权限。

## MCP：从探测面板到连接工作台

连接状态依次为“未配置→结构有效→已协商→已发现工具→最近调用成功/失败”；显示实际目标、服务器协商信息、最近时间及证据。临时地址与已注册连接互斥，服务端二次验证。

发现结果用可搜索工具目录，显示名称、用途和 inputSchema。选择工具后自动生成参数表单，不要求用户手写 JSON-RPC method/params。资源失效或目录更新时明确 stale，不沿用旧绿色状态。协议错误、isError、认证失败、网络超时分别有恢复指引。

后端先声明 HTTP 支持范围，再实现会话/协商/通知/分页/变更处理；stdio/list_changed 等缺口不能因 UI 新增下拉项就被认为完成。协议合规实施时依据官方 MCP 规范核对，本次未做规范联网认证。

## 全部 24 页实施与真实数据展示矩阵

以下是本轮整改目标，不能解释成已完成验收。认证、个人资料和系统页展示真实状态/业务操作记录，不强塞评测图表。

| 页面 | 必须改善的流程 | 真实内容/来源与验收重点 |
|---|---|---|
| Login | 清楚错误、提交锁、安全回跳、键盘输入 | 真实登录/拒绝记录；无权限不循环 |
| Dashboard | 任务待办、异常、最近活动、数字可下钻 | 同租户真实任务/模型/事件聚合，过滤条件一致 |
| Datasets | 导入向导、来源/许可、映射预览、分页 | 实际导入样本和质检状态；上传失败保留映射 |
| DatasetDetail | 样本/版本/质检/使用记录分区 | 冻结版本、真实样本与关联任务；修改出新版 |
| Quality | 问题筛选分页、定位样本、修复/复检 | 真质检结果；复检不得改写旧报告 |
| Models | 连通配置、凭证引用、状态、调用历史 | .env 配置的实际模型调用及失败；不泄露 Key |
| Prompts | 变量编辑/校验预览、版本 diff、实验进度 | 同输入真实 A/B 结果和保留集隔离；全量分页选择 |
| Resources | 上述向导、详情、运行历史 | 真 HTTP 工具/Skill/MCP 证据；>100 条分页 |
| Agents | 上述会话主流程 | 真规划消息、工具调用、审批、关联任务/报告 |
| Tasks | 远程资源选择、筛选分页、批量权限动作 | 实际队列/预算/进度；>50 条可访问 |
| TaskDetail | 概览/逐样本/异常/成本/制品分区 | 真实输出和裁判证据；未知值≠0，失败不隐藏 |
| TaskTemplates | 表单建模板、版本与预览、创建任务 | 用已验证模板实际生成任务；模板非运行成绩 |
| Benchmarks | 支持/缺口/授权说明、运行入口、覆盖表 | 正式执行证据；代码/媒体缺执行器保持 blocked |
| Safety | 试评与正式执行分开、专家复核抽屉 | 实际输出/机器依据/复核理由；AI 不伪造专家结论 |
| Leaderboard | cohort 筛选、可比性解释、下钻报告 | 仅合格真实任务；trial/缺指标/模拟不混入正式榜 |
| EvalServices | 办理步骤、最多两个主动作、版本/影子抽屉 | 真交付、一次结算；未满七天不伪造时间转正 |
| Ops | 探针/备份/恢复/工单分区，执行与登记区分 | 真恢复 hash/RPO/RTO，演练附件核验与签署 |
| Users | 分页、邀请/禁用反馈、角色与租户说明 | 实际测试账户和真实操作审计；禁用令牌失效 |
| RolePermission | 按模块搜索/选择、差异预览、影响说明 | 真角色配置；前后端动作权限一致 |
| AuditLog | 时间/主体/对象/trace 筛选、详情与导出 | 上述操作真实产生，脱敏且跨租户不可见 |
| NotificationManage | 草稿/发布/受众、已读与失败状态 | 测试任务真实完成/失败通知，禁止假送达 |
| ApiDocs | 搜索、鉴权帮助、与当前 API 一致 | 实际 OpenAPI；试调仅授权接口并警示副作用 |
| Profile | 信息、密码校验、保存反馈 | 当前登录用户真实信息；不回显秘密 |
| NotFound | 区分 403/404，保留返回路径 | 真实未知路由和无权限场景，无导航循环 |

公共 MainLayout、ResourcePicker、StatusBadge、EmptyState、NotificationCenter 和 request 错误处理需一起核对。新页面/button/API 的权限必须同提交更新前端判定、路由 meta、后端依赖、permissions.json、ACTION_NAMES、RESEARCHER/VIEWER 权限，并运行 collect-permissions。

## 体验证据标准

每页记录：角色/租户、数据来源与运行 ID、初始状态、操作、期望/实际、截图或视频、结果、缺口。24 页全部覆盖适用的六态；1440/1024/390 与明暗主题至少有全页检查，核心三页保留关键弹窗/错误/成功截图。保存针对慢网、离线、重复点击、刷新和键盘的流程测试，不只断言标题存在。

前端自动化可在隔离环境用受控响应验证时序和错误分支，但真实数据验收不得拦截 API 返回伪业务结果。用真实数据库记录 ID 对照 UI，确认刷新后依然存在且跨页一致。无法执行的格子保持 not_run/blocked，给具体原因。
