## 0. 平台是什么

**正式名称：多智能体协同的智能化大模型评测平台。**

这不是微调/训练平台，也不是通用 LLM 网关。它是一套面向政企的**评测操作系统**：

- **评测对象**：外部 50+ 行业垂域大模型 + 内部 50+ 开源/自研/微调模型；另含被测智能体 Agent(MUT)。
- **评测场景**：固定 **11 类**典型业务场景（统一数据集、统一标尺、统一口径）+ **14 个垂直行业**专项（每行业约 11 项指标）。
- **评测方式**：数据驱动的「输入 → 模型推理 → 量化评估」闭环；支持批量、可复现、可追溯、可横向对标。
- **合作模式（默认）**：远程加密访问。模型在企业本地，平台经 mTLS/VPN/API 网关调用 `/v1/chat/completions`。评测题、裁判、打分都在平台。
- **智能化**：主 Agent 编排评测任务，监控 Agent / 诊断 Agent 分析，底层仍走确定性工具体系。

### 0.1 四层业务架构

| 层级 | 名称 | 职责 |
|---|---|---|
| 能力底座 | 智能化评测底座 | 评测数据、被测模型、数据质量、提示词、智能工具底座 |
| 执行层 | 多智能体评测任务 | 能力测试、安全可信测试、任务管理、多智能体编排 |
| 应用层 | 评测应用服务 | 大模型榜单、评测服务管理（需求到交付） |
| 支撑层 | 平台运行支撑 | 系统管理（用户/RBAC/通知/审计）、部署、运维 |

层间通过统一数据接口、任务状态流转、结果归档衔接，全程可追责。

### 0.2 11 类评测场景（必须作为任务类型/数据集标签）

1. 智能对话  
2. 表格分析  
3. 文本写作  
4. 视频生成  
5. RAG 检索增强生成  
6. 单智能体作业  
7. 多智能体协同  
8. 代码应用  
9. 具身智能  
10. 工业软件辅助  
11. 科学智算  

每类核心指标：**任务完成率、效果满意度、资源消耗效率**（可再拆子指标）。

### 0.3 14 个行业（必须作为行业维度）

每行业约 11 项专属指标；测试原则是轻量化、可落地、可迭代，避免超高精度复杂研判。

## 2. 智能化评测底座

### 2.1 评测数据管理（5.3.2.1.1）

**目标**：异构评测数据统一接入、标准化、分类标签、版本追溯、安全调用。

**功能清单（必须全部有）**

1. 上传与导入：Excel(.xls/.xlsx)、CSV、JSON、TXT、ZIP；填写名称、来源、类型、描述、分类、标签、是否公开  
2. 格式识别与基础校验：格式合法、大小限制、字段结构、条目数  
3. 解析与预览：字段解析、样例预览、确认后入库  
4. 分类管理：按任务类型、领域、来源、难度  
5. 标签管理：系统标签 + 自定义；支持多级 `parent_id`  
6. 版本控制：每次实质更新生成版本；任务绑定具体版本  
7. 查询检索：关键词、标签、时间、任务类型、质量状态  
8. 导出：指定格式  
9. 调用与任务关联：任务选用数据集+版本；结果追溯版本  
10. 权限：查看/编辑/删除/审核/导出/调用按角色  

**状态机**：草稿 → 待审核 → 已发布 → 已停用 / 已归档 → 已删除（逻辑删除）。已被任务占用禁止物理删。

**上传校验**：格式、大小、字段结构、条目数。导入空文件禁止。重复数据集提示可继续或取消。任务占用禁止删除。

**库表（设计字段必须落地，可 JSON 扩展但不要丢列语义）**

1. 评测数据集表：`dataset_id, dataset_name, dataset_type, task_type, domain_type, data_source, data_format, data_count, dataset_desc, current_version, quality_status, status, creator, create_time, update_time` + `security_level`  
2. 评测数据条目表：`data_item_id, dataset_id, version_id, item_no, input_content, reference_answer, expected_output, task_requirement, difficulty_level, data_label, extended_content, quality_flag, status, create_time, update_time`  
3. 分类与标签表：`tag_id, tag_name, tag_type(领域/任务/系统/自定义), parent_id, tag_desc, use_count, status, creator, create_time, update_time`  
4. 数据版本表：`version_id, dataset_id, version_code, version_desc, change_content, data_count, file_path, quality_score, quality_status, status, creator, create_time, update_time` + checksum(SHA-256)  
5. 数据调用与操作日志：`log_id, dataset_id, version_id, task_id, operation_type(上传/导入/修改/导出/调用/删除), operation_desc, operator, operation_time, operation_result, error_message, remark`

**页面**：列表、新增、上传导入、预览、详情、分类标签、版本、检索、导出、调用记录、权限与日志。

**接口关系**：质量模块、任务模块、模型模块、提示词、结果分析、权限、审计。

**NFR**：分页/异步导入；敏感数据访问限制；关键操作审计；可扩展新格式与标签。

**续建缺口**：审核流、逻辑删除与占用校验、标签管理页、版本回滚、字段映射确认 UI、导出 Excel/TXT、按任务占用拦截删除。

### 2.2 评测模型管理（5.3.2.1.2）

**目标**：对待测模型统一注册、接入、元信息、版本、监控、可用性检测、分类检索、调用权限与日志。

**功能清单**

1. 模型注册：名称、类型、来源（本地/第三方 API/私有化/开源/内部）、描述、语言、模态、部署方式  
2. 接入配置：URL、方法、鉴权、请求模板、响应映射、超时、重试；在线 vs 远程加密访问；通道 mTLS/VPN/网关/明文联调  
3. 元信息：架构、参数规模、上下文长度、训练数据说明、微调方式、推理框架、硬件、适用场景  
4. 版本管理：多版本并存；任务钉住版本  
5. 运行状态监控：周期探测、成功率、时延  
6. 可用性检测：连接测试，失败标异常  
7. 分类管理：来源/模态/场景/行业  
8. 查询检索  
9. 调用权限控制  
10. 调用日志：时间、任务、用户、状态、错误、Token  

**状态机**：待配置 → 待检测 → 可用 → 异常 / 超时 → 停用 / 归档 → 已删除（逻辑删）。历史任务用过的禁止物理删。

**被测模型接口契约（V0.6.1 第 10 章，MUST）**

- 纯模型：`POST /v1/chat/completions`  
- 请求：`model, messages[{role,content}], temperature, max_tokens, stream`  
- 响应：`id, model, choices[].message.content, choices[].finish_reason, usage.{prompt_tokens,completion_tokens,total_tokens}`  
- 被测智能体 MUT：另实现会话接口 `/sessions` `/messages`  
- Manifest 必填：`model_id, model_name, model_type(internal/external), scene_white_list, max_context_tokens, support_stream, version, parallel_limit`  
- 外部专属：企业名、企业模型编码、endpoint、auth_type、联系人  
- 内部专属：`source_type(open_source/self_dev/fine_tune), base_model, deploy_cluster`  
- 远程加密：企业开放端口（默认 443）+ IP 白名单；推荐 mTLS+白名单；评测期可用性 ≥99%；变更提前 3 个工作日；维护提前 5 个工作日；失败重试 3 次后熔断  
- 厂商 **不必**实现 `/batch/*` 和打分；平台读数、封装请求、裁判、落库  

**库表**

1. 模型基础信息  
2. 模型元信息  
3. 模型版本  
4. 模型接入配置（api_url, method, auth_type, auth_config, request_template, response_mapping, timeout, retry_count）  
5. 模型调用日志（含 token_usage）

**页面**：列表、新增、接入配置、元信息、版本、状态监控、可用性检测、调用日志。

**续建缺口**：拆表（元信息/版本/接入配置）、请求模板与响应映射、周期监控与告警、调用 ACL、逻辑删除、场景白名单、并发限流 `parallel_limit`。

### 2.5 智能工具底座（5.3.2.1.5 + 规范全书）

**定位**：不执行评测业务逻辑，只做资源标准化接入、注册治理、协议适配、流量调度、数据转发、质量管控。上层任务编排走底座统一接口。

**五层**

1. 资源接入层：Agent / Skill / 数据集 / 外部工具 / 插件；HTTP、RPC、本地、库、文件  
2. 协议适配层：参数映射、编码、统一信封  
3. 资源治理层：注册、版本、状态、权限、黑白名单、熔断降级、负载、并发  
4. 数据处理层：校验、标准化、清洗、脱敏、缓存、分发  
5. 能力输出层：统一工具调用、数据集读取、智能体调度  

**流程（双轨）**

- 准入：提交接入 → 协议适配注册 → 质量校验 → 上线备案  
- 执行：任务触发 → 权限/参数/状态校验 → 调度 → 执行 → 标准化回传 → 监控迭代  

**九类资源**

底座内部：Tool、Agent、MCP、Skill、DataSource、External API  
被测对象：Model、Agent(MUT)、Eval Kit（非默认）

**Manifest 顶层必填**：`spec_version, resource_id({ns}/{name}), resource_type, name, version, description, owner{name,contact,email}, capabilities{input_schema,output_schema,call_mode,idempotent,timeout}, interfaces`  
评测类必填 `evaluation_spec`：`judge_type(llm_judge|regex|exact_match|fuzzy|custom), metric_names, pass_threshold键必须∈metric_names, judge_prompt_template/judge_model(llm_judge时)`  
`resource_id`：namespace≤32 小写数字，name≤64 小写数字下划线。  
`call_mode`：sync / async / stream / batch。batch 时 endpoint 仅健康检查，真正走第 9 章 `/batch/*`。

**信封 1.3**：Header(message_id UUID、message_type request|response|event|stream、version、timestamp、source、destination、correlation_id、priority、ttl、tenant_id) + Trace(trace_id, span_id, W3C) + Auth + Body。失败 `status=error` + 标准 error 对象。响应含 `usage` Token 计量。

**Tool**：无状态、幂等（写操作用 correlation_id）、超时内返回、副作用声明。async 需 `/tasks` 提交查询取消心跳（>300s 每 60s 心跳，连续 3 次丢失 TASK_HEARTBEAT_LOST）。stream 末块 `finish_reason`：stop/length/content_filter/tool_calls。

**内部 Agent**：多轮会话、规划、调工具；**不是**被测对象。

**Skill**：技能包、触发条件、链式 `$ref`、冲突按优先级。

**DataSource**：`dataset_id, name, version, format(jsonl|csv|parquet|json), total_items, schema, source_type(mount|api|stream), checksum SHA-256, evaluation_spec, security_level(public|internal|confidential|restricted)`。mount 路径 `/datasets/{id}`。批量启动必须冻结分片快照 Snapshot ID，任务内热更新不影响；快照保留 7 天。

**批量评测 MUST**

- `POST /batch/run` → batch_id + snapshot_id  
- `GET /batch/status/{batch_id}`  
- `DELETE /batch/{batch_id}`  
- `GET /batch/{id}/shards/{shard_id}?snapshot_id=`  
- `PUT /batch/{id}/shards/{shard_id}/results` 原子回写  
- `GET /batch/{id}/results` JSONL/CSV  
约束：分片独立；部分失败记 `failed_details`；30s 进度；Token 预算耗尽 `BUDGET_EXHAUSTED`；Schema 不符 skipped。

**注册发现 MUST**

1. 交 Manifest → Schema + resource_id 唯一  
2. 准入：可达、权限、资源、标尺  
3. 健康检查  
4. 入库 active  
5. 事件 `resource.registered`  
灰度转正：score_stability 平均差 ≤±5%、单条 ≤±10%；方差 ≤1.2 倍基线；皮尔逊 ≥0.95 否则回滚。

查询 API：`GET /api/v1/resources`、详情、`POST /api/v1/resources/match`、health、SSE events。

**网关**：鉴权、限流、熔断（错误率>50% 或连续失败 5 次，冷却 30s 半开）、429+Retry-After。

**安全**：零信任；RBAC+ABAC；TLS1.2+；凭证不进日志；脱敏；沙箱与 side_effects Mock；审计+数据血缘 `parent_trace_id`，≥180 天，restricted≥365 天。

**可观测**：结构化日志；Prometheus 指标（calls、duration、errors、health、tokens、cost、batch_items、score_stability）；W3C Trace 默认 10% 采样，ERROR 全采。

**质量阈值（设计原文，作为告警/准入配置，可按环境放宽试点）**

- Agent 准入：用例 100%，百次成功率 ≥99.5%，偏差 ≤3%，单任务 ≤5s  
- Skill：判定准确率 ≥98%  
- 数据集：完整无缺失重复，标注准确，通用样本建议 ≥1000（试点可配置下限）  
- 外部工具：可用率 ≥99.9%  

**接入实体**

- 内部 Agent：HTTP/RPC、心跳 30s、JSON UTF-8、超时 120s、分片  
- Skill：注册/执行/版本  
- 数据集：静态文件 / DB 同步 / 远程拉取  
- 外部工具：适配层封装鉴权、重试熔断  
- 插件：入口函数、沙箱、安装启停卸载  

**续建缺口**：统一网关、完整信封字段、/batch 全套、MCP/Skill/Agent 运行时、外部 API 适配、健康检查器、灰度稳定性指标、Prometheus/Jaeger、副作用沙箱、DataSource 校验 checksum 与快照 7 天 GC。

## 3. 多智能体评测任务

### 3.1 模型能力测试（5.3.2.2.1）

统一闭环：标准数据输入 → 模型推理 → 量化评估。原则：标准化、轻量化、可迭代、可自动化。

**A. 通用基础能力**（按模态拆任务模板与数据集）

- 语言：生成质量、语义理解、知识问答、流畅性、逻辑、合规、意图、歧义；自动+人工  
- 语音：识别、合成、情感  
- 视觉：分类、检测、生成、视频理解  
- 多模态：跨模态对齐、生成一致性、编码转换  

**B. 场景应用能力**（11 类，见 0.2）：每类专属任务集；指标任务完成率、效果满意度、资源消耗。

**C. 行业专项**（14 行业，见 0.3）：行业知识图谱 + 轻量任务集；核验行业知识适配与业务落地，禁止做成超难研判。

实现要求：每类/每行业是**可配置的任务模板**（绑定数据集、提示词、标尺、指标权重），不是写死一个 qa 任务。

### 3.2 安全可信测试（5.3.2.2.2）

四个基准，均需：动态数据集、指标体系、评测流程、结果入库可上榜。

1. **生成合成内容风险**：多源动态采集；替换/扰动/细粒度对抗样本；多模态指标（有害性、拒绝率、过度拒绝、跨模态安全准确率）；场景权重（未成年教育↑涉黄涉暴，政务↑涉政谣言）；自适应对抗序列；多轮隐式递进测主动安全。参考规范 T/UNP 186-2026。  
2. **标识合规**：显式（OCR/角标）+ 隐式（水印/元数据 ContentID/签名）；抗篡改（擦除、覆盖、压缩、转码）；指标完整性/可解析/抗篡改/感知度。依据《人工智能生成合成内容标识办法》、GB 45438-2025、EU AI Act 规则库。  
3. **价值对齐**：施瓦茨价值观自演化题库；语境改写/极性逆转；立场稳定性、跨文化对齐、多元性；探测过度安全与僵化。  
4. **幻觉**：感知/认知/上下文幻觉；对象-属性-关系陷阱；分层自适应（感知→认知→跨场景）；指标对象/属性/关系幻觉率、时序一致性、跨轮稳定性。  

实现策略：先做**可运行的安全任务类型 + 规则/裁判工具 + 专用数据集**，再迭代动态数据生成。不要因为研究表述就跳过模块。

### 3.3 测试任务管理（5.3.2.2.3）

**架构**：事件驱动 + 任务状态机 + 事件总线。

层：任务管理、调度引擎、执行引擎、资源管理、监控告警、数据存储。

**状态（至少）**：草稿、待审核、排队 queued、运行 running、成功、失败、取消；服务侧另有配置中、已完成等（与评测服务对齐）。

**调度**：优先级、资源约束、任务依赖、工具可用性、预计耗时；队列、负载均衡、故障转移、执行窗口。

**执行**：拆子任务；调模型/数据/工具；并行；上下文；状态回传。记录 **模型版本、数据版本、工具版本、参数、结果**。

**监控**：排队/执行/完成/失败/取消；超时、工具失败、资源不足、回传异常 → 告警（通知模块）。

**NFR**：可复现、可追溯、可对比；并发；配额隔离。

**续建缺口**：真正的队列与依赖、优先级、事件、子任务拆分、告警策略、报告归档文件、任务模板库。

### 3.4 多智能体自动化编排（5.3.2.2.4）

设计铁律：**主 Agent 编排，子 Agent 分析，工具执行，知识库复用。Agent 不进入调度/资源主链路。**

- **主 Agent**：唯一用户入口；理解需求、生成配置、编排计划、跟踪、汇总报告  
- **监控分析 Agent**：每任务一个；进度摘要、风险趋势、异常上报  
- **异常诊断 Agent**：只出建议，不直接恢复；回主 Agent，校验/人工确认后再调工具  
- **经验知识库**：模板、案例、异常策略、资源画像（不是 Agent）  

工具封装：任务管理、调度执行、资源管理、监控告警、结果报告、知识检索。

校验：配置完整性、权限配额、资源可用、风险安全、关键任务人工确认。创建/改配/恢复/补测必须校验。

运行：需求 → 配置 → 知识优化 → 校验确认 → 工具创建执行 → 监控 → 诊断 → 报告 → 沉淀经验。

## 4. 评测应用服务

### 4.1 大模型榜单（5.3.2.3.1）

四种榜：

1. **综合得分榜**：分行业加权平均，权重后台可配  
2. **单项能力榜**：代码、数学、中文理解等，Top10  
3. **专项评测榜**：医疗问答、金融风控、智能对话、RAG 等场景  
4. **性价比榜**：效果 × 成本（Token 价、时延、GPU），用户可自定义成本参数  

刷新：手动、定时、新模型入库。同模型多次评测默认取最近一次完整结果。分数归一化后排序。写入快照，可回溯。

可视化：表格、雷达（2–5 模型）、趋势曲线、模型卡片（元数据、摘要、接口信息）。导出 Excel/CSV。查询 <3s，缓存与刷新周期一致，增量更新。异常时展示上次数据并提示“数据更新异常”。

数据源：任务结果、模型元数据、成本价格表。

### 4.2 评测服务管理（5.3.2.3.2）

全生命周期：需求提交 → 方案报价（自动/专家）→ 确认创建 → 执行监控 → 报告交付（PDF/Word/Excel + API）。

三大能力：

1. **注册发现**：Nacos/Consul 或等价注册中心；网关鉴权限流路由；健康剔除  
2. **版本与灰度**：多版本；影子测试复制流量只返回生产结果；对比差异率/时延/资源；转正；一键回滚  
3. **配额计费**：日/月/总量，可限定模型；不足拒绝；80/90/100% 预警；审计日志 180 天；账单发票  

企业工作空间：管理员/工程师/观察员；共享模型配置、私有数据集、报告模板、历史报告；租户隔离。

任务看板：待审核、配置中、执行中、已完成、失败；Token、API 次数、GPU 时长；预算上限告警。

性能设计原文：100 并发任务、队列 1000、网关 500 QPS、超时 30s 重试 3 次。按实际环境可配置，但产品行为要在。

## 5. 部署与运维（5.3.2.4）

### 5.1 部署

流水线：编译、规范检查、单测、安全扫描 → 制品仓库（镜像/包+版本）→ 编排（串并行、审批卡点、失败重试）→ 滚动/蓝绿/金丝雀 → 失败自动回滚。IaC（Terraform/Ansible）可选但环境要可重建。

监控三层：数据中间件、应用（延迟/流量/错误/饱和 + 链路）、服务器资源。

仓库已有 `deploy/nginx-eval-platform.conf`、`deploy/eval-backend.service`，续建补：健康检查、备份、升级说明，不必一上来上 K8s，但设计不要删。

### 5.2 运维

六层：网络基建、社区运营、环境（多环境+CI/CD+可观测）、团队（SRE/轮值）、制度（变更/发布/应急）、开源合规。

对产品实现优先：**多环境配置、日志指标链路、备份恢复、告警、变更审计**。社区/开源生态可后置，但规格保留。

## 6. 跨切面规则

### 6.1 可复现铁律

每次正式评测必须落库并在结果/报告中可查：数据集 ID+版本+checksum/snapshot、模型 ID+版本、提示词 ID+版本、工具/标尺 ID+版本、任务参数、逐条输出与分数、Token 与时延。

### 6.2 逻辑删除

数据、模型、提示词凡被历史任务引用，只停用/归档，不物理删。

### 6.3 不合格数据

质量不合格或检测失败不得进入正式评测（可允许「仅测试」标记的试跑）。

### 6.4 租户

信封 `tenant_id` 贯穿；企业工作空间数据隔离；审计按租户。

### 6.5 远程评测数据流（默认路径）

1. DataSource 按 snapshot 读条目  
2. 平台封装 chat.completions，加密通道调企业模型  
3. 平台用裁判 Tool（llm_judge/regex/exact_match/fuzzy/custom）打分  
4. 写 batch 结果：score、usage、finish_reason、error_code、latency_ms  

### 6.6 交付验收（厂商接入）

基础级：Manifest、加密通道、连通、功能用例、错误处理、信封。  
完整级：性能、稳定性、评分稳定性、并发、SLA。  
企业交付物：Manifest、连通说明、加密通道配置、能力声明、网络就绪单、对接人。

## 7. 建议实现顺序（给后续 AI 排期）

按依赖，不要跳层空做 UI。

1. **补齐数据域**：审核、标签、逻辑删、占用校验、质量规则/问题单/报告、不合格拦截  
2. **补齐模型域**：版本表、接入映射、周期健康、ACL、Manifest 场景白名单、限流  
3. **补齐提示词域**：审核、测试、优化/生成（可先规则后 LLM）、调用日志  
4. **补齐底座协议**：完整信封、/batch/*、快照、checksum、网关熔断限流、注册事件  
5. **任务引擎**：状态机事件、队列依赖、子任务、报告文件、模板（11 场景 + 14 行业 + 4 类安全）  
6. **榜单 2.0**：四类榜、权重、归一化、快照、雷达趋势、成本表  
7. **评测服务**：报价双模式、配额、工作空间、报告导出  
8. **编排 Agent**：主/监控/诊断 + 知识库，全部走工具  
9. **远程加密与可观测**：mTLS 配置项落地、Prometheus 指标、血缘审计字段  
10. **部署运维**：流水线、备份、监控面板  

每步仍遵守权限工作流与可复现铁律。
