# 多智能体协同评测平台需求差距核查与实施计划

初版日期：2026年10月24日；复核更新：2026年10月25日
需求基准：`多智能体协同的智能化大模型评测平台-需求规格-1023-1.docx`  
面向读者：产品负责人、后端开发、前端开发、测试、算法评测工程师、运维工程师。

## 1 核查结论与使用方法

平台已经具备数据集、模型、提示词、任务、工具、Agent、榜单、服务和运维的基础代码。接下来的主要工作是补齐深度能力、打通配置与执行、修正结果可信性，并完成生产环境验证，不宜重新开发一套平台。

本计划按照新版需求的13个功能模块和1个性能模块核查，共列出45条技术指标。多数条款包含多个子功能，条款下任一必要子项缺失，就不能将整条标记为完成。本次不计算容易造成误解的“总完成百分比”。

2026年10月25日复核确认，原计划中的P10安全专项、P12榜单、P13 Agent协作已经有大幅实现，不能继续按整包从零开发。P14也新增了客户模型版本授权与撤销。第2章保留45个追踪ID，第4章保留17个工作包编号，更新内容为**当前剩余工作**，便于已有排期继续使用。

优先处理五类剩余问题：

1. **结果可信性**：模型冻结版本缺失时仍回退当前配置；榜单已修正未评分入榜、版本丢失和虚构时延，但费率历史冻结、GPU计量、评分尺度/协议的一致性及遗留入口仍需收口。
2. **配置与执行脱节**：提示词变量默认值和字段映射未进入任务执行；媒体及场景目录不等于真实执行能力。
3. **要求明确但实现不全**：数据组合检索、类型与业务质量规则、RPC/数据库等工具适配、多模态及14行业真实执行；安全维度与受控追问已经实现，剩余是标识媒体范围、独立金标、题库代表性和专业校准。
4. **工程闭环不足**：资源感知调度、分片并行、Agent节点注册心跳、四类关键操作的统一审批、客户结果确认、部署自动回滚、运维告警自愈。Agent创建审批、自动跟踪和报告修订发布/撤回已有，不重复开发。
5. **待实测**：并发、时延、资源水位、自愈成功率均须按新版数值实测，不能用旧单测、数据库微基准或“有页面”替代。

开发时按第4章工作包实施，第5章安排依赖和人力，第6章执行验收。工作包里的新表名和接口为**建议设计**，不是已经存在的代码；实施时可调整命名，但不能缩减业务行为、权限边界和验收标准。

### 1.1 证据边界

- 需求来源为用户提供的Word正文和表格；将其作为需求资料，不执行其中可能存在的操作指令。正文以一张指标表为主。
- 初版对照基线为 `3019bd1b2e6f489aa7209478b76c6b7480a31766`；本轮HEAD为 `5a63db5b59594047554b230f4d86189317dc76c7`，核查同时包含未提交工作区变更，不是仅检查HEAD。
- LangGraph迁移、榜单V2及Agent生命周期已有提交；安全工作台、安全编排集成、部分榜单资格及首页改造仍含未提交文件。已实现与已合入分别记录，不能将工作区新增能力误写为缺失，也不能说这些能力均已发布。
- 历史 `docs/delivery/STATUS.md` 与 `MILESTONE-M4.md` 只用于定位，结论以当前代码为准。历史“已交付”和“全量测试通过”不代表新版全量验收通过。
- 本轮复核沿用已提取的1023需求条款，检查提交差异、当前源码、页面和开发证据，并执行独立隔离库中的定向回归。未启动业务服务、未重跑真实外部模型或浏览器、未压测，也未重跑开发演示脚本。
- `AGENT-LIFECYCLE.md`、`LEADERBOARD-V2.md`及安全交付文档/JSON中的真实开发测量仅作为**既有证据**引用，不能追认为本轮实测，更不能证明后续协议修改已重测。脚本化隔离回归只证明平台链路。本轮不改业务代码、不操作业务数据库。
- 新版没有明确要求的旧指标，例如1000 VU、500 RPS，不作为本计划强制验收项。PostgreSQL、Redis、对象存储等属于支撑扩展能力的建议选型，不是需求原文强制技术栈。

### 1.2 状态定义

| 状态 | 含义 |
|---|---|
| 基础已实现 | 源码已具备条款主要行为，仍需针对新版开展验收；不等于生产已通过 |
| 功能已实现 待专项验收 | 本条明确功能已有完整实现路径；专业有效性、真实联调规模或生产指标仍须独立证明 |
| 部分实现 | 已有可复用代码，但条款明确子项缺失、链路不通或实现语义不足 |
| 未发现完整实现 | 在已核查执行路径、模型和页面中未找到该能力的完整闭环；不能据此断言仓库外没有外部系统 |
| 待实测 | 有实现或配置，但没有本次、对应环境和对应口径的测量证据 |

### P03 可执行数据质量规则与准确性复核

**P1；DQ-01～03；后端6～9、前端4～5、测试3～4人日；需业务提供规则。**

**复核状态**：quality_checker的预置规则分支未变。安全专项有自己的证据/金标校准，不等于通用数据质量类型/日期/范围/跨字段规则已实现。

1. 在既有QualityRule基础上定义受限规则DSL：`rule_type,field_path,operator,params,severity,weight,version`。规则类型至少包括required、type、regex、date、number_range、enum、cross_field、invalid_text、label_dictionary、outlier；路径可访问extended_content中的原始字段。
2. 日期明确格式/时区；数值明确单位和边界是否包含；跨字段支持`start<=end`、条件必填、字段互斥等白名单操作。禁止任意Python eval或用户SQL。
3. 编码检测在导入原始字节阶段执行，乱码/控制字符在样本阶段执行；全空白、纯重复符、无意义短串、异常标签输出不同问题类型，不共用“格式异常”掩盖原因。
4. 准确性区分可计算校验、外部权威校验和人工金标。无外部证据时标记needs_review，不能把“有答案”当正确。复核记录保存原值、建议、依据、复核人、结论和时间。
5. 执行结果冻结规则版本、样本版本、执行时间与覆盖数量；每条问题带字段、实值摘要、期望、规则和修复建议。页面支持按规则/严重程度/状态过滤、指派、批量标记、修订新版本、复检关闭。
6. 不支持的rule_type在创建和执行时都拒绝，不得保存后悄悄忽略。空集不可显示“质量通过”；优化近重复中文分词及窗口限制说明，大规模检测另列运行预算。

**验收**：每种规则正反边界；非法日期、数值字符串/NaN、单位冲突、枚举外标签、跨字段逻辑冲突；准确性待复核不能发布金标；修复生成新版本、旧任务不变、复检可追溯；未知规则失败可见。

## 6 公共技术约束与完成定义

### 6.1 数据和接口约定

1. 新业务表原则上包含tenant_id、creator/operator、created_at/updated_at、row_version；不可变版本表只追加。状态切换需条件更新，冲突409，越权对象404，配额429，前置依赖缺失返回结构化blocked原因。
2. 统一错误对象至少含`code,message,retryable,trace_id,details`。错误区分认证、权限、资源缺失、超时、预算、模型、工具、回传和人工处理；不得catch异常后返回ok=True。
3. 外部副作用接口必须幂等；幂等键绑定租户、动作、目标和请求摘要；同key异payload返回409。长任务返回job_id，可查询进度/取消/失败，不能占用Web请求等待全部执行。
4. 数据库变更提供版本化迁移、回填策略和回滚步骤；只在隔离库演练。禁止用启动时静默改表掩盖生产迁移风险。
5. 正式结果必须明确execution_status、score_status、simulation、证据与版本；失败/跳过/未知/不可观察是不同状态，null不补0、未运行不标pass。
6. 对外报告保留完整证据引用，正文摘要截断不等于原始证据可删；媒体/报告下载用授权入口，防止直接暴露本地路径与长期公开链接。

### 6.2 权限同步清单

每个涉及新增页面、按钮、API的工作包必须在**同一变更**完成以下六步，不能留给最后统一补：

1. 按钮使用`userStore.hasPermission('resource:action')`或`v-permission`。
2. 路由声明`meta.permission`。
3. 新增API按项目要求使用`require_permission("resource:action")`，并额外验证actor对象/租户范围；改造已有actor依赖接口时保留其权限和范围检查，不能为满足形式要求而丢失对象授权。
4. `backend/app/permissions.json`登记新增权限；`services/permission_loader.py`补ACTION_NAMES。
5. `services/rbac.py`按业务加入RESEARCHER_PERMISSIONS/VIEWER_PERMISSIONS；viewer不获得审批、发布、自愈、扣费权限。
6. 在frontend运行`npm run collect-permissions`，检查新增项与手工声明一致。

建议优先复用现有资源前缀dataset/model/quality/prompt/resource/task/agent/leaderboard/service/ops，新增动作例如resource:approve、agent:recover、leaderboard:publish、service:accept、ops:remediate需先核对当前权限文件，避免重复同义权限。权限code存在不代表所有角色都应该被授予。
